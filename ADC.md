# ADC

## Текущий этап

Согласованные изменения ADC обновлены 18.10.2026. DMA и TIM в этом проходе
не изменялись. Для G031/F429/F767 скомпилированы изолированные тела IRQ
до/после правок; полная сборка ADC и аппаратная работа не подтверждены.
Сравнение ассемблера: [Review/ADC_IRQ_Timing.md](Review/ADC_IRQ_Timing.md).

Ошибка вычисления consteval ADC_PIN в таблицах исправлена: тип определён
до ADC_N, а ADC_N::ADC_PIN сохранён как алиас. Таблицы и настоящий adc.hpp
скомпилированы GCC 13.3 для G031/F429/F767 без ошибок и предупреждений.
Это проверка заголовка, а не полной реализации adc.cpp или готовой прошивки.

**Зависимость сборки остаётся:** в TIM ещё нет TIM_TriggerGenerator.
ADC хранит указатель на этот тип и обращается к его GetReq().extsel, Start()
и Stop(). Одного forward declaration для компиляции этих обращений недостаточно:
потребуется определение класса в следующем этапе TIM.
Временного генератора, заглушки или отдельного trigger-фреймворка в ADC нет.

В DMA добавлены GetHT_Flag(), ClearHT_Flag() и ClearTC_Flag(). Независимая
обработка HT/TC в ADC будет подключена отдельным шагом. OnDmaHalf предусмотрен,
но сейчас не вызывается и отдельный HT source через ADC не включается.
OnDmaComplete работает через имеющийся TC API. При добавлении HT нужно заменить
общую очистку в circular TC на выборочную, чтобы не терять соседние события.
Задача генератора записана в [Review/TIM.md](Review/TIM.md).

## Модель работы

`SetUp → AddChannel → при необходимости AttachDMA / AttachTrig → Start`

- SetUp выполняется один раз. Повторная настройка — через явный DeInit.
- Каналы добавляются непосредственно в регистры; после конечного измерения
  можно вызвать Start повторно без повторных SetUp/AddChannel/AttachDMA.
- При активном захвате новый запуск и изменение каналов возвращают Busy.
- Stop останавливает захват, сохраняя каналы и подключённые ресурсы.
- Конфигурация, запуск, Stop и DeInit выполняются последовательно из main.
  Из callbacks только уведомлять приложение либо отключать источник IRQ.
- System/RCC должны быть настроены заранее. GetTick/Delay_ms/WaitBits требуют
  работающего SysTick; аппаратные ожидания G0 имеют предел 1 мс.
- adc_thread_context, IPSR/PRIMASK, IrqLock, Config/cancelled и скрытой фазы
  FinishStop больше нет. IsBusy/GetStatus не останавливают DMA, не трогают кеш
  и не очищают аппаратные флаги.

| Метод | Действие |
|---|---|
| Start() | Одна последовательность без DMA |
| Start_DMA(buf) | Одна последовательность в буфер, автоматическое завершение |
| StartTrig_DMA(buf, len) | Circular DMA, последовательность по каждому триггеру |
| StartCont_DMA(buf, len) | Непрерывные последовательности и circular DMA |
| StartCont() | Один канал непрерывно, последнее значение через GetData() |

SetUp/Attach возвращают SysInitStatus. Операции возвращают SysStatus:
OK — принят запуск/операция завершена, Busy — идёт захват, NotInit — нет SetUp,
Error — неверные аргументы/конфигурация или ошибка DMA, Timeout — аппаратный
handshake не завершился. Для асинхронного запуска OK не означает готовые данные.

После timeout изменения последовательности вызывающий должен успешно выполнить
ClearChannels либо DeInit/SetUp перед новым захватом: частично изменённую
последовательность драйвер автоматически не восстанавливает.

## Пины и последовательность

Имена содержат GPIO и аппаратный номер входа:

~~~cpp
ADC_N::_1::PA0_IN0
ADC_N::_1::PC4_IN14
ADC_N::_3::PF6_IN4
ADC_N::IN::PB0_IN8       // G0
~~~

INn — номер входа, а не позиция измерения. Позицию задаёт порядок AddChannel.

ADC_PIN использует неизменяемый PIN; порт/номер, диапазон номера входа и наличие
ADC проверяются в consteval-конструкторе. Принадлежность переданного пина объекту
проверяет AddChannel. Доступность вывода в корпусе проверяет вызывающий.
Тип определён перед ADC_N, чтобы конструктор был доступен при вычислении таблиц;
публичное имя ADC_N::ADC_PIN сохранено через using.
Никакой изменяемой публичной привязки ADCx нет.

F4/F7 допускает до 16 позиций, повторы и произвольный порядок.
У G0 восемь позиций для входов 0…14; при девятой позиции или входе 15…18
используется битовая последовательность со строго возрастающими входами без повторов.
Один физический канал не может иметь разный sampling в разных позициях.

### Тактирование и внутренние источники

На F4/F7 устанавливается PCLK2/4. ADCPRE общий для ADC1/2/3 **даже при независимых
измерениях**. Сначала настройте все используемые ADC, затем запускайте захват.
Менеджер общего режима и переключение делителя во время работы не добавлены.

На G0 используется синхронное тактирование PCLK/2. SMP1/SMP2 задаются через SetUp,
а AddChannel выбирает один из них. На F4/F7 sampling задаётся для каждого канала.

TEMP/VREFINT/VBAT доступны через AddChannel(INTERNAL, sampling), на ADC1.
Вызывающий выбирает sampling по datasheet своего МК и частоте ADC:
короткий default для внешних входов может быть недостаточен.
Задержка включения источника не заменяет время выборки каждого измерения.
Автоподбор и новые проверки sampling не добавлены.
Где TEMP/VBAT используют общий вход, одновременно включать их в последовательность нельзя.

## IRQ и callbacks

SetUp регистрирует объект на ADC IRQ; AttachDMA — на DMA IRQ.
Оба проверяют результат Register и сохраняют чужое состояние общей линии при отказе.
Не регистрируйте тот же объект вручную. IRQ_en меняет только источники, не реестр.
DMA инициализируется через существующие DMAReq/CanUseRequest и SetUp(cfg);
повторный AttachDMA запрещён до DeInit.

Callbacks переопределяются в наследнике:

~~~cpp
class MyADC : public ADC_N {
public:
    using ADC_N::ADC_N;
    volatile bool ready = false;
    volatile uint32_t errors = 0;

protected:
    void OnDmaComplete() override { ready = true; }
    void OnError(uint32_t causes) override { errors = causes; }
    void OnEOS() override { /* уведомление о конце последовательности */ }
};
~~~

Есть OnEOS, OnDmaHalf, OnDmaComplete и OnError; на G0 также OnEOC.
Отдельный OnOverrun удалён: overrun передаётся только через OnError.
OnDmaHalf ожидает отдельной интеграции HT в DMA, как указано выше.
Это уведомления: состояние и кеш обрабатываются до callback,
вызывать базовую реализацию для завершения захвата не требуется.
На F4/F7 EOC/EOS используют один источник и означают конец последовательности:
вызывается только OnEOS, метода OnEOC на этих семействах больше нет.
Имена IRQ::EOC/IRQ::EOS сохраняются как алиасы одного аппаратного источника.
На G0 события и callbacks EOC/EOS остаются независимыми.
Без DMA сохраняется только последний результат в DR.

Маска Error содержит Overrun и Dma. ADC overrun обслуживается при включённом
IRQ::OVR; DMA error sources включает AttachDMA. При обнаруженной ошибке захват останавливается,
выставляется Error и один раз вызывается OnError; успешные callbacks не вызываются.
Ошибки DMA читаются один раз за IRQ. Для конечного TC снимок ошибок делается
после подтверждённой остановки DMA. Буфер при ошибке считается непригодным:
invalidate пропускается, частичные данные читать нельзя. Для нового захвата
вызывающий код запускает ADC заново из main.
Непрерывный режим без DMA допускает перезапись непрочитанного результата.
Чтение GetData во время DMA может забрать его данные из DR и не допускается.

### Однократный DMA и повторный запуск

~~~cpp
MyADC adc(ADC1);
#if defined(STM32G0)
DMA_Sx dma(DMA1_Channel1, DMA_Sx::Req::Adc1::RX);
#else
DMA_Sx dma(DMA_Sx::Req::Adc1::RX_DMA2_Stream0);
#endif
alignas(32) static uint16_t samples[16];

// После System/RCC:
if (adc.SetUp() == SysInitStatus::InitOK) {
#if defined(STM32G0)
    SysStatus channel = adc.AddChannel(ADC_N::IN::PA0_IN0);
#else
    SysStatus channel = adc.AddChannel(ADC_N::_1::PA0_IN0);
#endif
    if (channel == SysStatus::OK && adc.AttachDMA(&dma) == SysInitStatus::InitOK) {
        adc.ready = false;
        SysStatus started = adc.Start_DMA(samples);
        // Проверить started == OK перед ожиданием.
    }
}
// В main после adc.ready: обработать samples[0], сбросить ready,
// затем снова Start_DMA(samples). Ошибку обрабатывать отдельно через errors/GetStatus.
~~~

AttachDMA включает TC/TE и DME на F4/F7. Конечный Start_DMA сам включает TC,
который нужен для остановки DMA и обслуживания кеша; не отключайте его во время
этого захвата. Конечная передача получает стабильный буфер до OnDmaComplete.
SetMemAddr/SetCount проверяются до включения DMA. Перенастраивать/освобождать
переданный DMA извне до DeInit нельзя.

### Circular DMA: ответственность вызывающего

В триггерном режиме обработка должна укладываться в интервал до повторной записи
читаемой части буфера. В continuous доступное время зависит от длины буфера,
частоты ADC и sampling всех каналов. TC сообщает о полном круге, после чего
DMA начинает следующий круг. Это не неизменяемый снимок данных.

Вызывающий выбирает размер буфера и своевременно обрабатывает данные.
Остановки на обработку, копирования, дополнительных буферов и контроля
отставания нет. После отдельной доработки DMA будут доступны независимые HT/TC;
вызывающий сможет обрабатывать половины до их повторного использования.

На F7 при работе по половинам нужно владеть затронутыми кеш-линиями каждой
обрабатываемой части; границы частей следует разнести по линиям.
Это будущая интеграция HT, а не новое ограничение длины однократного RX.

## Кеш и освобождение

Перед RX вызывается System::CacheCleanInvalidate. После успешного конечного
DMA или обычной остановки без DMA-ошибок — CacheInvalidate до доступа CPU.
При ошибке буфер отбрасывается без invalidate и недоступен для чтения.
В circular TC invalidate не останавливает поток; срок чтения обеспечивает вызывающий.
Весь буфер пока обслуживается на TC; invalidate по половинам ожидает
подключения готового DMA HT/TC API в ADC.

На F7 выделение владеет всеми затронутыми 32-байтовыми линиями, включая padding.
CPU не меняет линии, которыми владеет RX DMA. Само число передаваемых байтов
не обязано быть кратно 32. Память должна быть доступна выбранному DMA.
System пропускает диапазон, целиком расположенный в настроенной некешируемой
DMA-области; на F4/G0 его cache helpers пустые.

DeInit нужен только при явном освобождении. Он останавливает/отключает ADC,
останавливает подключённый генератор, возвращает активный DMA-буфер CPU,
удаляет только собственные IRQ-регистрации и освобождает DMA.
Общие линии с чужими обработчиками сохраняются. Тактирование своего ADC
отключается; общие GPIO/DMA clocks и аналоговый режим GPIO сохраняются.
Настроенный снаружи объект генератора не уничтожается и не перенастраивается.
Автоматического освобождения в деструкторе нет.

## Переход со старого API

| Раньше | Теперь |
|---|---|
| Start(): void | Start(): SysStatus |
| StartDMA | Start_DMA |
| StartTrig | StartTrig_DMA |
| StartCont(buf, len) | StartCont_DMA(buf, len) |
| SetEOCCallback / SetEOSCallback | OnEOS на F4/F7; отдельные OnEOC / OnEOS на G0 |
| SetOVRCallback | protected virtual OnError, причина Error::Overrun |
| SetDMACallback | protected virtual OnDmaComplete |
| IsDMAError | GetStatus и маска OnError |
| PA0 / PC4 | PA0_IN0 / PC4_IN14 (по реальному номеру входа) |
| Повторный SetUp / замена DMA | Сначала явный DeInit |
