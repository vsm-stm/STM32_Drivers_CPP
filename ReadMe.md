# Drivers — STM32 Peripheral Driver Library

*[English](#english) · [Русский](#русский)*

---

## English

A universal C++ library on top of CMSIS for the **STM32G0**, **STM32F4**, and **STM32F7** families.
Core (always built): System, RCC, GPIO, Flash, IRQ_Registry. Optional modules: UART, SPI, DMA, TIM, RTC, ADC, DAC, I2C, MODBUS, CONTAINERS, PID, DSP, CRC.

The library is not a standalone CMake project: it is cloned and wired in by the [stm32_cmake_base](https://github.com/vsm-stm/stm32_cmake_base) platform (see "Integration and build").

Additionally, the **`DSP`** module: a subset of Arm's current CMSIS-DSP (fast math `arm_sin_f32`/`arm_cos_f32`/`arm_sqrt_q31`/`arm_atan2_*`, controllers `arm_pid_*`, shared tables). Not part of the repository — pulled in at configuration time (`FetchContent`, tag v1.16.2). Enabled the same way as the other optional modules — by adding `"DSP"` to the project's `"drivers"` list. Third-party licenses are in `THIRD_PARTY.md`.

The **`PID`** module — an in-house PID controller (`math/PID.*`): variable step `dT`, dead zone `e_lim`, integral-term clamp `max_ki_I`, a helper `PID_get_quality` (overshoot, settling time).

## Integration and build

Drivers are enabled with a single line in the `project.json` of a project built on `stm32_cmake_base`:

```json
"drivers": ["UART", "SPI", "DMA", "TIM"]
```

- `null` / `false` / no key — drivers are not built at all;
- `true` or `[]` — core only (System, RCC, GPIO, Flash, IRQ_Registry);
- `["UART", ...]` — core + the listed modules. A typo in a name is a configuration error with a list of valid names.

The first configuration clones the repository into `Drivers/`; the version is set by the tag (`GIT_TAG` in the platform's `CMakeLists.txt`). The `stm32_platform` target links against `stm32_drivers` (flags, CMSIS, chip defines). Chip-specific configs (`flash_config.h` — the sector map, `irq_registry_config.h` — the vector table) are generated by the library itself into `cmsis-core/drivers_gen/`.

The core is included via `#include <system.hpp>`, `<rcc.hpp>`, `<gpio.hpp>`, `<flash.hpp>`, `<irq_registry.hpp>`; optional modules — `<uart.hpp>`, `<spi.hpp>`, `<tim.hpp>`, etc. (an example is the commented-out block in the platform's `inc/main.hpp`).

### Modules and verification status

Only **compilation** has been checked (release, one module at a time; F446RE, F746ZG, G071RB). This does not confirm operation on real hardware.

## 1. Architectural Principles

### Peripheral tables (PeriphInfo)

Instead of long if-else chains like `if (USARTx == USART1) { RCC->APB2ENR |= ...; }`, each driver keeps a **static table** describing every instance of the peripheral:

```cpp
struct PeriphInfo {
    USART_TypeDef*      periph;   // pointer to the peripheral (USART1, USART2...)
    volatile uint32_t*  clk_reg;  // clock-enable register (APBxENR)
    uint32_t            clk_bit;  // bit in clk_reg
    uint32_t const*     bus_clk;  // pointer to the bus-frequency variable
    IRQn_Type           irq;      // interrupt vector number
};
static const PeriphInfo usart_table[];
```

When `SetUp()` is called, the driver scans the table, finds the right entry by the peripheral pointer, and automatically:
- enables the clock
- reads the current bus frequency
- knows the interrupt vector

This is the only place that needs updating when adding a new MCU.

### Compile-time pin validation

Pins for USART and SPI are selected from nested structures:

```cpp
USART debug(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);
```

Each pin from `USART::_1::TX::PB6` carries the peripheral's base address. The constructor checks the match — if you pass a pin belonging to a different USART, a `BKPT` and an infinite loop fire, which is caught instantly while debugging.

### IRQ_Registry — a single interrupt dispatcher

All interrupts pass through a single dispatcher. The stub handlers in `irq_registry_config.h` call `IRQ_Registry::Dispatch(IRQn)`, which forwards the call to the registered `IIRQHandler` object.

Drivers register and unregister automatically when an interrupt is enabled/disabled through `IRQ_en()`.

## 2. System

**Files:** `system.hpp`, `system.cpp`
**Details:** [System.md](System.md)

The base module: FPU, Flash accelerator, SysTick, delays.

### Initialization

```cpp
System::Init();  // enables the FPU, configures Flash latency, starts SysTick (1 kHz)
```

Must be called **first** in `main()`, before `ClockSystem::Init()`.

### Working with time

```cpp
uint32_t t = System::GetTick();   // ms since startup
System::Delay_ms(500);            // blocking 500 ms delay

// Non-blocking timer:
uint32_t start = System::GetTick();
if ((System::GetTick() - start) > 1000) { /* one second has passed */ }
```

### Microsecond delays (F4/F7)

```cpp
System::Enable_CYCCNT();   // once at startup
System::Delay_us(10);      // 10 us delay via DWT
```

On **STM32G0** the DWT is unavailable — `Delay_us` does not exist.

### Bus frequency variables

After `ClockSystem::Init()`, these are available:

```cpp
System::SystemCoreClock  // core frequency (AHB)
System::APB1BusClock     // APB1 frequency
System::APB2BusClock     // APB2 frequency
System::TIMxAPB1Clock    // frequency for timers on APB1
System::TIMxAPB2Clock    // frequency for timers on APB2
```

## 3. RCC / ClockSystem

**Files:** `rcc.hpp`, `rcc.cpp`
**Details:** [RCC.md](RCC.md)

Configures the clock system: HSI/HSE, PLL, AHB/APB bus dividers.

### Simple startup (HSI without PLL)

```cpp
ClockSystem::Init();  // HSI 16 MHz, DIV1 dividers
```

### Startup with PLL (recommended)

Example: STM32G0, a 16 MHz crystal on the input, SYSCLK = 64 MHz:

```cpp
ClockSystem::Init(
    ClockSystem::SystemClockSource::PLL,
    16000000,  // HSE crystal frequency
    ClockSystem::BusDividers{
        ClockSystem::AHB_Divider::DIV1,
        ClockSystem::APB_Divider::DIV1,
        ClockSystem::APB_Divider::DIV1
    },
    ClockSystem::PLL_CFGR{
        ClockSystem::PLL_ClockSource::HSE,
        1,   // M
        16,  // N  → VCO = 16 MHz / 1 * 16 = 256 MHz
        2,   // P
        2,   // Q
        4    // R  → SYSCLK = 256 / 4 = 64 MHz
    }
);
```

Example: STM32F407, HSE 8 MHz, SYSCLK = 168 MHz:

```cpp
ClockSystem::Init(
    ClockSystem::SystemClockSource::PLL,
    8000000,
    ClockSystem::BusDividers{
        ClockSystem::AHB_Divider::DIV1,
        ClockSystem::APB_Divider::DIV4,   // APB1 ≤ 42 MHz
        ClockSystem::APB_Divider::DIV2    // APB2 ≤ 84 MHz
    },
    ClockSystem::PLL_CFGR{
        ClockSystem::PLL_ClockSource::HSE,
        4,    // M → VCO_in = 2 MHz
        168,  // N → VCO = 336 MHz
        2,    // P → SYSCLK = 168 MHz
        7,    // Q → USB/SDIO = 48 MHz
        2
    }
);
```

### Automatic PLL calculation

```cpp
// I want 64 MHz, source — HSE 16 MHz
ClockSystem::InitCalcPLL(64*MHz, ClockSystem::PLL_ClockSource::HSE, 16000000);
```

`InitCalcPLL` picks M/N/R/P on its own.

### Limits

`Init()` checks all frequency limits for the specific MCU and returns `SysInitStatus::InitError` if they are exceeded. Flash latency is configured automatically.

## 4. GPIO / PIN

**Files:** `gpio.hpp`, `gpio.cpp`
**Details:** [GPIO.md](GPIO.md)

### Creating and configuring a pin

```cpp
PIN led(GPIOB, 8);                        // port + pin number
PIN btn(GPIOA, 0);

led.SetUp(PIN::TYPE::OUTPUT_PushPull);    // push-pull output
btn.SetUp(PIN::TYPE::INPUT_PullUp);       // input with pull-up

led.SetLevel(true);      // HIGH
led.SetLevel(false);     // LOW
led.TogglePin();         // toggle

bool state = btn.GetLevel();   // read the state
```

### All pin types

| Constant | Description |
|---|---|
| `INPUT_NO_Pull` | Input without pull |
| `INPUT_PullUp` | Input pulled up to VCC |
| `INPUT_PullDown` | Input pulled down to GND |
| `OUTPUT_PushPull` | Push-pull output |
| `OUTPUT_OD` | Open-drain output |
| `OUTPUT_OD_PulUp` | Open-drain + pull-up |
| `AF_PushPull` | Alternate function, push-pull |
| `AF_OD` | Alternate function, open-drain |
| `ANALOG` | Analog mode (for ADC/DAC) |

### Output speed

```cpp
led.SetUp(PIN::TYPE::OUTPUT_PushPull, PIN::OUTPUT_SPEED::High);
```

### Alternate function

```cpp
PIN sck(GPIOA, 5);
sck.SetUp(PIN::TYPE::AF_PushPull, 5);   // AF5 = SPI1 on most F4/G0 parts
```

Drivers (USART, SPI, TIM) call `SetUp(AF_PushPull, af)` automatically.

### Assignment and conversion operator

```cpp
led = true;       // SetLevel(true)
led = false;      // SetLevel(false)
bool b = (bool)led;   // GetLevel()
```

### IsValid()

A pin created via `PIN{}` (the default constructor) returns `IsValid() == false`. Drivers use this as a "channel not connected" marker:

```cpp
SPI spi(SPI1, sck, mosi, PIN{}, PIN{});   // MISO and SS are not used
```

### PinArray — an array of pins

```cpp
PIN segments[] = {
    PIN(GPIOA, 0), PIN(GPIOA, 1), PIN(GPIOA, 2), PIN(GPIOA, 3)
};
PinArray<4> seg_pins(segments);

seg_pins.SetUpAll(PIN::TYPE::OUTPUT_PushPull);
seg_pins.SetLevelAll(0b1010);    // set by bits
uint32_t state = seg_pins.GetLevelAll();  // read all at once
```

## 5. IRQ_Registry

**Files:** `irq_registry.hpp`, `irq_registry.cpp`, `irq_registry_config.h`
**Details:** [IRQ_Registry.md](IRQ_Registry.md)

### The idea

Instead of `extern "C" void USART1_IRQHandler() { my_usart.HandleIRQ(); }` for every peripheral, there's a single object-registration mechanism. The stubs in `irq_registry_config.h` always call `IRQ_Registry::Dispatch(IRQn)`, which delegates to the registered object.

### IIRQHandler

Any class that wants to handle interrupts inherits from `IIRQHandler`:

```cpp
class MyHandler : public IIRQHandler {
    void HandleIRQ() override {
        // called from the ISR
    }
};
```

### Manual registration

```cpp
MyHandler handler;
IRQ_Registry::Register(TIM3_IRQn, &handler);
NVIC_EnableIRQ(TIM3_IRQn);
```

Most drivers do this **automatically** when `IRQ_en()` is called.

### Registration without inheritance (a plain function)

If writing a separate class just for `IIRQHandler` is overkill (a one-off handler, test code), you can register a plain function (or a non-capturing lambda) directly, with an optional context:

```cpp
void OnButtonIrq(void* ctx) {
    static_cast<Button*>(ctx)->Poll();
}

IRQ_Registry::Register(EXTI0_IRQn, OnButtonIrq, &my_button);
NVIC_EnableIRQ(EXTI0_IRQn);
```

Under the hood, this creates an `IIRQHandler` adapter from a separate static pool (`IRQ_MAX_FUNCTION_HANDLERS`, 8 by default) — details and edge cases are in [IRQ_Registry.md](IRQ_Registry.md#11-регистрация-без-наследования-function-обработчики).

### Unregistering

```cpp
IRQ_Registry::Unregister(TIM3_IRQn);
NVIC_DisableIRQ(TIM3_IRQn);
```

### Shared IRQ lines (one vector for multiple channels)

On STM32G0, channels DMA1_Channel2 and DMA1_Channel3 share one vector, `DMA1_Channel2_3_IRQn`.
`IRQ_Registry` supports a **linked list of handlers** on a single line:

```cpp
// First registration — creates the head of the list
IRQ_Registry::Register(DMA1_Channel2_3_IRQn, &handler_ch2);
// Second — appended to the end of the chain, BKPT does not fire
IRQ_Registry::Register(DMA1_Channel2_3_IRQn, &handler_ch3);
```

`Dispatch` calls **both** handlers in turn. Each one checks its own TC flag:

```cpp
void HandleIRQ() override {
    if (_dma->GetTC_Flag()) {   // only if it was specifically my channel that fired
        // ...
    }
}
```

### Adding a new vector

Add a line to `irq_registry_config.h`:

```cpp
extern "C" void NEW_IRQHandler() { IRQ_Registry::Dispatch(NEW_IRQn); }
```

And increase `IRQ_TABLE_SIZE` if `NEW_IRQn` is larger than the current maximum.

## 6. DMA

**Files:** `dma.hpp`, `dma.cpp`, `dma_requests.hpp`
**Details:** [DMA.md](DMA.md)

Supports F4/F7 (streams, `DMA_Stream_TypeDef`) and G0 (channels, `DMA_Channel_TypeDef`). The API is identical for both families.

### Constructor (STM32G0)

On G0, DMAMUX1 lets you connect any channel to any peripheral. The user picks the channel; the request comes from the `Req::` table:

```cpp
// Option 1: channel + request from the table (recommended)
DMA_Sx dma_tx(DMA1_Channel4, DMA_Sx::Req::Usart1::TX);
DMA_Sx dma_rx(DMA1_Channel5, DMA_Sx::Req::Usart1::RX);

// Option 2: channel + raw DMAMUX1 request ID
DMA_Sx dma(DMA1_Channel3, 48u);

// Option 3: channel without a request (ID supplied later via StreamSettings)
DMA_Sx dma(DMA1_Channel3);
```

### Constructor (STM32F4/F7)

On F4, the stream and CHSEL are hard-wired to the peripheral:

```cpp
DMA_Sx dma_tx(DMA_Sx::Req::Usart1::TX);       // DMA2, Stream7, CH4
DMA_Sx dma_tx(DMA_Sx::Req::Usart1::TX_alt);   // alternative stream
```

### Configuration via StreamSettings

```cpp
DMA_Sx::StreamSettings cfg;
cfg.direction   = DMA_Sx::DIR::To_Per;    // memory → peripheral
cfg.data_size   = DMA_Sx::SIZE::Byte;     // element width
cfg.minc        = true;                   // increment the memory address
cfg.pinc        = false;                  // peripheral address is fixed
cfg.per_address = reinterpret_cast<uint32_t>(&USARTx->TDR);
cfg.count       = 0;                      // set before each transfer

dma.SetUp(cfg);
```

### Manual transfer start

```cpp
dma.ClearFlags();
dma.SetMemAddr(reinterpret_cast<uint32_t>(buf));
dma.SetCount(len);
dma.Stream_EN(ENABLE);
```

### TC interrupt

```cpp
IRQ_Registry::Register(dma.GetIRQn(), &my_handler);
NVIC_EnableIRQ(dma.GetIRQn());
dma.Enable_IRQ(DMA_Sx::IRQ::TC);
```

In the handler:

```cpp
void HandleIRQ() override {
    if (_dma.GetTC_Flag()) {
        _dma.Stream_EN(DISABLE);
        _dma.ClearFlags();
        // transfer complete
    }
}
```

### Directions

| `DIR` | Value |
|---|---|
| `From_Per` | Peripheral → Memory |
| `To_Per` | Memory → Peripheral |
| `Mem_To_Mem` | Memory → Memory |

### Element width

| `SIZE` | Size |
|---|---|
| `Byte` | 8 bits |
| `Half_Word` | 16 bits |
| `Word` | 32 bits |

### Important: shared IRQs on G0

| Channels | Vector |
|---|---|
| CH1 | `DMA1_Channel1_IRQn` (exclusive) |
| CH2, CH3 | `DMA1_Channel2_3_IRQn` (shared) |
| CH4, CH5 (G030/G031/G041) | `DMA1_Ch4_5_DMAMUX1_OVR_IRQn` (shared) |
| CH4–CH7 (G05x/G06x/G07x/G08x) | `DMA1_Ch4_7_DMAMUX1_OVR_IRQn` (shared) |
| DMA1 CH4–CH7 + DMA2 CH1–CH5 (G0Bx/G0Cx) | `DMA1_Ch4_7_DMA2_Ch1_5_DMAMUX1_OVR_IRQn` (shared) |

Several channels on one vector is not a problem: `IRQ_Registry` supports a chain of handlers
(`IRQ_MAX_SHARED = 4` on G0).

## 7. USART

**Files:** `uart.hpp`, `uart.cpp`, `uart_defs.hpp`
**Details:** [UART.md](UART.md)

### Basic usage

```cpp
USART debug(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);

debug.SetUp();
debug.Send((uint8_t*)"Hello\r\n", 7);

uint8_t buf[16];
debug.Receive(buf, sizeof(buf), 500);  // 500 ms timeout
```

### TX only (no RX)

```cpp
USART log(USART2, 115200, USART::_2::TX::PA2, PIN{});
log.SetUp();
log.Send((uint8_t*)"OK\r\n", 4);
```

### DMA transfer

```cpp
USART  uart(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);
DMA_Sx dma_tx(DMA1_Channel4, DMA_Sx::Req::Usart1::TX);
DMA_Sx dma_rx(DMA1_Channel5, DMA_Sx::Req::Usart1::RX);

uart.SetUp();
uart.AttachDMA(&dma_tx, &dma_rx);   // no need to call DMA's SetUp separately

uart.Send_DMA(tx_buf, sizeof(tx_buf));
uart.Receive_DMA(rx_buf, sizeof(rx_buf));  // completes on IDLE or when the buffer fills
```

### Interrupts

```cpp
uart.IRQ_en(USART::IRQ::RXNE, ENABLE);   // enable the RXNE interrupt
uart.IRQ_en(USART::IRQ::TXE, DISABLE);   // disable the TXE interrupt
```

On the first `IRQ_en(..., ENABLE)` — the object registers itself in `IRQ_Registry` and enables the NVIC.
On the last `IRQ_en(..., DISABLE)` — it unregisters and disables the NVIC.

### Custom interrupt handling (inheritance)

```cpp
class MyUART : public USART {
    using USART::USART;  // inherit the constructor
    void OnRxByte(uint8_t b) override { ring_buf.push(b); }
    void OnIdle()            override { process_packet();  }
};

MyUART uart(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);
```

### Changing the baud rate on the fly

```cpp
uart.SetBaud(9600);
```

## 8. SPI

**Files:** `spi.hpp`, `spi.cpp`, `spi_defs.hpp`
**Details:** [SPI.md](SPI.md)

### Basic usage (blocking mode)

```cpp
SPI spi(SPI1, SPI::_1::SCK::PA5, SPI::_1::MOSI::PA7,
                SPI::_1::MISO::PA6, SPI::_1::SS::PA4);

spi.SetUp(SPI::Master_sel::Master,
          SPI::NSS_ctrl::Software,
          SPI::TYPE::TXRX,
          SPI::Data_frame_format::Byte,
          SPI::Frame_Format::MSB,
          SPI::cPolPha::None,
          SPI::BaudRate::DIV4);

spi.SlaveSelect(ENABLE);
spi.Send(tx_buf, sizeof(tx_buf));
spi.SlaveSelect(DISABLE);
```

### Half-duplex (TX only)

```cpp
SPI spi(SPI2, SPI::_2::SCK::PB10, SPI::_2::MOSI::PB11, PIN{}, PIN(GPIOB, 12));

spi.SetUp(SPI::Master_sel::Master, SPI::NSS_ctrl::Software,
          SPI::TYPE::TX, SPI::Data_frame_format::Byte,
          SPI::Frame_Format::MSB, SPI::cPolPha::None, SPI::BaudRate::DIV4);
```

### DMA transfer

```cpp
SPI    spi(SPI1, SPI::_1::SCK::PA5, SPI::_1::MOSI::PA7);
DMA_Sx dma_tx(DMA1_Channel3);

spi.SetUp(...);
spi.AttachDMA(&dma_tx, nullptr);  // nullptr = no RX DMA
spi.SendDMA(buf, len);            // non-blocking transfer

// Completion callback — override in a subclass:
// void OnDmaTxComplete() override { ... }
```

| Constant | Divider |
|---|---|
| `DIV2` | PCLK / 2 |
| `DIV4` | PCLK / 4 |
| `DIV8` | PCLK / 8 |
| ... | ... |
| `DIV256` | PCLK / 256 |

| Constant | CPOL | CPHA | SPI Mode |
|---|---|---|---|
| `None` | 0 | 0 | Mode 0 |
| `cPha` | 0 | 1 | Mode 1 |
| `cPol` | 1 | 0 | Mode 2 |
| `cPolPha` | 1 | 1 | Mode 3 |

## 9. TIM

**Files:** `tim.hpp`, `tim.cpp`
**Details:** [TIM.md](TIM.md)

Class hierarchy:

```
TIM : IIRQHandler
    TIM_PeriodicIRQ      — periodic interrupts
    TIM_PWM              — PWM outputs (1–4 channels), DMA support
    TIM_InputCapture     — input signal capture
    TIM_PulseMeasure     — period and pulse-width measurement (PWM input)
    TIM_EncoderGenerator — quadrature pulse generator for stepper motors
```

### TIM_PeriodicIRQ — periodic interrupts

```cpp
TIM_PeriodicIRQ timer(TIM3);

// Configuration: 1000 Hz (1 kHz), callback
timer.SetUp(1000, []{ led.TogglePin(); });
timer.Start();
```

`SetUp()` automatically computes PSC and ARR, enables the UE interrupt, and registers the object in `IRQ_Registry`. `Start()` must be called explicitly.

### TIM_PWM — PWM

```cpp
// Single-channel PWM on PA8 (TIM1 CH1)
TIM_PWM pwm(TIM1, PIN{GPIOA, 8});

pwm.SetUp(10000);          // 10 kHz PWM, ARR=999 (0.1% resolution)
pwm.SetDuty(TIM::TIM_Channel::CH1, 75);   // 75% duty cycle
```

Four-channel PWM:

```cpp
TIM_PWM pwm(TIM3,
    PIN{GPIOA, 6},  // CH1
    PIN{GPIOA, 7},  // CH2
    PIN{GPIOB, 0},  // CH3
    PIN{GPIOB, 1}   // CH4
);
pwm.SetUp(50);   // 50 Hz (servos)
pwm.SetDuty(TIM::TIM_Channel::CH1, 5);   // 5% = ~1 ms (min angle)
pwm.SetDuty(TIM::TIM_Channel::CH1, 10);  // 10% = ~2 ms (max angle)
```

Direct CCR writes (for protocols like WS2812B):

```cpp
TIM_PWM ws(TIM1, PIN{GPIOA, 8});
ws.SetUp(800000, 79);    // 800 kHz, ARR=79 (explicit ARR)
ws.SetCCR(TIM::TIM_Channel::CH1, 52);   // ~0.8 us (bit "1")
ws.SetCCR(TIM::TIM_Channel::CH1, 26);   // ~0.4 us (bit "0")
```

### TIM_PWM + DMA — generating WS2812B

The most powerful mode: DMA writes CCR values on every Update event, with no CPU involvement.

```cpp
constexpr size_t N_LEDS = 8;
constexpr uint16_t ONE  = 52;
constexpr uint16_t ZERO = 26;

static uint16_t ws_buf[N_LEDS * 24 + 40];  // +40 zeros = 50 us reset
// ... fill ws_buf with ONE/ZERO values

DMA_Sx dma_ws(DMA1_Channel3);
TIM_PWM ws_tim(TIM1, PIN{GPIOA, 8});

ws_tim.SetUp(800000, 79);                         // 800 kHz, ARR=79
ws_tim.AttachDMA(&dma_ws, TIM::TIM_Channel::CH1); // attach DMA to CH1
ws_tim.SetDMACallback([]{ /* transfer complete */ });

ws_tim.SendDMA(ws_buf, sizeof(ws_buf)/sizeof(ws_buf[0]));

// Readiness check:
while (ws_tim.IsDMABusy()) {}
```

`AttachDMA` configures DMAMUX1, the peripheral address (CCR1), the Half_Word width, and registers the DMA TC handler in `IRQ_Registry` automatically.

### TIM_InputCapture — capture

```cpp
TIM_InputCapture cap(TIM3, PIN{GPIOA, 6}, TIM::TIM_Channel::CH1);

cap.SetUp(100000, []{ uint32_t v = cap.GetCapture(); /* ... */ });
cap.Start();
```

### TIM_PulseMeasure — measuring a PWM signal

PWM-input mode: one channel measures the period, the other the pulse width.

```cpp
TIM_PulseMeasure pm(TIM3, TIM::Line{PIN{GPIOA, 6}, TIM::TIM_Channel::CH1});
pm.SetUp(100000);   // maximum expected frequency 100 kHz
pm.Start();

// After the signal arrives:
uint32_t period = pm.GetPeriod();   // period in timer ticks
uint32_t width  = pm.GetWidth();    // pulse width
pm.Clear();
```

### TIM_EncoderGenerator — quadrature generator

```cpp
TIM_EncoderGenerator enc(TIM3,
    TIM::Line{PIN{GPIOA, 6}, TIM::TIM_Channel::CH1},  // A
    TIM::Line{PIN{GPIOA, 7}, TIM::TIM_Channel::CH2}   // B (90° shift)
);

enc.SetUp(1000, 99, 50, 50);  // 1000 Hz, period ARR=99, CCR=50 for both channels
enc.SetCompleteCallback([]{ /* complete */ });
enc.GenPulse(200);   // 200 steps forward
enc.GenPulse(-50);   // 50 steps backward
```

### PSC/ARR calculation algorithm

```
ratio = bus_clk / freq         // full product (PSC+1)*(ARR+1)
psc   = ratio / 65536          // minimum divider so ARR fits into 16 bits
arr   = ratio / (psc+1) - 1    // maximum ARR for the best resolution
```

For `TIM_PWM` with an explicit ARR:

```
psc = bus_clk / ((arr+1) * freq) - 1
```

### Supported timers (STM32G0)

| Peripheral | Bus | irq_up | irq_cc | BDTR | AF |
|---|---|---|---|---|---|
| TIM1 | APB2 | TIM1_BRK_UP_TRG_COM | TIM1_CC | yes | 2 |
| TIM3 | APB1 | TIM3 | TIM3 | no | 1 |
| TIM14 | APB2 | TIM14 | TIM14 | no | 4 |
| TIM16 | APB2 | TIM16 | TIM16 | yes | 2 |
| TIM17 | APB2 | TIM17 | TIM17 | yes | 2 |

`has_bdtr = true` means an advanced/semi-advanced timer that requires setting `TIM_BDTR_MOE` to activate the outputs.

## 10. RTC

**Files:** `rtc.hpp`, `rtc.cpp`
**Details:** [RTC.md](RTC.md)

A fully static class — no objects are created. All methods are called as `RTC_cl::SetUp(...)`.

### Initialization

```cpp
// LSE — a 32.768 kHz crystal (recommended for accuracy)
RTC_cl::SetUp(RTC_cl::CLK_Source::LSE);

// LSI — internal RC ~32 kHz (no external components, less accurate)
RTC_cl::SetUp(RTC_cl::CLK_Source::LSI);
```

By default: `prediv_a = 127`, `prediv_s = 255` → 32768 / (128 × 256) = 1 Hz.

If `ICSR::RSF == 0` (the RTC is already synchronized, e.g. after exiting Stop), initialization is skipped — the time is not reset.

### Setting the time and date

```cpp
RTC_cl::SetTime({14, 25, 00});                           // 14:25:00
RTC_cl::SetDate({22, 05, 26}, RTC_cl::WeekDay::Friday);  // 22.05.2026, Fri
```

### WakeUp Timer — periodic interrupts

```cpp
// Every second (counter=0, clock_div=0b100 = ck_spre=1Hz → period = counter+1 sec)
RTC_cl::EnableWakeUpTimer(0, 0b100, []{ read_sensors(); });

// Every 5 seconds
RTC_cl::EnableWakeUpTimer(4, 0b100, []{ ... });
```

### Alarm A / Alarm B

Triggering at a specific time:

```cpp
RTC_cl::AlarmConfig cfg {
    .hour = {14, RTC_cl::Alarm_Masks::Care},  // match hour 14
    .min  = {25, RTC_cl::Alarm_Masks::Care},  // match minute 25
    .sec  = { 0, RTC_cl::Alarm_Masks::Care},  // match second 0
    // day — not specified → mask = Ignore → any day
};
RTC_cl::EnableAlarm_A(ENABLE, cfg, []{ buzz(); });
```

Fields with `mask = Alarm_Masks::Ignore` (the default) are not compared.

Disabling the alarm:

```cpp
RTC_cl::EnableAlarm_A(DISABLE);
```

### Reading the current time

```cpp
// Direct register reads (inside the WUT callback):
uint8_t hours   = ((RTC->TR & RTC_TR_HT)  >> RTC_TR_HT_Pos)  * 10
                 + (RTC->TR & RTC_TR_HU);
uint8_t minutes = ((RTC->TR & RTC_TR_MNT) >> RTC_TR_MNT_Pos) * 10
                 + ((RTC->TR & RTC_TR_MNU) >> RTC_TR_MNU_Pos);
uint8_t seconds = ((RTC->TR & RTC_TR_ST)  >> RTC_TR_ST_Pos)  * 10
                 + (RTC->TR & RTC_TR_SU);
```

### Subseconds

`RTC->SSR` counts down from `prediv_s` (255) to 0 over one second. Resolution:
```
t_ss = 1 / (prediv_s + 1) = 1/256 ≈ 3.9 ms
```

### Calibration output (512 Hz / 1 Hz)

```cpp
RTC_cl::EnableCOE(true);   // outputs the signal on the RTC_CALIB pin
```

Useful for measuring crystal accuracy with an oscilloscope. Expected frequency at prediv_a=127, prediv_s=255: **512 Hz** (RTCCLK / 64).

### Write protection

The methods manage the protection automatically. The unlock sequence: write `0xCA`, then `0x53` into `RTC->WPR`. Locking: write any invalid key (e.g. `0xFF`).

## 11. Flash

**Files:** `flash.hpp`, `flash.cpp`
**Details:** [Flash.md](Flash.md)

### flash_base — low-level access

```cpp
flash_base::init();
flash_base::enable_access();  // unlock writing (KEYR keys)

// Read any type
uint32_t val = flash_base::read<uint32_t>(0x08010000);

// Write
uint32_t data[] = {0x12345678, 0xDEADBEEF};
flash_base::write(0x08010000, data, 2);

// Erase a sector
flash_base::erase_sector(3);
```

On **STM32G0** writes are always 64-bit (two consecutive 32-bit operations). On **F4**, 8/16/32/64-bit writes are supported with automatic `PSIZE` configuration.

### flash_data — storing structures in Flash

```cpp
uint8_t settings_buf[32];
flash_data settings(7,            // sector number
                    settings_buf, // data buffer in RAM
                    sizeof(settings_buf));

settings.SetUp();

// Read the last saved data
auto status = settings.read_data();
if (status == flash_data::Data_Status::DATA_OK) {
    // settings_buf contains the current data
}

// Write new data (append-log inside the sector)
memcpy(settings_buf, &my_config, sizeof(my_config));
settings.write_data();
```

`flash_data` uses wear-leveling within a single sector: each write is appended at the end, and `find_offset()` finds the last valid entry during initialization.

## Order of initialization in main()

```cpp
int main() {
    System::Init();      // 1. FPU, Flash latency, SysTick

    ClockSystem::Init(   // 2. Clocking
        ClockSystem::SystemClockSource::PLL, ...);

    // 3. Peripherals — in any order
    uart.SetUp();
    spi.SetUp(...);
    rtc.SetUp(...);

    // 4. DMA — after SetUp() of the corresponding peripheral
    uart.AttachDMA(&dma_tx, &dma_rx);
    spi.AttachDMA(&dma_spi_tx, nullptr);
    tim_pwm.AttachDMA(&dma_tim, TIM::TIM_Channel::CH1);

    // 5. Start timers that require an explicit Start()
    periodic_timer.Start();

    for (;;) { /* main loop */ }
}
```

## Подключение и сборка

Драйверы включаются одной строкой в `project.json` проекта на `stm32_cmake_base`:

```json
"drivers": ["UART", "SPI", "DMA", "TIM"]
```

- `null` / `false` / ключа нет — драйверы не собираются вообще;
- `true` или `[]` — только ядро (System, RCC, GPIO, Flash, IRQ_Registry);
- `["UART", ...]` — ядро + перечисленные модули. Опечатка в имени — ошибка конфигурации со списком допустимых имён.

Первая конфигурация клонирует репозиторий в `Drivers/`; версию задаёт тег (`GIT_TAG` в `CMakeLists.txt` платформы). Из `stm32_drivers` линкуется цель `stm32_platform` (флаги, CMSIS, определения чипа). Конфиги под конкретный чип (`flash_config.h` — карта секторов, `irq_registry_config.h` — таблица векторов) библиотека генерирует сама в `cmsis-core/drivers_gen/`.

Ядро подключается заголовками `#include <system.hpp>`, `<rcc.hpp>`, `<gpio.hpp>`, `<flash.hpp>`, `<irq_registry.hpp>`, опциональные модули — `<uart.hpp>`, `<spi.hpp>`, `<tim.hpp>` и т.д. (пример — закомментированный блок в `inc/main.hpp` платформы).

## 1. Архитектурные принципы

### Таблицы периферии (PeriphInfo)

Вместо длинных if-else цепочек вида `if (USARTx == USART1) { RCC->APB2ENR |= ...; }` каждый драйвер хранит **статическую таблицу** с описанием всех экземпляров периферии:

```cpp
struct PeriphInfo {
    USART_TypeDef*      periph;   // указатель на периферию (USART1, USART2...)
    volatile uint32_t*  clk_reg;  // регистр включения тактирования (APBxENR)
    uint32_t            clk_bit;  // бит в clk_reg
    uint32_t const*     bus_clk;  // указатель на переменную с частотой шины
    IRQn_Type           irq;      // номер вектора прерывания
};
static const PeriphInfo usart_table[];
```

При вызове `SetUp()` драйвер проходит по таблице, находит нужную запись по указателю на периферию, и автоматически:
- включает тактирование
- читает актуальную частоту шины
- знает вектор прерывания

Это единственное место, которое нужно обновлять при добавлении нового МК.

### Валидация пинов при компиляции

Пины для USART, SPI выбираются из вложенных структур:

```cpp
USART debug(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);
```

Каждый пин из `USART::_1::TX::PB6` содержит базовый адрес периферии. В конструкторе проверяется соответствие — если передать пин от другого USART, сработает `BKPT` и бесконечный цикл, что мгновенно обнаруживается при отладке.

### IRQ_Registry — единый диспетчер прерываний

Все прерывания проходят через один диспетчер. Стаб-обработчики в `irq_registry_config.h` вызывают `IRQ_Registry::Dispatch(IRQn)`, который перенаправляет вызов зарегистрированному объекту `IIRQHandler`.

Драйверы регистрируются и отменяют регистрацию автоматически при включении/выключении прерывания через `IRQ_en()`.

System::Init();  // включает FPU, настраивает Flash latency, запускает SysTick (1 кГц)

System::Enable_CYCCNT();   // один раз при старте

## 3. RCC / ClockSystem

**Файлы:** `rcc.hpp`, `rcc.cpp`
**Подробнее:** [RCC.md](RCC.md)

Конфигурирует систему тактирования: HSI/HSE, PLL, делители шин AHB/APB.

### Простой запуск (HSI без PLL)

```cpp
ClockSystem::Init();  // HSI 16 МГц, делители DIV1
```

### Запуск с PLL (рекомендуется)

Пример: STM32G0, кварц 16 МГц на входе, SYSCLK = 64 МГц:

```cpp
ClockSystem::Init(
    ClockSystem::SystemClockSource::PLL,
    16000000,  // частота HSE кварца
    ClockSystem::BusDividers{
        ClockSystem::AHB_Divider::DIV1,
        ClockSystem::APB_Divider::DIV1,
        ClockSystem::APB_Divider::DIV1
    },
    ClockSystem::PLL_CFGR{
        ClockSystem::PLL_ClockSource::HSE,
        1,   // M
        16,  // N  → VCO = 16 МГц / 1 * 16 = 256 МГц
        2,   // P
        2,   // Q
        4    // R  → SYSCLK = 256 / 4 = 64 МГц
    }
);
```

Пример: STM32F407, HSE 8 МГц, SYSCLK = 168 МГц:

```cpp
ClockSystem::Init(
    ClockSystem::SystemClockSource::PLL,
    8000000,
    ClockSystem::BusDividers{
        ClockSystem::AHB_Divider::DIV1,
        ClockSystem::APB_Divider::DIV4,   // APB1 ≤ 42 МГц
        ClockSystem::APB_Divider::DIV2    // APB2 ≤ 84 МГц
    },
    ClockSystem::PLL_CFGR{
        ClockSystem::PLL_ClockSource::HSE,
        4,    // M → VCO_in = 2 МГц
        168,  // N → VCO = 336 МГц
        2,    // P → SYSCLK = 168 МГц
        7,    // Q → USB/SDIO = 48 МГц
        2
    }
);
```

### Автоматический расчёт PLL

```cpp
// Хочу 64 МГц, источник — HSE 16 МГц
ClockSystem::InitCalcPLL(64*MHz, ClockSystem::PLL_ClockSource::HSE, 16000000);
```

`InitCalcPLL` сам подберёт M/N/R/P.

### Ограничения

`Init()` проверяет все частотные лимиты для конкретного МК и возвращает `SysInitStatus::InitError` при выходе за допустимые значения. Flash latency настраивается автоматически.

## 4. GPIO / PIN

**Файлы:** `gpio.hpp`, `gpio.cpp`
**Подробнее:** [GPIO.md](GPIO.md)

### Создание и настройка пина

```cpp
PIN led(GPIOB, 8);                        // порт + номер пина
PIN btn(GPIOA, 0);

led.SetUp(PIN::TYPE::OUTPUT_PushPull);    // выход push-pull
btn.SetUp(PIN::TYPE::INPUT_PullUp);       // вход с подтяжкой

led.SetLevel(true);      // HIGH
led.SetLevel(false);     // LOW
led.TogglePin();         // инверсия

bool state = btn.GetLevel();   // читаем состояние
```

### Все типы пинов

| Константа | Описание |
|---|---|
| `INPUT_NO_Pull` | Вход без подтяжки |
| `INPUT_PullUp` | Вход с подтяжкой к VCC |
| `INPUT_PullDown` | Вход с подтяжкой к GND |
| `OUTPUT_PushPull` | Выход push-pull |
| `OUTPUT_OD` | Выход open-drain |
| `OUTPUT_OD_PulUp` | Open-drain + подтяжка |
| `AF_PushPull` | Альтернативная функция, push-pull |
| `AF_OD` | Альтернативная функция, open-drain |
| `ANALOG` | Аналоговый режим (для ADC/DAC) |

### Скорость вывода

```cpp
led.SetUp(PIN::TYPE::OUTPUT_PushPull, PIN::OUTPUT_SPEED::High);
```

### Альтернативная функция

```cpp
PIN sck(GPIOA, 5);
sck.SetUp(PIN::TYPE::AF_PushPull, 5);   // AF5 = SPI1 на большинстве F4/G0
```

Драйверы (USART, SPI, TIM) вызывают `SetUp(AF_PushPull, af)` автоматически.

### Оператор присваивания и преобразования

```cpp
led = true;       // SetLevel(true)
led = false;      // SetLevel(false)
bool b = (bool)led;   // GetLevel()
```

### IsValid()

Пин, созданный через `PIN{}` (конструктор по умолчанию), возвращает `IsValid() == false`. Используется в драйверах как признак "канал не подключён":

```cpp
SPI spi(SPI1, sck, mosi, PIN{}, PIN{});   // MISO и SS не используются
```

### PinArray — массив пинов

```cpp
PIN segments[] = {
    PIN(GPIOA, 0), PIN(GPIOA, 1), PIN(GPIOA, 2), PIN(GPIOA, 3)
};
PinArray<4> seg_pins(segments);

seg_pins.SetUpAll(PIN::TYPE::OUTPUT_PushPull);
seg_pins.SetLevelAll(0b1010);    // установить по битам
uint32_t state = seg_pins.GetLevelAll();  // прочитать все сразу
```

## 5. IRQ_Registry

**Файлы:** `irq_registry.hpp`, `irq_registry.cpp`, `irq_registry_config.h`
**Подробнее:** [IRQ_Registry.md](IRQ_Registry.md)

### Идея

Вместо `extern "C" void USART1_IRQHandler() { my_usart.HandleIRQ(); }` для каждой периферии — единый механизм регистрации объектов. Стабы в `irq_registry_config.h` всегда зовут `IRQ_Registry::Dispatch(IRQn)`, который делегирует зарегистрированному объекту.

### IIRQHandler

Любой класс, который хочет обрабатывать прерывания, наследует `IIRQHandler`:

```cpp
class MyHandler : public IIRQHandler {
    void HandleIRQ() override {
        // вызывается из ISR
    }
};
```

### Регистрация вручную

```cpp
MyHandler handler;
IRQ_Registry::Register(TIM3_IRQn, &handler);
NVIC_EnableIRQ(TIM3_IRQn);
```

Большинство драйверов делают это **автоматически** при вызове `IRQ_en()`.

### Регистрация без наследования (обычная функция)

Если писать отдельный класс ради `IIRQHandler` избыточно (разовый обработчик,
тестовый код), можно зарегистрировать обычную функцию (или non-capturing lambda)
напрямую, с опциональным контекстом:

```cpp
void OnButtonIrq(void* ctx) {
    static_cast<Button*>(ctx)->Poll();
}

IRQ_Registry::Register(EXTI0_IRQn, OnButtonIrq, &my_button);
NVIC_EnableIRQ(EXTI0_IRQn);
```

Под капотом создаётся `IIRQHandler`-адаптер из отдельного статического пула
(`IRQ_MAX_FUNCTION_HANDLERS`, по умолчанию 8) — подробности и угловые случаи
в [IRQ_Registry.md](IRQ_Registry.md#11-регистрация-без-наследования-function-обработчики).

### Отмена регистрации

```cpp
IRQ_Registry::Unregister(TIM3_IRQn);
NVIC_DisableIRQ(TIM3_IRQn);
```

### Разделяемые IRQ-линии (общий вектор для нескольких каналов)

На STM32G0 каналы DMA1_Channel2 и DMA1_Channel3 делят один вектор `DMA1_Channel2_3_IRQn`.  
`IRQ_Registry` поддерживает **связный список обработчиков** на одной линии:

```cpp
// Первая регистрация — создаёт голову списка
IRQ_Registry::Register(DMA1_Channel2_3_IRQn, &handler_ch2);
// Вторая — добавляется в конец цепочки, BKPT не срабатывает
IRQ_Registry::Register(DMA1_Channel2_3_IRQn, &handler_ch3);
```

`Dispatch` вызывает **оба** обработчика по очереди. Каждый сам проверяет свой TC-флаг:

```cpp
void HandleIRQ() override {
    if (_dma->GetTC_Flag()) {   // только если именно мой канал сработал
        // ...
    }
}
```

### Добавление нового вектора

В `irq_registry_config.h` добавить строку:

```cpp
extern "C" void NEW_IRQHandler() { IRQ_Registry::Dispatch(NEW_IRQn); }
```

И увеличить `IRQ_TABLE_SIZE` если `NEW_IRQn` больше текущего максимума.

## 6. DMA

**Файлы:** `dma.hpp`, `dma.cpp`, `dma_requests.hpp`
**Подробнее:** [DMA.md](DMA.md)

Поддерживает F4/F7 (потоки, `DMA_Stream_TypeDef`) и G0 (каналы, `DMA_Channel_TypeDef`). API идентичен для обоих семейств.

### Конструктор (STM32G0)

На G0 DMAMUX1 позволяет подключить любой канал к любой периферии. Канал выбирает пользователь, запрос — из таблицы `Req::`:

```cpp
// Вариант 1: канал + запрос из таблицы (рекомендуется)
DMA_Sx dma_tx(DMA1_Channel4, DMA_Sx::Req::Usart1::TX);
DMA_Sx dma_rx(DMA1_Channel5, DMA_Sx::Req::Usart1::RX);

// Вариант 2: канал + сырой ID запроса DMAMUX1
DMA_Sx dma(DMA1_Channel3, 48u);

// Вариант 3: канал без запроса (ID передаётся позже через StreamSettings)
DMA_Sx dma(DMA1_Channel3);
```

### Конструктор (STM32F4/F7)

На F4 поток и CHSEL жёстко привязаны к периферии:

```cpp
DMA_Sx dma_tx(DMA_Sx::Req::Usart1::TX);       // DMA2, Stream7, CH4
DMA_Sx dma_tx(DMA_Sx::Req::Usart1::TX_alt);   // альтернативный поток
```

### Настройка через StreamSettings

```cpp
DMA_Sx::StreamSettings cfg;
cfg.direction   = DMA_Sx::DIR::To_Per;    // память → периферия
cfg.data_size   = DMA_Sx::SIZE::Byte;     // ширина элемента
cfg.minc        = true;                   // инкремент адреса памяти
cfg.pinc        = false;                  // адрес периферии фиксирован
cfg.per_address = reinterpret_cast<uint32_t>(&USARTx->TDR);
cfg.count       = 0;                      // задаётся перед каждой передачей

dma.SetUp(cfg);
```

### Ручной запуск передачи

```cpp
dma.ClearFlags();
dma.SetMemAddr(reinterpret_cast<uint32_t>(buf));
dma.SetCount(len);
dma.Stream_EN(ENABLE);
```

### Прерывание по TC

```cpp
IRQ_Registry::Register(dma.GetIRQn(), &my_handler);
NVIC_EnableIRQ(dma.GetIRQn());
dma.Enable_IRQ(DMA_Sx::IRQ::TC);
```

В обработчике:

```cpp
void HandleIRQ() override {
    if (_dma.GetTC_Flag()) {
        _dma.Stream_EN(DISABLE);
        _dma.ClearFlags();
        // передача завершена
    }
}
```

### Направления

| `DIR` | Значение |
|---|---|
| `From_Per` | Периферия → Память |
| `To_Per` | Память → Периферия |
| `Mem_To_Mem` | Память → Память |

### Ширина элемента

| `SIZE` | Размер |
|---|---|
| `Byte` | 8 бит |
| `Half_Word` | 16 бит |
| `Word` | 32 бита |

### Важно о разделяемых IRQ на G0

| Каналы | Вектор |
|---|---|
| CH1 | `DMA1_Channel1_IRQn` (эксклюзивный) |
| CH2, CH3 | `DMA1_Channel2_3_IRQn` (общий) |
| CH4, CH5 (G030/G031/G041) | `DMA1_Ch4_5_DMAMUX1_OVR_IRQn` (общий) |
| CH4–CH7 (G05x/G06x/G07x/G08x) | `DMA1_Ch4_7_DMAMUX1_OVR_IRQn` (общий) |
| DMA1 CH4–CH7 + DMA2 CH1–CH5 (G0Bx/G0Cx) | `DMA1_Ch4_7_DMA2_Ch1_5_DMAMUX1_OVR_IRQn` (общий) |

Несколько каналов на одном векторе — не проблема: `IRQ_Registry` поддерживает цепочку обработчиков
(`IRQ_MAX_SHARED = 4` на G0).

**Файлы:** `uart.hpp`, `uart.cpp`, `uart_defs.hpp`
**Подробнее:** [UART.md](UART.md)

### Базовое использование

```cpp
USART debug(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);

debug.SetUp();
debug.Send((uint8_t*)"Hello\r\n", 7);

```

### Только TX (без RX)

```cpp
USART log(USART2, 115200, USART::_2::TX::PA2, PIN{});
log.SetUp();
log.Send((uint8_t*)"OK\r\n", 4);
```

### DMA-передача

```cpp
USART  uart(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);
DMA_Sx dma_tx(DMA1_Channel4, DMA_Sx::Req::Usart1::TX);
DMA_Sx dma_rx(DMA1_Channel5, DMA_Sx::Req::Usart1::RX);

uart.SetUp();
uart.AttachDMA(&dma_tx, &dma_rx);   // SetUp DMA вызывать отдельно НЕ нужно

uart.Send_DMA(tx_buf, sizeof(tx_buf));
uart.Receive_DMA(rx_buf, sizeof(rx_buf));  // завершается по IDLE или по заполнению
```

### Прерывания

```cpp
uart.IRQ_en(USART::IRQ::RXNE, ENABLE);   // включить RXNE-прерывание
uart.IRQ_en(USART::IRQ::TXE, DISABLE);   // выключить TXE-прерывание
```

При первом `IRQ_en(..., ENABLE)` — объект сам регистрируется в `IRQ_Registry` и включает NVIC.

### Собственная обработка прерываний (наследование)

```cpp
class MyUART : public USART {
    using USART::USART;  // наследуем конструктор
    void OnRxByte(uint8_t b) override { ring_buf.push(b); }
    void OnIdle()            override { process_packet();  }
};

MyUART uart(USART1, 115200, USART::_1::TX::PB6, USART::_1::RX::PB7);
```

### Изменение baudrate на лету

```cpp
uart.SetBaud(9600);
```

## 9. TIM

**Файлы:** `tim.hpp`, `tim.cpp`
**Подробнее:** [TIM.md](TIM.md)

Иерархия классов:

```
TIM : IIRQHandler
    TIM_PeriodicIRQ      — периодические прерывания
    TIM_PWM              — ШИМ-выходы (1–4 канала), поддержка DMA
    TIM_InputCapture     — захват входного сигнала
    TIM_PulseMeasure     — измерение периода и длительности импульса (PWM-input)
    TIM_EncoderGenerator — генератор квадратурных импульсов для шаговых двигателей
```

### TIM_PeriodicIRQ — периодические прерывания

```cpp
TIM_PeriodicIRQ timer(TIM3);

// Настройка: 1000 Гц (1 кГц), колбэк
timer.SetUp(1000, []{ led.TogglePin(); });
timer.Start();
```

`SetUp()` автоматически вычисляет PSC и ARR, включает UE-прерывание и регистрирует объект в `IRQ_Registry`. `Start()` нужно вызвать явно.

### TIM_PWM — ШИМ

```cpp
// Одноканальный ШИМ на PA8 (TIM1 CH1)
TIM_PWM pwm(TIM1, PIN{GPIOA, 8});

pwm.SetUp(10000);          // 10 кГц ШИМ, ARR=999 (0.1% разрешение)
pwm.SetDuty(TIM::TIM_Channel::CH1, 75);   // 75% скважность
```

Четырёхканальный ШИМ:

```cpp
TIM_PWM pwm(TIM3,
    PIN{GPIOA, 6},  // CH1
    PIN{GPIOA, 7},  // CH2
    PIN{GPIOB, 0},  // CH3
    PIN{GPIOB, 1}   // CH4
);
pwm.SetUp(50);   // 50 Гц (сервоприводы)
pwm.SetDuty(TIM::TIM_Channel::CH1, 5);   // 5% = ~1 мс (мин угол)
pwm.SetDuty(TIM::TIM_Channel::CH1, 10);  // 10% = ~2 мс (макс угол)
```

Прямая запись CCR (для протоколов типа WS2812B):

```cpp
TIM_PWM ws(TIM1, PIN{GPIOA, 8});
ws.SetUp(800000, 79);    // 800 кГц, ARR=79 (явный ARR)
ws.SetCCR(TIM::TIM_Channel::CH1, 52);   // ~0.8 мкс (бит "1")
ws.SetCCR(TIM::TIM_Channel::CH1, 26);   // ~0.4 мкс (бит "0")
```

### TIM_PWM + DMA — генерация WS2812B

Самый мощный режим: DMA записывает CCR-значения на каждое событие Update, без участия CPU.

```cpp
constexpr size_t N_LEDS = 8;
constexpr uint16_t ONE  = 52;
constexpr uint16_t ZERO = 26;

static uint16_t ws_buf[N_LEDS * 24 + 40];  // +40 нулей = 50 мкс reset
// ... заполнить ws_buf значениями ONE/ZERO

DMA_Sx dma_ws(DMA1_Channel3);
TIM_PWM ws_tim(TIM1, PIN{GPIOA, 8});

ws_tim.SetUp(800000, 79);                         // 800 кГц, ARR=79
ws_tim.AttachDMA(&dma_ws, TIM::TIM_Channel::CH1); // привязать DMA к CH1
ws_tim.SetDMACallback([]{ /* передача завершена */ });

ws_tim.SendDMA(ws_buf, sizeof(ws_buf)/sizeof(ws_buf[0]));

// Проверка готовности:
while (ws_tim.IsDMABusy()) {}
```

`AttachDMA` настраивает DMAMUX1, периферийный адрес (CCR1), ширину Half_Word и регистрирует обработчик DMA TC в `IRQ_Registry` автоматически.

### TIM_InputCapture — захват

```cpp
TIM_InputCapture cap(TIM3, PIN{GPIOA, 6}, TIM::TIM_Channel::CH1);

cap.SetUp(100000, []{ uint32_t v = cap.GetCapture(); /* ... */ });
cap.Start();
```

### TIM_PulseMeasure — измерение PWM-сигнала

Режим PWM-input: один канал измеряет период, второй — ширину импульса.

```cpp
TIM_PulseMeasure pm(TIM3, TIM::Line{PIN{GPIOA, 6}, TIM::TIM_Channel::CH1});
pm.SetUp(100000);   // максимальная ожидаемая частота 100 кГц
pm.Start();

// После прихода сигнала:
uint32_t period = pm.GetPeriod();   // период в тактах таймера
uint32_t width  = pm.GetWidth();    // ширина импульса
pm.Clear();
```

### TIM_EncoderGenerator — квадратурный генератор

```cpp
TIM_EncoderGenerator enc(TIM3,
    TIM::Line{PIN{GPIOA, 6}, TIM::TIM_Channel::CH1},  // A
    TIM::Line{PIN{GPIOA, 7}, TIM::TIM_Channel::CH2}   // B (90° сдвиг)
);

enc.SetUp(1000, 99, 50, 50);  // 1000 Гц, период ARR=99, CCR=50 для обоих каналов
enc.SetCompleteCallback([]{ /* завершено */ });
enc.GenPulse(200);   // 200 шагов вперёд
enc.GenPulse(-50);   // 50 шагов назад
```

### Алгоритм вычисления PSC/ARR

```
ratio = bus_clk / freq         // полное произведение (PSC+1)*(ARR+1)
psc   = ratio / 65536          // минимальный делитель, чтобы ARR влез в 16 бит
arr   = ratio / (psc+1) - 1    // максимальный ARR для наилучшего разрешения
```

Для `TIM_PWM` с явным ARR:

```
psc = bus_clk / ((arr+1) * freq) - 1
```

### Поддерживаемые таймеры (STM32G0)

| Периферия | Шина | irq_up | irq_cc | BDTR | AF |
|---|---|---|---|---|---|
| TIM1 | APB2 | TIM1_BRK_UP_TRG_COM | TIM1_CC | да | 2 |
| TIM3 | APB1 | TIM3 | TIM3 | нет | 1 |
| TIM14 | APB2 | TIM14 | TIM14 | нет | 4 |
| TIM16 | APB2 | TIM16 | TIM16 | да | 2 |
| TIM17 | APB2 | TIM17 | TIM17 | да | 2 |

`has_bdtr = true` означает расширенный/полурасширенный таймер, требующий установки `TIM_BDTR_MOE` для активации выходов.

## 10. RTC

**Файлы:** `rtc.hpp`, `rtc.cpp`
**Подробнее:** [RTC.md](RTC.md)

Полностью статический класс — объектов не создаётся. Все методы вызываются как `RTC_cl::SetUp(...)`.

### Инициализация

```cpp
// LSE — кварц 32.768 кГц (рекомендуется для точности)
RTC_cl::SetUp(RTC_cl::CLK_Source::LSE);

// LSI — внутренний RC ~32 кГц (без внешних компонентов, менее точный)
RTC_cl::SetUp(RTC_cl::CLK_Source::LSI);
```

По умолчанию: `prediv_a = 127`, `prediv_s = 255` → 32768 / (128 × 256) = 1 Гц.

Если `ICSR::RSF == 0` (RTC уже синхронизирован, например после выхода из Stop), инициализация пропускается — время не сбрасывается.

### Установка времени и даты

```cpp
RTC_cl::SetTime({14, 25, 00});                           // 14:25:00
RTC_cl::SetDate({22, 05, 26}, RTC_cl::WeekDay::Friday);  // 22.05.2026, Пт
```

### WakeUp Timer — периодические прерывания

```cpp
// Каждую секунду (counter=0, clock_div=0b100 = ck_spre=1Гц → период = counter+1 сек)
RTC_cl::EnableWakeUpTimer(0, 0b100, []{ read_sensors(); });

// Каждые 5 секунд
RTC_cl::EnableWakeUpTimer(4, 0b100, []{ ... });
```

### Alarm A / Alarm B

Срабатывание в конкретное время:

```cpp
RTC_cl::AlarmConfig cfg {
    .hour = {14, RTC_cl::Alarm_Masks::Care},  // матчить час 14
    .min  = {25, RTC_cl::Alarm_Masks::Care},  // матчить минуту 25
    .sec  = { 0, RTC_cl::Alarm_Masks::Care},  // матчить секунду 0
    // day — не указан → mask = Ignore → любой день
};
RTC_cl::EnableAlarm_A(ENABLE, cfg, []{ buzz(); });
```

Поля с `mask = Alarm_Masks::Ignore` (умолчание) не сравниваются.

Отключение будильника:

```cpp
RTC_cl::EnableAlarm_A(DISABLE);
```

### Чтение текущего времени

```cpp
// Прямое чтение регистров (внутри WUT-колбэка):
uint8_t hours   = ((RTC->TR & RTC_TR_HT)  >> RTC_TR_HT_Pos)  * 10
                 + (RTC->TR & RTC_TR_HU);
uint8_t minutes = ((RTC->TR & RTC_TR_MNT) >> RTC_TR_MNT_Pos) * 10
                 + ((RTC->TR & RTC_TR_MNU) >> RTC_TR_MNU_Pos);
uint8_t seconds = ((RTC->TR & RTC_TR_ST)  >> RTC_TR_ST_Pos)  * 10
                 + (RTC->TR & RTC_TR_SU);
```

### Субсекунды

`RTC->SSR` убывает от `prediv_s` (255) до 0 за одну секунду. Разрешение:
```
t_ss = 1 / (prediv_s + 1) = 1/256 ≈ 3.9 мс
```

### Калибровочный выход (512 Гц / 1 Гц)

```cpp
RTC_cl::EnableCOE(true);   // выводит сигнал на вывод RTC_CALIB
```

Полезно для измерения точности кристалла осциллографом. Ожидаемая частота при prediv_a=127, prediv_s=255: **512 Гц** (RTCCLK / 64).

### Защита от записи

Методы управляют защитой автоматически. Последовательность снятия: запись `0xCA`, затем `0x53` в `RTC->WPR`. Установка: запись любого неверного ключа (например `0xFF`).

## 11. Flash

**Файлы:** `flash.hpp`, `flash.cpp`
**Подробнее:** [Flash.md](Flash.md)

### flash_base — низкоуровневый доступ

```cpp
flash_base::init();
flash_base::enable_access();  // разблокировать запись (ключи KEYR)

// Чтение любого типа
uint32_t val = flash_base::read<uint32_t>(0x08010000);

// Запись
uint32_t data[] = {0x12345678, 0xDEADBEEF};
flash_base::write(0x08010000, data, 2);

// Стирание сектора
flash_base::erase_sector(3);
```

На **STM32G0** запись всегда 64-битная (две 32-битных операции подряд). На **F4** поддерживается 8/16/32/64-битная запись с автонастройкой `PSIZE`.

### flash_data — хранение структур во Flash

```cpp
uint8_t settings_buf[32];
flash_data settings(7,            // номер сектора
                    settings_buf, // буфер данных в RAM
                    sizeof(settings_buf));

settings.SetUp();

// Чтение последних сохранённых данных
auto status = settings.read_data();
if (status == flash_data::Data_Status::DATA_OK) {
    // settings_buf содержит актуальные данные
}

// Запись новых данных (append-журнал внутри сектора)
memcpy(settings_buf, &my_config, sizeof(my_config));
settings.write_data();
```

`flash_data` использует wear-leveling внутри одного сектора: каждая запись добавляется в конец, `find_offset()` находит последнюю валидную запись при инициализации.

## Порядок инициализации в main()

```cpp
int main() {
    System::Init();      // 1. FPU, Flash latency, SysTick

    ClockSystem::Init(   // 2. Тактирование
        ClockSystem::SystemClockSource::PLL, ...);

    // 3. Периферия — в любом порядке
    uart.SetUp();
    spi.SetUp(...);
    rtc.SetUp(...);

    // 4. DMA — после SetUp() соответствующей периферии
    uart.AttachDMA(&dma_tx, &dma_rx);
    spi.AttachDMA(&dma_spi_tx, nullptr);
    tim_pwm.AttachDMA(&dma_tim, TIM::TIM_Channel::CH1);

    // 5. Запуск таймеров, которые требуют явного Start()
    periodic_timer.Start();

    for (;;) { /* main loop */ }
}
```
