# WS2812B / RGB / HSV: проблемы и предложения

Дата: 12.10.2026. Проверена рабочая копия; сборки и аппаратные тесты в этом проходе не запускались.

**Файлы:** [src/ws2812b.hpp](../src/ws2812b.hpp).

**Зависимости:** Header с encoding buffer; физическая передача через TIM_PWM и DMA, настройки периода/CCR задаются пользователем.

GRB/MSB-first encoding и RGB::dim() по чтению кода согласованы. Цветовой порядок должен соответствовать конкретной ленте.

## Список для обсуждения

### WS-1 — P2 — SetCCR() не пересчитывает уже закодированные цвета

**Место:** [src/ws2812b.hpp](../src/ws2812b.hpp), строка 166.

**Проблема:** Меняются только _one/_zero; _buf хранит прежние CCR. Метод описан как обновление после изменения настройки timer.

**Последствие / условие:** Повторная отправка уже записанного рисунка использует старые длительности импульсов; новые SetPixel используют новые значения, в одном buffer смешиваются две настройки.

**Возможное решение:** Либо пересчитать весь encoded buffer при изменении CCR, либо ясно документировать необходимость повторного заполнения всех pixels. Не хранить второй массив RGB без согласования расходов RAM.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### WS-2 — P2 — RESET_SLOTS не гарантирует заявленную длительность без знания PWM частоты

**Место:** [src/ws2812b.hpp](../src/ws2812b.hpp), строка 76.

**Проблема:** Комментарий обещает ≥50 мкс, но trailer задан числом slots. При 800 кГц 40 slots дают 50 мкс, при 1 МГц — только 40 мкс. API не знает period.

**Последствие / условие:** Reset/latch интервал может быть короче требуемого для выбранной ленты/частоты.

**Возможное решение:** Зафиксировать в примере реальную частоту и формулу RESET_SLOTS >= ceil(t_reset * f_pwm), сверять t_reset с datasheet используемой версии LED. Не считать DMA TC автоматически концом физического trailer — учитывать TIM preload.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### WS-3 — P2 — Буфер может превышать аппаратную длину DMA

**Место:** [src/ws2812b.hpp](../src/ws2812b.hpp), строка 88.

**Проблема:** BUF_SIZE=N_LEDS*24+RESET_SLOTS не ограничен; Len() возвращает size_t, TIM SendDMA/DMA counter имеют свои limits.

**Последствие / условие:** Большое число LED даст truncated DMA count, хотя объект и buffer скомпилируются.

**Возможное решение:** Если класс остаётся именно для одной DMA передачи, добавить compile-time ограничение BUF_SIZE<=65535 и защиту арифметики. Для больших лент chunking обсуждать отдельно, а не добавлять скрыто.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### WS-4 — P2 — Нет явного контракта изменения buffer во время передачи

**Место:** [src/ws2812b.hpp](../src/ws2812b.hpp), строка 107.

**Проблема:** SetPixel/SetAll/Clear/SetCCR свободно меняют _buf, который DMA читает асинхронно. На F7 _buf также не имеет отдельного alignment/ownership контракта.

**Последствие / условие:** Изображение меняется в середине отправки; отсутствие clean TIM-5 оставляет старые данные в SRAM.

**Возможное решение:** Указать: buffer не изменять до DMA completion, TX clean выполняет TIM/DMA. Если нужен одновременный расчёт следующего кадра, сначала согласовать второй фиксированный buffer.

**Статус:** решение не принято, код в рамках этого обзора не изменён.
