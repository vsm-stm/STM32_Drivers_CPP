## Проблемы и принятые решения

### MODBUS-1 — P1 — UART IDLE ошибочно используется как конец RTU кадра

**Место:** [Interfaces/Modbus-slave.cpp](../Interfaces/Modbus-slave.cpp), строка 31.

**Проблема:** Rx_Process сразу разбирает completed USART packet, который OnIdle завершает после UART IDLE. Нет t1.5/t3.5 state/timer и проверки inter-frame silence.

**Последствие / условие:** Разрешённая пауза внутри RTU кадра может разрезать его на отдельные пакеты; ответ может начаться до обязательного межкадрового интервала.

**Возможное решение:** UART IDLE использовать как сигнал паузы, окончательный frame delimiter определять t3.5; t1.5 инвалидирует неполный frame. Сначала согласовать подходящий TIM/сервис main, без Delay в IRQ. Правило описано в [Modbus serial specification §2.5.1](https://www.modbus.org/file/secure/modbusoverserial.pdf).

**Статус:** По решению пользователя сохранён IDLE; ограничения t1.5/t3.5 описаны в Modbus.md, аппаратный TIM не добавлен.

### MODBUS-2 — P1 — CRC читается и пишется через невыровненный uint16_t*

**Место:** [Interfaces/Modbus-slave.cpp](../Interfaces/Modbus-slave.cpp), строка 41.

**Проблема:** Каст &buffer[len] в uint16_t* используется для чтения/записи CRC; при нечётной длине адрес невыровнен, также нарушается тип доступа к byte-array.

**Последствие / условие:** На Cortex-M0+ это может вызвать fault; на других ядрах поведение зависит от unaligned access settings/compiler.

**Возможное решение:** Собирать/записывать CRC двумя uint8_t в wire order low byte, high byte. Это одновременно убирает aliasing и зависимость от выравнивания.

**Статус:** Исправлено: чтение/запись CRC двумя байтами в wire order, без uint16_t-кастов.

### MODBUS-3 — P1 — SendData() не откатывает DE/буфер при ошибке DMA

**Место:** [Interfaces/Modbus-slave.cpp](../Interfaces/Modbus-slave.cpp), строка 67.

**Проблема:** До проверки Send_DMA результата ставятся OnSend и DE=1. Если Send_DMA вернул Error/Busy, эти состояния не возвращаются. Затем идёт бесконечный while(GetTxStatus()==Busy).

**Последствие / условие:** Шина остаётся в transmit mode, буфер недоступен; при потерянном DMA IRQ/TE или вызове из ISR ожидание не закончится. UART-3 дополнительно делает polling state ненадёжным.

**Возможное решение:** При ошибке старта сразу вернуть DE=0 и согласованный buffer status. Предпочтительно возврат после успешного запуска, освобождение буфера/DE по wire TC; если метод остаётся blocking, задать реальный timeout и main-only контракт.

**Статус:** Исправлено: неблокирующий SendData, откат DE при ошибке старта, освобождение по UART TC или ошибке DMA TX.

### MODBUS-4 — P1 — Ошибки DMA/cache/IRQ USART наследуются транспортом

**Место:** [Interfaces/Modbus-slave.hpp](../Interfaces/Modbus-slave.hpp), строка 15.

**Проблема:** RX/TX buffers не имеют отдельного cache-line ownership/alignment; USART RX не обслуживает F7 кеш. SetUp()/AttachDMA не подтверждают успешность всех ресурсов; UART handler может читать чужие flags.

**Последствие / условие:** Ошибки UART-1..UART-7 приводят к повреждённым RTU frames и неверному DE timing независимо от правильности CRC.

**Возможное решение:** Разбирать Modbus после UART/DMA/IRQ. Для F7 выделить buffer lines отдельно от управляющих полей; обслуживание — внутри transfer drivers, согласно принятой модели кеша.

**Статус:** Используется текущий USART с собственными DMA/IRQ/cache. Внутренние F7-буферы выровнены и изолированы по кеш-линиям.

### MODBUS-5 — P2 — Полный RX buffer и задержка Rx_Process не имеют политики потерь

**Место:** [Interfaces/Modbus-slave.cpp](../Interfaces/Modbus-slave.cpp), строка 25.

**Проблема:** Приём запускается только очередным Rx_Process(); после TC/IDLE он остановлен до следующего вызова. Нет обработки переполнения/слияния frames и счётчика потерь.

**Последствие / условие:** Следующий запрос, пришедший пока main разбирает пакет или между вызовами Rx_Process, теряется. Заполненный 256-byte buffer может быть принят за полный RTU frame без корректной t3.5 границы.

**Возможное решение:** Явно определить допустимую скорость обработки и обработку overrun. Согласовать rearm/буфер владения после parser, при необходимости две фиксированные области вместо неограниченной очереди.

**Статус:** Сохранён один буфер без очереди; окно потери до rearm документировано. Пакет потребляется один раз, после ошибки RX можно возобновить приём из main.

### MODBUS-6 — P2 — Линия всегда настраивается как 8N1 без parity API

**Место:** [Interfaces/Modbus-slave.cpp](../Interfaces/Modbus-slave.cpp), строка 4.

**Проблема:** Используется USART::SetUp(), который обнуляет CR2/CR1 format; SetParity() в USART — no-op. Формат RS-485 RTU не выбирается транспортом.

**Последствие / условие:** Устройства с согласованным 8E1/8O1 или 8N2 не смогут общаться; время символа для t1.5/t3.5 также зависит от формата.

**Возможное решение:** Добавить после обсуждения явную настройку поддерживаемого UART frame format либо документировать единственный реализованный 8N1 режим. Не обещать полную Modbus serial совместимость до реализации.

**Статус:** Добавлены 8E1/8O1/8N2 через FrameFormat при SetUp; 8N1 оставлен по умолчанию для совместимости. Минимально расширен USART::SetUp.

### MODBUS-7 — P3 — Статусы и роль класса неочевидны

**Место:** [Interfaces/Modbus-slave.cpp](../Interfaces/Modbus-slave.cpp), строка 56.

**Проблема:** Неверная len возвращает Busy; нет отмены OnFill, если полученный TX buffer не отправлен. Slave address/function validation полностью оставлены Rx_Parse, но имя класса выглядит как готовый slave.

**Последствие / условие:** Пользователь может ждать освобождения вместо исправления аргумента либо забыть filtering address/broadcast в parser.

**Возможное решение:** Для неверного аргумента вернуть Error; определить release/cancel для OnFill. Описать обязанности Rx_Parse и оставить простой транспорт без автоматического расширения Modbus layer.

**Статус:** Неверный аргумент возвращает Error; согласованный CancelTxBuffer освобождает подготовленный ответ, Busy во время передачи. Роль parser описана.
