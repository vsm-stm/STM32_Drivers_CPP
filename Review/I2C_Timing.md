# I2C Timing: состояние расчёта

Обновлено 20.10.2026. Файл: [i2c_timing_utility.hpp](../src/tools/i2c_timing_utility.hpp).
Сборки и тесты этой правки не запускались.

## Принятое решение

Расчёт перенесён в consteval. I2C::SetUp<pclk_hz, SPEED>() рассчитывает слова
регистров и проверяет результат через static_assert, как RCC. На F4 используется
расчёт CCR/TRISE/FREQ в i2c.hpp, на F7/G0 — адаптированный алгоритм ST для TIMINGR.
Приложение обеспечивает соответствие pclk_hz реальной APB1; динамическая
перенастройка тактирования и runtime-поиск не добавлены.

## Статус замечаний

| Пункт | Исходная проблема | Текущее решение |
|---|---|---|
| I2CT-1 | Общий счётчик смешивал результаты и приводил к выходу за массив | Сначала исправлен 18.10; теперь массив/счётчик и C utility полностью удалены |
| I2CT-2 | Общий workspace для разных I2C | Общей изменяемой памяти больше нет; расчёт выполняет компилятор |
| I2CT-3 | Диапазон частот выбирал номинал, фронты и фильтры фиксированы | API принимает только STANDARD/FAST/FAST_PLUS; прежние фронты и фильтры сохранены и описаны в I2C.md |
| I2CT-4 | C header требовал внешнего extern C | C API удалён; C++20 header с consteval, extern C не требуется |
| I2CT-5 | Массив 128×20 = 2560 байт постоянной RAM | Массив удалён целиком; runtime stack на 16 кандидатов тоже не требуется |

## Алгоритм

- Целочисленный период kernel clock в наносекундах округляется как раньше.
- Для каждого из 16 PRESC выбирается первая допустимая пара SCLDEL/SDADEL.
  Вместо вложенных циклов по задержкам используются эквивалентные округления вверх.
- Далее выбирается SCLL/SCLH с минимальной ошибкой периода. При равной ошибке
  сохраняется первый вариант в прежнем порядке PRESC, SCLL, SCLH.
- Если минимальный период уже больше максимально допустимого, цикл SCLL
  завершается. Во внутреннем цикле SCLH действует такой же досрочный выход.
- Параметры платы не расширялись: analog filter 50..260 нс, DNF=0;
  rise/fall STANDARD 1000/300, FAST 300/300, FAST_PLUS 100/100 нс.
- Промежуточная арифметика расширена до 64 бит внутри consteval, чтобы не
  переполнялись выражения. В прошивку эти вычисления не попадают.

Прежние i2c_timing_utility.c/.h удалены; CMake больше не собирает C utility и
не добавляет её отдельный include path. Пользовательские настройки в CMake
не вводились. Примеры миграции находятся в [I2C.md](../I2C.md).

Исходники и преобразования просмотрены вручную. Эквивалентность результатов
набором тестов и фактическая точность на шине в этом проходе не проверялись.
