# DSP / подключение CMSIS-DSP: проблемы и предложения

Дата: 12.10.2026. Проверена рабочая копия; сборки и аппаратные тесты в этом проходе не запускались.

**Файлы:** [CMakeLists.txt](../CMakeLists.txt), [THIRD_PARTY.md](../THIRD_PARTY.md).

**Зависимости:** Arm CMSIS-DSP v1.16.2 через FetchContent, CMSIS core, compiler target flags из stm32_platform.

В репозитории нет собственной DSP реализации: проверены подключение, состав sources и публичный include. Алгоритмы внешнего пакета целиком и все их аппаратные оптимизации в этот проход не проверялись. Это не отчёт о найденных ошибках математики Arm.

## Список для обсуждения

### DSP-1 — P2 — Публичный arm_math.h шире реально собранной части библиотеки

**Место:** [CMakeLists.txt](../CMakeLists.txt), строка 208.

**Проблема:** Собираются FastMathFunctions, ControllerFunctions и два CommonTables files; Filtering/Transform/Statistics и другие каталоги не включены. Публичный [arm_math.h v1.16.2](https://raw.githubusercontent.com/ARM-software/CMSIS-DSP/v1.16.2/Include/arm_math.h) подключает headers всех групп.

**Последствие / условие:** Вызов объявленной arm_fir/arm_cfft/arm_mean и других не включённых функций даёт undefined reference. README описывает subset, поэтому сам выбранный состав не является ошибкой.

**Возможное решение:** Сохранить выбранный subset и перечислить реально поддерживаемые API/группы. Расширять список sources только после запроса пользователя; не включать CMSIS-DSP целиком ради header.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### DSP-2 — P3 — Покрытие внешней зависимости ограничено выбранными файлами

**Место:** [CMakeLists.txt](../CMakeLists.txt), строка 201.

**Проблема:** Tag фиксирован, что хорошо для воспроизводимости. Собственный CMake CMSIS-DSP намеренно не запускается, compiler features берутся из base. Это не проверяет оптимизированные paths и математические edge cases внешнего пакета.

**Последствие / условие:** Успешный include не гарантирует наличие symbol/корректное target-specific исполнение каждой функции.

**Возможное решение:** При отдельной проверке собрать с base F4/F7/G0 и вызвать реально нужные fast math/controller functions; проверить domain/error output. Не обновлять tag без отдельного решения.

**Статус:** решение не принято, код в рамках этого обзора не изменён.
