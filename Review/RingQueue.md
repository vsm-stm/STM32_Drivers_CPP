# RingQueue: проблемы и предложения

Дата: 12.10.2026. Проверена рабочая копия; сборки и аппаратные тесты в этом проходе не запускались.

**Файлы:** [Containers/RingQueue.hpp](../Containers/RingQueue.hpp).

**Зависимости:** Header-only, cstddef; не зависит от периферии.

Подтверждённых ошибок push/pop/full/empty/wrap в заявленной модели одного контекста не найдено. Ёмкость N-1 прямо описана; N>1 проверяется. Отсутствие встроенной ISR/main синхронизации не считается дефектом этой модели.

## Список для обсуждения

### RQ-1 — P3 — Комментарий рекомендует отсутствующий IrqLock

**Место:** [Containers/RingQueue.hpp](../Containers/RingQueue.hpp), строка 6.

**Проблема:** Синхронизация объявлена внешней и примером назван IrqLock, которого сейчас нет в ядре библиотеки.

**Последствие / условие:** Пользователь получает рекомендацию API, не существующего в репозитории. Это замечание документации, не предложение встроить lock в очередь.

**Возможное решение:** Заменить пример на выбранный внешний контракт без конкретного отсутствующего типа. Если потребуется ISR/main FIFO, отдельно определить SPSC/доступ и видимость head/tail; текущую single-context очередь не усложнять.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### RQ-2 — P3 — Требования к типу T и lifetime элементов не описаны

**Место:** [Containers/RingQueue.hpp](../Containers/RingQueue.hpp), строка 17.

**Проблема:** Весь массив T создаётся сразу; нужны default construction и copy assignment. pop() не разрушает объект в освобождённом slot.

**Последствие / условие:** Для resource-owning T удержание ресурса до перезаписи/уничтожения может отличаться от ожиданий std::queue.

**Возможное решение:** Документировать value-type/assignment контракт и lifetime. Если используются только простые встроенные структуры, реализации storage/placement-new не нужны.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

## Проверка после возможных правок

N=2, N=3 и степень двойки; заполнение N-1 slots, отказ push при full, FIFO order после нескольких оборотов, pop при empty. Отдельная concurrency проверка нужна только если такой режим будет согласован.
