# UART / USART: проблемы и предложения

Дата: 12.10.2026. Проверена рабочая копия; сборки и аппаратные тесты в этом проходе не запускались.

**Файлы:** [src/uart.cpp](../src/uart.cpp), [src/uart.hpp](../src/uart.hpp), [src/uart_defs.hpp](../src/uart_defs.hpp).

**Зависимости:** System/RCC/GPIO, IRQ Registry, DMA; Modbus наследует USART.

## Список для обсуждения

### UART-1 — P1 — HandleIRQ() обрабатывает флаги даже при выключенном источнике

**Место:** [src/uart.cpp](../src/uart.cpp), строка 269.

**Проблема:** RXNE/TXE/IDLE/TC проверяются без CR1/CR3 interrupt-enable masks. Этот же handler вызывается DMA IRQ. tx_data/rx_data не инициализированы до своего IRQ-transfer.

**Последствие / условие:** Обычный RX IRQ при TXE=1 вызывает OnTxEmpty() с неинициализированным tx_data. DMA IRQ может вычитать RXDR вне активного IRQ-приёма и записать байт по неверному указателю.

**Возможное решение:** Обрабатывать UART-событие только при включённом соответствующем источнике и действующей операции. Инициализировать descriptors нулями; чтение RDR при DMA RX не выполнять в CPU handler.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-2 — P1 — Неполное обслуживание RX D-cache на F7

**Место:** [src/uart.cpp](../src/uart.cpp), строка 172.

**Проблема:** Send_DMA() делает clean TX, но Receive_DMA(), OnIdle() и OnDmaRxComplete() не готовят и не инвалидируют RX-буфер.

**Последствие / условие:** CPU получает старые данные, либо грязная строка CPU позже перезаписывает принятые DMA данные.

**Возможное решение:** По принятой модели обслужить принадлежащие буферу линии до RX и после фактической остановки DMA; дополнить записью исходного адреса и длины. Не ограничивать логическую длину пакета кратностью 32, если выделенная область владеет достаточными целыми линиями.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-3 — P1 — Флаги и статусы main/IRQ не имеют нужной видимости

**Место:** [src/uart.hpp](../src/uart.hpp), строка 356.

**Проблема:** tx_status/rx_status/data_received/counters — обычные поля, изменяемые ISR и читаемые из main; inline polling не читает volatile/atomic. GetDataReceivedCount() читает и обнуляет несколько полей без согласованного снимка.

**Последствие / условие:** Компилятор может не перечитывать флаг в пустом while; событие, пришедшее между чтением и обнулением, теряется. Это относится и к Modbus SendData().

**Возможное решение:** Для одиночных ISR/main flags определить простую volatile-модель; для read-and-clear counters согласовать короткий атомарный снимок либо чтение только после завершения. Не вводить поддержку потоков без необходимости.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-4 — P1 — IDLE считает данные до фактической остановки DMA

**Место:** [src/uart.cpp](../src/uart.cpp), строка 336.

**Проблема:** NDTR читается раньше Stream_EN(DISABLE), подтверждения EN=0 нет. DMA TC и IDLE могут быть обработаны одним вызовом в разном порядке.

**Последствие / условие:** Последний байт может ещё изменить счётчик/буфер, reported count не соответствует данным. На F4 CPU-чтение DR для очистки IDLE особенно важно увязать с остановкой RX DMA.

**Возможное решение:** Сначала прекратить запросы и подтвердить остановку канала, затем взять остаток и обслужить кеш. Уточнить приоритет IDLE/TC и единственное уведомление на передачу.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-5 — P1 — Длины и состояние перед стартом проверяются неодинаково

**Место:** [src/uart.cpp](../src/uart.cpp), строка 60.

**Проблема:** Blocking Send/Receive отвергают только Busy и принимают NotInit/nullptr. IRQ len=0 становится Busy и может не завершиться. IRQ/DMA descriptors имеют uint16_t size при uint32_t len; DMA не проверяет 65535.

**Последствие / условие:** Обращение к ненастроенной периферии/нулевому буферу, обрезка длины, зависание RX_IRQ(0). Повторный запуск при остатках старого state не исключён.

**Возможное решение:** Единообразно проверять InitOK, указатели и длину для каждого режима; нулевую длину определить явно. Для DMA лимит счётчика 65535. Сбрасывать состояние completed packet при новом Receive, не накапливать data_received_count от предыдущей передачи.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-6 — P1 — Ошибки UART/DMA не завершают операцию

**Место:** [src/uart.cpp](../src/uart.cpp), строка 256.

**Проблема:** Handler проверяет только DMA TC, не TE; UART ORE/FE/PE не очищает и не отдаёт пользователю. При ORE приём может не завершиться, Busy остаётся.

**Последствие / условие:** Повреждённый/оборванный приём принимается как обычный либо остаётся Busy; IRQ/ DMA операция не имеет результата ошибки.

**Возможное решение:** Добавить минимальный error path: сбросить соответствующие флаги, остановить операцию, сообщить статус/callback. Error IRQ включать только если он действительно обрабатывается.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-7 — P2 — AttachDMA() игнорирует ошибки настройки и повторное владение

**Место:** [src/uart.cpp](../src/uart.cpp), строка 193.

**Проблема:** Указатели сохраняются до настройки; возвраты tx/rx->SetUp() не проверяются. Повторный AttachDMA() регистрирует handler заново. Отдельный preset может относиться к другой периферии.

**Последствие / условие:** При ошибке запускается чужой/неподготовленный канал; повторная регистрация расходует IRQ slots.

**Возможное решение:** Вернуть SysInitStatus, публиковать DMA-подключение только после успешной настройки обеих сторон и проверять реальный маршрут. Согласовать повторное подключение с DMA/IRQ API.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-8 — P2 — SetBaud() может делить на ноль и теряет новое значение

**Место:** [src/uart.hpp](../src/uart.hpp), строка 303.

**Проблема:** baud не проверяется, BaudRate не обновляется, BRR записывается на включённом USART; расчёт всегда floor(PCLK/baud). Kernel clock selector F7/G0 не установлен явно.

**Последствие / условие:** SetBaud(0) вызывает деление на ноль; следующий SetUp() возвращает старый baud. При kernel clock не PCLK расчёт неверен.

**Возможное решение:** Проверять baud/допустимый BRR, хранить новое значение, настраивать BRR при допустимом состоянии UE и применять округление. Явно выбрать PCLK kernel clock либо рассчитывать фактический источник.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-9 — P2 — Таблица устройств и FIFO не соответствуют заявленным возможностям

**Место:** [src/uart_defs.hpp](../src/uart_defs.hpp), строка 307.

**Проблема:** F4/F7 guard исключает сразу все строки кроме USART1/2 на F411, включая имеющийся USART6. UART7/8 имеют pin tables, но нет runtime rows; G0 USART3/4 тоже без rows. FIFO_TH::all=0b111, тогда как допустимый full threshold G0 кодируется 0b101.

**Последствие / условие:** Доступные через pin API устройства возвращают InitError либо не компилируются на MCU без безусловно перечисленных UART. Значение all пишет зарезервированный FIFO threshold.

**Возможное решение:** Описывать наличие каждой периферии через device capabilities, синхронизировать pin/runtime/DMA tables. Исправить encoding FIFO после сверки header/RM. Код full threshold 0b101 указан в [ST G0 UARTEx constants](https://raw.githubusercontent.com/STMicroelectronics/stm32g0xx-hal-driver/master/Inc/stm32g0xx_hal_uart_ex.h).

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-10 — P2 — DeInit() не останавливает DMA и не сбрасывает программное состояние

**Место:** [src/uart.hpp](../src/uart.hpp), строка 317.

**Проблема:** DeInit очищает CR1/2/3 и удаляет UART IRQ, но не останавливает подключённые DMA, не снимает их регистрации и не переводит статусы в NotInit.

**Последствие / условие:** DMA IRQ может прийти после деинициализации, а GetStatus() и повторный start показывают устаревшую готовность.

**Возможное решение:** Остановить свои операции/каналы, убрать свои registrations и очистить descriptors/status. Учитывать shared IRQ; не удалять чужие обработчики.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### UART-11 — P3 — Комментарии и примеры описывают другой API

**Место:** [src/uart.hpp](../src/uart.hpp), строка 137.

**Проблема:** Упоминаются SysInitStatus::OK/Error и EnableNVIC_IRQ(), которых нет; timeout описан как per byte, а tick_start один на всю операцию. Blocking Send заканчивается по TXE-очереди, не по wire TC.

**Последствие / условие:** Пользователь не понимает, когда передача физически закончилась и как включать IRQ.

**Возможное решение:** Указать реальные enum names и IRQ_en(); определить результат Send как «данные переданы в регистр» или добавить ожидание TC по отдельному согласованному контракту. TX buffers сделать const по API, если они не меняются.

**Статус:** решение не принято, код в рамках этого обзора не изменён.
