# StaticDList: проблемы и предложения

Дата: 12.10.2026. Проверена рабочая копия; сборки и аппаратные тесты в этом проходе не запускались.

**Файлы:** [Containers/StaticDList.hpp](../Containers/StaticDList.hpp).

**Зависимости:** Header-only, индексный пул.

Вставка, unlink, move_to_tail, erase_and_next, free list и size в обычном single-context режиме согласованы. Подтверждённых ошибок этих операций не найдено. ref(i) имеет явно указанное предусловие valid(i).

## Список для обсуждения

### DL-1 — P3 — next()/prev() проверяют диапазон, но не занятость slot

**Место:** [Containers/StaticDList.hpp](../Containers/StaticDList.hpp), строка 66.

**Проблема:** Для удалённого индекса next() возвращает ссылку free list, а не цепочки live nodes. valid() есть отдельно, но предусловия next/prev не описаны так же явно, как ref.

**Последствие / условие:** После erase использование старого индекса способно перевести обход в свободные элементы. При обходе через возвращаемое erase_and_next значение текущая логика корректна.

**Возможное решение:** Документировать обязательный valid(i) для next/prev либо возвращать npos для unused slot. Защита от повторного использования того же индекса не нужна без требования generation handles.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### DL-2 — P3 — Удаление не заканчивает lifetime значения T

**Место:** [Containers/StaticDList.hpp](../Containers/StaticDList.hpp), строка 37.

**Проблема:** free_node меняет только metadata; value живёт до overwrite/destructor контейнера, весь T pool создаётся заранее.

**Последствие / условие:** Для T с ресурсами erase не освобождает ресурс немедленно; для обычных данных ошибки нет.

**Возможное решение:** Документировать типы T и assignment/lifetime модель. Не внедрять manual storage только ради соответствия std::list, если контейнер нужен для простых структур.

**Статус:** решение не принято, код в рамках этого обзора не изменён.
