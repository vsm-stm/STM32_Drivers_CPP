# ADC: согласованные правки и оставшиеся зависимости

Обновлено: **18.10.2026**. Исходники ADC изменены по согласованным решениям.
DMA, TIM, I2C и проектные файлы в этом проходе не изменялись.
Скомпилированы изолированные IRQ до/после упрощения для G031/F429/F767.
Полная сборка ADC и аппаратная работа не подтверждены.
Подробный API и примеры: [ADC.md](../ADC.md).
Ассемблер и оценка выигрыша: [ADC_IRQ_Timing.md](ADC_IRQ_Timing.md).

## ADC-1 — Обновлённая интеграция и незакрытые зависимости

ADC использует существующие DMAReq, CanUseRequest, SetUp(cfg), GetErrorFlags,
GetTC_Flag, ClearFlags, Release. RequestSet, SetUp(cfg, request),
GetTE_Flag и отсутствующие cache helpers DMA удалены.

**Отдельный этап TIM:** TIM_TriggerGenerator пока отсутствует.
Сохраняется согласованное подключение по указателю; ADC обращается к
GetReq().extsel, Start(), Stop(). Сам ADC не реализует временный генератор.
Forward declaration позволяет объявить указатель, но не заменяет определение:
до реализации класса обращения в adc.cpp блокируют его компиляцию.
Задача записана в [Review/TIM.md](TIM.md).

**DMA API согласован и добавлен 18.10.2026:** GetHT_Flag() const,
ClearHT_Flag() и ClearTC_Flag(). Следующий отдельный шаг — их подключение в ADC.
Сейчас ADC обслуживает только TC через прежний интерфейс.
В circular TC пока используется ClearFlags(), которая очищает и HT/ошибки;
её нужно заменить на выборочную очистку при подключении HT/TC в ADC.
OnDmaHalf предусмотрен как согласованный callback, но пока не вызывается.
Не считать эту часть завершённой или проверенной сборкой.

## ADC-2 — Простая модель управления

SetUp -> AddChannel -> необязательные DMA/trigger -> нужный Start.
После завершения конечного захвата следующий Start запускает его повторно.
Во время активного захвата возвращается Busy, как в USART.

Удалены IrqLock, adc_thread_context, BeginConfig, RunActive, RequestStop,
FinishStop, Config и _cancelled. Остались только режим захвата, статус
и необходимые G0 аппаратные операции. IsBusy/GetStatus — чистые запросы.
Управляющие методы вызываются последовательно из main, callbacks уведомляют.
Скрытой конфигурационной фазы при чтении IsBusy нет.

## ADC-3/5 — Кеш и подтверждённая остановка

Перед DMA RX — System::CacheCleanInvalidate; после Stream_EN(DISABLE),
подтверждающего EN=0, — CacheInvalidate, затем публикация успешного результата.
При ошибке буфер непригоден: invalidate пропускается, частичное чтение запрещено.
Idle Stop/DeInit не инвалидирует уже возвращённый приложению буфер.

Требование кратности длины 32 байтам удалено. Вызывающий владеет затронутыми
линиями, включая padding. Некешируемые области определяет System;
на F4/G0 методы пустые. Дополнительные capacity-поля и буферы не добавлены.

## ADC-4 — Circular DMA: согласованное ограничение

В триггерном режиме вызывающий обеспечивает достаточный интервал обработки.
В continuous он учитывает длину очереди, sampling и частоту преобразований.
TC/HT не замораживают буфер: части нужно прочитать до перезаписи.
Для некешируемой памяти это ограничение также действует.

Автоматических остановок, копирования и защиты от отставания не добавлено.
Независимый HT ожидает подключения готового DMA API в ADC. Текущие TC callbacks оставляют
circular DMA работающим, как согласовано. Особенность описана в ADC.md/header.

## ADC-6/7 — Общий делитель и sampling

На F4/F7 ADCPRE задаёт PCLK2/4 для всех ADC даже в независимом режиме.
При обычной последовательной настройке этим драйвером используется один делитель.
Общий менеджер и новые проверки чужих ADC не добавлены.

Default sampling внутренних источников не изменён. Пользователь выбирает
длительность по datasheet и ADC clock. Startup Delay_ms(1) не увеличивает
время выборки каждого измерения. Автоподбора/новой валидации нет.

## ADC-8 — Ожидания System

Локальный wait_bits и проверки IPSR/PRIMASK удалены.
Аппаратные masked waits G0 используют System::WaitBits с прежним пределом 1 мс.
Enable сохраняет только аппаратно необходимое повторение ADEN до ADRDY,
ограниченное GetTick; дополнительных временных обёрток нет.
GetTick/Delay_ms требуют инициализированного System и работающего SysTick.
В обработчике ошибок IRQ команда ADSTP выдаётся без блокирующего ожидания SysTick;
DMA при этом останавливается с подтверждением EN=0.

## ADC-9 — Единообразный API

Start возвращает SysStatus. Все варианты DMA названы Start_DMA,
StartTrig_DMA, StartCont_DMA. AddChannel/ClearChannels возвращают ошибки/Busy
вместо DebugTrap. Аппаратные ошибки не выдаются через успешный DMA callback.

Set…Callback заменены protected virtual OnEOS, OnDmaHalf/OnDmaComplete/OnError(uint32_t).
На G0 также остаётся OnEOC; на F4/F7 вызывается только OnEOS.
OnOverrun удалён; обе причины передаются одним OnError с маской Overrun/Dma.
Notifications выполняются после обработки аппаратуры/статуса; успешные данные
передаются после обслуживания кеша. В ошибочном пути кеш не обслуживается.
В IRQ DMA-ошибки читаются один раз. Успешный конечный TC останавливает DMA
непосредственно, без повторной проверки ошибок в StopDMA.
OnDmaHalf пока ожидает подключения HT; полнота реализации не утверждается.

## ADC-10/11 — IRQ и освобождение

SetUp регистрирует ADC IRQ один раз, AttachDMA — DMA IRQ.
Результат Register проверяется; при отказе освобождаются только приобретённые
ресурсы и восстанавливается предыдущее состояние общей линии.
IRQ_en меняет источники, а не таблицу. Из callback реестр не изменяется.

Stop сохраняет привязки. Явный DeInit удаляет только собственные записи,
освобождает DMA, останавливает/отключает ADC и отключает его clock.
Чужие обработчики и shared NVIC сохраняются. Общие GPIO/DMA clocks и
аналоговый режим GPIO остаются, как и внешне настроенный объект генератора.
Основная модель — объекты до конца программы; автоматического деструктора нет.
Повторные SetUp/AttachDMA требуют DeInit.

## ADC-12 — Подготовка DMA

SetMemAddr/SetCount проверяются до Stream_EN(ENABLE).
Отказ не запускает захват и не публикует новый буфер.
Обработка использует GetErrorFlags, включая DME/FE на F4/F7.

## ADC-13/14 — Статические пины и неизменяемый ADC

ADC_PIN использует PIN с consteval-проверками порта/номера, диапазона канала
и наличия ADC. Метаданные неизменны; номера входов добавлены в имена:
PA0_IN0, PC4_IN14, PF6_IN4. AddChannel конфигурирует непосредственно PIN.
Сохранённый указательный конструктор общего GPIO не удалялся.

Ошибка GCC при вычислении таблиц до завершения внешнего ADC_N исправлена:
определение ADC_PIN перенесено перед ADC_N в adc.hpp; внутри сохранён
using ADC_PIN = ::ADC_PIN. Имена и записи таблиц не изменены, тело consteval
конструктора и проверки сохранены. Таблицы отдельно и настоящий adc.hpp
скомпилированы GCC 13.3 для G031/F429/F767 без ошибок и предупреждений.

ADCx закрыт и const. Descriptor ищется в локальном указателе;
старый _info не может быть принят за результат нового поиска.

## Проверки и границы результата

Выполнен просмотр изменённого исходника и diff. Для сравнения ассемблера
скомпилированы изолированные тела StopDMA/HandleIRQ и диспетчер IRQ
для Cortex-M0+/M4/M7. Аппаратные тесты и полная сборка не выполнялись.
Сборка ADC пока зависит от определения TIM_TriggerGenerator;
полный HT/TC — от подключения готового DMA API в ADC. Эти зависимости не закрывались
заглушками и не объявлены реализованными. Ошибка consteval ADC_PIN исправлена
отдельным следующим шагом; компиляция заголовка с таблицами подтверждена
на G031/F429/F767. Это не подтверждение сборки adc.cpp и прошивки.
Исторические логи: [Build.md](Build.md).
