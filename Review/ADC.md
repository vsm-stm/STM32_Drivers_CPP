# ADC: миграция API и статус замечаний

## Таймаут G0 — 20.10.2026

ADC_TIMEOUT_MS изменён с 1 на 2. При равномерном системном тике 1 мс это даёт
окно примерно 1–2 мс вместо почти 0–1 мс. Механизм ожидания не менялся.
Сборки/аппаратные измерения этого изменения не запускались.

## Перенос DMAReq и выбор атомарности — 19.10.2026

- ADC_USE_ATOMIC в adc.hpp: 0 по умолчанию, 1 выбирает ATOMIC_* ST для управляющих
  битов и полей. Групповые операции и владение буфером сериализует вызывающий код.
- ADC содержит DMA_Sx, конструктор получает именованный Req F4/F7 либо канал G0.
  Принадлежность ADC и направление проверяются в конструкторе F4/F7. На G0 источник
  ADC1_RX выбирается автоматически. Дублирующие маршруты в PeriphInfo удалены.
- G0 проверки ADSTART/ADSTP и ADEN/ADDIS используют один снимок CR для каждой
  проверки; после аппаратного ожидания берётся новый снимок.
- DMA IRQ читает HT/TC/ошибки одним GetIRQFlags и разбирает публичные маски DMA,
  без собственного дублирования TC и повторного чтения HT. Main-only StopDMA
  также использует единый снимок.
- Единый Start, режимы/триггер, callbacks и правила кеша сохранены.
- Комментарии/примеры обновлены. Сборки, тесты и ассемблер не проверялись.

Обновлено: **18.10.2026**. Реализованы согласованные фиксированные привязки,
единый Start, отдельные ADC/DMA IRQ и HT/TC. Изменения этого этапа ограничены
ADC и документацией его связей с TIM/DMA. Исходники других драйверов,
база, CMake и TEST в этом этапе не менялись.

Выполнен просмотр исходников и diff. **Сборки, тесты и аппаратная проверка
нового API не запускались.** Предыдущая изолированная компиляция заголовка и
[оценка ассемблера](ADC_IRQ_Timing.md) относятся к старой версии.

Подробные контракты и примеры: [ADC.md](../ADC.md).

## Реализовано

- Конструктор: ADC_N(ADCx, Conversion::Single/Continuous, DMAReq = {},
  TIM* = nullptr, Trigger = None). Привязки const; копирование/перемещение запрещены.
- Один Start(buf = nullptr, len = 0). Наличие DMA однозначно определяет его
  использование. Single/software — одна последовательность; Continuous и
  внешний триггер с DMA — circular. Continuous с триггером даёт InitError.
- AttachDMA/AttachTrig/AttachExtTrig, отдельные Start_DMA/StartCont/StartCont_DMA/
  StartTrig_DMA удалены. Режим при запуске не меняется.
- SetUp настраивает конструкторный DMA через существующие DMAReq/CanUseRequest;
  проверяет приобретение и отдельно регистрирует ADC и DMA-адаптер. Повторный
  SetUp запрещён до DeInit. Частичная настройка освобождает свои приобретения.
- ADC IRQ читает только ADC flags, DMA IRQ — только flags собственного DMA.
  Registry API не менялся. В IRQ нет Stream_EN(DISABLE), WaitBits и циклов ожидания.
- DMA_HT включается явно до запуска через IRQ_en. GetHT_Flag/ClearHT_Flag/
  ClearTC_Flag подключены; HT и TC очищаются раздельно.
- При HT первая половина проходит invalidate до OnDmaHalf. Circular TC с HT
  обслуживает вторую половину; без HT — весь буфер. Конечный TC возвращает
  весь завершённый буфер. DMA_HT требует чётную длину, иначе Start → Error.
- На F7 используются System cache helpers, пропускающие проектные некешируемые
  диапазоны. Для кешируемого HT-буфера линии половин разделяет вызывающий код.
- При ошибке F4/F7 запрашивается остановка без ожидания; Busy сохраняется до DMA
  IRQ с TC либо аппаратным TE при EN=0. Тогда Error и один OnError.
  На G0 пакет отбрасывается без CNDTR; уведомление после команды остановки.
  Ошибочные данные не инвалидируются и не используются.
- IRQ_en и восстановление источников при Start сохраняют NVIC через
  Enable_IRQ(..., false). Регистрации существуют до DeInit.
- Общий TIM* заменил отсутствующий TIM_TriggerGenerator. ADC содержит Trigger
  с семейными значениями EXTSEL; TIM настраивает приложение. Start вооружает
  ADC/DMA перед TIM Start. Stop/ошибка останавливают переданный TIM.
- Stop/DeInit из main могут ждать аппаратное завершение. Stop сохраняет
  каналы/привязки; DeInit адресно снимает свои регистрации и освобождает только
  приобретённый DMA. Параметры конструктора сохраняются для нового SetUp.
- Комментарии, примеры, ADC.md, README и описания связей TIM/DMA обновлены.

## Статус исходных пунктов

| Пункт | Текущий статус |
|---|---|
| ADC-1 | Привязки в конструкторе; существующий DMA API и общий TIM; отсутствующего TriggerGenerator больше нет |
| ADC-2 | Единый Start, нет runtime-переключения режима и Attach-методов |
| ADC-3 | Обслуживание кеша через System, включая половины |
| ADC-4 | HT/TC подключены; интервал обработки и защита от перезаписи остаются приложению |
| ADC-5 | IRQ не ждёт остановку; main Stop/DeInit подтверждают остановку |
| ADC-6 | Общий ADCPRE описан; common manager не вводился |
| ADC-7 | Sampling внутренних источников остаётся ответственностью приложения |
| ADC-8 | Нет локального wait_bits, IPSR/PRIMASK, IrqLock или потокового контекста |
| ADC-9 | SysStatus и protected virtual callbacks; F4/F7 только OnEOS, G0 также OnEOC |
| ADC-10 | Отдельные регистрации ADC/DMA с проверкой результата и откатом |
| ADC-11 | Явный DeInit сохраняет чужие shared handlers и фиксированные привязки |
| ADC-12 | Буфер/длина/выравнивание и SetMemAddr/SetCount проверяются перед запуском |
| ADC-13 | Неизменяемые consteval ADC_PIN и именованные входы сохранены |
| ADC-14 | ADCx/режим/DMA/TIM/источник закрыты и закреплены конструктором |

## Контракты и ограничения

- Управление из main и ADC/DMA IRQ сериализует вызывающий код. Обработчики одного
  объекта не прерывают друг друга. Встроенных блокировок или Process нет.
- Нельзя вызывать настройку/Start/Stop/DeInit либо менять Registry из callbacks.
  Для HT политика задаётся до Start; смена DMA_HT при Busy игнорируется.
- DMA_TC нельзя отключить для конечного захвата: он нужен для завершения и кеша.
  Для circular отключение TC управляет уведомлениями, а не преобразованиями.
- При HT len чётна; для F7 кешируемые половины занимают разные полные
  32-байтные линии. Некешируемые области не требуют границы по кеш-линиям.
- HT/TC не замораживают circular DMA. Пропущенные обороты/перезапись не
  обнаруживаются автоматически; приложение успевает обработать свои данные.
- Single/software DMA требует len == GetChannelCount. Для repeating DMA длина
  кратна GetChannelCount. Без DMA DR хранит лишь последний результат.
- TIM обязан соответствовать Trigger, его TRGO/CCx и частоту настраивает
  приложение до ADC SetUp. Служебный UG выполняется до вооружения ADC.
- Поддержан нарастающий фронт и источники текущего TIM API. TRGO2 не добавлен.
  В частности, ADC G0 использует TIM1_CC4, а не неподдержанный TIM1 TRGO2.
- TIM не переносится/не настраивается из ADC и не освобождается как собственный
  объект. Он останавливается при Stop/ошибке, что учитывают другие его потребители.
- Sampling, привязка к корпусу, DMA-доступность RAM и время жизни буфера проверяются
  приложением. ADCPRE F4/F7 общий даже для независимых ADC.
- На G0 после ошибки данные непригодны, callback не обещает завершённый пакет.
  Новый захват проходит main-handshakes; чтение частичного буфера запрещено.

## Проверка результата

Просмотрены ветви F4/F7/G0, отдельные входы IRQ, очистка HT/TC, переходы
Single/Continuous/trigger, повторный Start, освобождение/откат и документация.
Это просмотр кода, **не подтверждение собираемости или работы на плате**.
Повторная оценка размера/тактов нового IRQ не выполнялась.
