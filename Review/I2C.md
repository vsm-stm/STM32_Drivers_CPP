# I2C: состояние после миграции API

## Изменения — 19.10.2026

- DMAReq в конструкторе, TX/RX DMA_Sx внутри I2C; AttachDMA удалён.
  F4/F7 проверяют owner/direction при создании, G0 получает только физический
  канал и сам выбирает источник DMAMUX по I2Cx/направлению.
- SetUp один раз до DeInit. IRQ I2C, DMA TX и DMA RX регистрируются отдельно,
  ошибки регистрации возвращают InitError с откатом добавленных записей.
  Общий EV/ER G0 регистрируется один раз.
- IrqLock, Reserve/Release, ожидающие циклы IRQ и старые cache helpers удалены.
  Одна FSM обслуживает Poll/IRQ/DMA, аппаратные ветки остаются в i2c.cpp
  под #if. .inc-файлы не добавлялись.
- F4 STOP не ожидается; следующий запуск проверяет STOP/BUSY.
  F7/G0 успешный DMA ждёт оба события: STOPF и конечный TC. TC раньше STOP
  сохраняется до автобусного завершения. Успех требует нулевого остатка.
- Ошибка F4/F7 запрашивает stop и возвращает буфер после TC/TE при EN=0.
  Ошибочный G0 пакет отбрасывается без чтения CNDTR как фактической длины.
- OnComplete/OnError(ERR) через наследование; SetDoneCallback/SetErrorCallback
  удалены. Блокирующие операции и Abort callbacks не вызывают.
- DMA готовится с проверкой SetMemAddr/SetCount. TX clean; RX clean+invalidate
  до запуска и invalidate только успешных данных после завершения.
- I2C_USE_ATOMIC=0 по умолчанию, 1 — ATOMIC_* ST для управляющих RMW.
  Статусы W1C/rc_w0 и регистры данных остаются прямыми операциями.
- Recover удалён по решению пользователя: восстановление шины делает приложение.
- REG/SPEED проверяются до использования. Нулевой Send/Receive — Error;
  IsReady и register-only WriteReg без DMA сохранены.
- Добавлены owner/direction I2C Req; исправлен I2C3 RX Stream2 CH3,
  добавлены отсутствовавшие именованные I2C1 TX Stream7, I2C4 F7 CH2
  и G0 I2C3 62/63. Ссылки на документацию ST — в [I2C.md](../I2C.md).

Приложение сериализует main/IRQ и задаёт невытесняющиеся приоритеты обработчиков
одного объекта. Внутреннего watchdog или Process из main не добавлено.
При потере события операция может остаться Busy до внешнего Abort.
Длинные сторонние ISR и последовательности последних 1–3 байт F4 требуют
проверки на конкретном МК; внутренние критические секции не вводились.

Сборки, тесты и аппаратная проверка этой миграции не запускались.

## I2C-1 — P1 — I2C использует отсутствующий API DMA и IrqLock

**Место:** [i2c.hpp:193](../src/i2c.hpp#L193),
[i2c.cpp:199](../src/i2c.cpp#L199), [i2c_defs.hpp:329](../src/i2c_defs.hpp#L329).

Нет DMA_Sx::RequestSet, SetUp(cfg, request), GetTE_Flag, ClearTC_Flag
и CacheRxOk/CacheClean/CacheInvalidate. IrqLock также отсутствует.
Таблицы ещё ссылаются на отсутствующие I2c1::TX_alt, I2c3::RX_alt,
I2c4, а в соответствующей ветке G0 — I2c3.
Часть ссылок уже переименована в явные имена потоков, но миграция не завершена.

**Предложение:** описывать маршруты через существующие DMAReq,
проверять выбранный DMA посредством CanUseRequest(), затем вызывать SetUp(cfg).
Ошибки читать через GetErrorFlags(), флаги очищать доступными методами,
кеш обслуживать в System. Реальные альтернативные маршруты сверить по моделям.
Не восстанавливать RequestSet или общий lock ради совместимости старого кода.
Модель доступа main/IRQ согласовать при исправлении I2C.

**Статус:** открыто; Release и адресный IRQ API больше не относятся к отсутствующим
зависимостям. Это несовместимость исходников, а не проблема include paths CMake.

## I2C-2 — P1 — Повторный расчёт TIMINGR смешивает варианты и выходит за массив

**Место:** [i2c_timing_utility.c:140](../src/tools/i2c_timing_utility.c#L140).

Статический I2c_valid_timing_nbr не сбрасывается в I2C_GetTiming().
Новый расчёт добавляет варианты к предыдущим; запись в массив выполняется
до проверки его вместимости. После достижения 128 следующий расчёт пишет
элемент с индексом 128 за границей массива. Это касается и последовательной
настройки разных I2C, а не только повторного SetUp одного объекта.

**Предложение:** обнулять счётчик перед расчётом и проверять границу до записи.
Остальные вопросы utility вынесены в [I2C_Timing.md](I2C_Timing.md).

**Статус:** исправлено 18.10.2026: счётчик сбрасывается перед расчётом,
вместимость проверяется до записи. Размер массива и алгоритм выбора не менялись.
Сборки и тесты не запускались.

## I2C-3 — Прежняя причина снята: остановка DMA подтверждается

**Место:** [i2c.cpp:648](../src/i2c.cpp#L648), [dma.hpp](../src/dma.hpp).

Finish отключает периферийные DMA requests, затем вызывает Stream_EN(DISABLE).
Текущий DMA ждёт сброса EN и выполняет барьер, поэтому прежнее утверждение
«после вызова остановки DMA ещё пишет в буфер» по этой причине больше не действует.

**Осталось:** заменить отсутствующий cache helper и соблюдать порядок передачи
буфера CPU — I2C-4. Проверка полноты при завершении по STOP — отдельный I2C-14.

**Статус:** исходный дефект закрыт изменением DMA; новое ожидание EN в I2C не нужно.

## I2C-4 — P2 — Устаревший кеш-контракт и неправильная подготовка RX

**Место:** [i2c.hpp:149](../src/i2c.hpp#L149),
[i2c.cpp:316](../src/i2c.cpp#L316), [i2c.cpp:648](../src/i2c.cpp#L648).

Header требует len, кратную 32, а Begin вызывает отсутствующий CacheRxOk.
Поэтому отказ короткого RX сейчас нельзя описывать как подтверждённый runtime:
текущий модуль сначала требует исправления зависимостей.
Перед RX вызывается CacheInvalidate; по принятому контракту System подготовка
должна выполнять CacheCleanInvalidate.

**Предложение:** TX — System::CacheClean перед запуском;
RX — CacheCleanInvalidate перед запуском и CacheInvalidate после остановки,
до доступа CPU. Для F7 вызывающий код владеет всеми затронутыми 32-байтовыми
линиями, включая padding. Длина передачи 1/2/6/14 байт допустима при выполнении
этого условия; отдельный аргумент ёмкости сам по себе не обязателен.
System пропускает обслуживание диапазона, полностью лежащего в настроенной
некешируемой DMA-области; на F4/G0 методы пустые.

**Статус:** миграция на уже принятое решение, без нового выбора кеш-политики.

## I2C-5 — P2 — Условное число проходов остаётся вместо времени

**Место:** [i2c.cpp:294](../src/i2c.cpp#L294),
[i2c.cpp:661](../src/i2c.cpp#L661).

F4 Finish ждёт STOP не более SystemCoreClock/1000 итераций.
Recover аналогично формирует программные импульсы и называет их ~25 кГц.
Число проходов не задаёт длительность: она зависит от кода, оптимизации и памяти.
Finish вызывается и из IRQ; длинный цикл задерживает другие события.

**Предложение:** согласовать завершение STOP без условного счётчика:
ожидание из main с GetTick либо неблокирующее завершение.
Прямая замена на GetTick внутри запрещённых IRQ не обеспечит таймаут.
Для Recover выбрать доступный источник задержки: Delay_us существует только
на F4/F7 и требует включённого CYCCNT; на G0 такого метода сейчас нет.
Конкретный вариант для G0 требует согласования.

**Статус:** открыто; новые обёртки над счётчиками проходов не предлагаются.

## I2C-6 — P2 — Recover не подтверждает отпускание SCL на каждом такте

**Место:** [i2c.cpp:279](../src/i2c.cpp#L279).

После отпускания open-drain SCL проверяется только итоговый уровень в конце
восстановления. STOP формируется без подтверждения высокого SCL.
При удерживаемом SCL/clock stretching запрошенные импульсы и STOP могут
фактически не произойти.

**Предложение:** определить Recover как операцию восстановления зависшей шины
при исключённой работе другого master. Подтверждать высокий SCL с согласованным
таймаутом до следующего фронта/STOP. Источник времени согласовать вместе с I2C-5.

**Статус:** открыто; Recover уже возвращает NotInit до SetUp и проверяет оба
итоговых уровня, добавлять эти существующие проверки повторно не нужно.

## I2C-7 — Требует подтверждения: короткие последовательности F4 polling RX

**Место:** [i2c.cpp:558](../src/i2c.cpp#L558).

В Poll режиме Process вызывается без маскирования прерываний.
Короткие последовательности ACK/POS, очистки ADDR и STOP могут прерываться.
Прежняя формулировка была слишком широкой: само отсутствие блокировки
не доказывает ошибку всех приёмов 1/2/3 байт; порядок ACK перед очисткой ADDR
в текущем коде уже учитывается.

**Предложение:** при разборе F4 сопоставить конкретные окна последнего приёма
с RM выбранной модели и проверить их при длительном стороннем ISR.
Если защита необходима, согласовать только конкретный короткий участок.
Ожидания и весь transfer engine под общий запрет IRQ не помещать.

**Статус:** аппаратный риск для уточнения, не подтверждённый дефект всех Poll
операций и не основание возвращать IrqLock.

## I2C-8 — P3 — Для IRQ/DMA нужно описать внешний срок ожидания

**Место:** [i2c.hpp](../src/i2c.hpp), [i2c.cpp:270](../src/i2c.cpp#L270).

Внутреннего срока у асинхронной операции нет. При отсутствии ожидаемого
события она может остаться Busy. Abort существует: ставит ERR::Aborted,
останавливает операцию и намеренно не вызывает callback.

**Предложение:** по принятой для UART/SPI модели ограничивать ожидание в main
через GetTick, затем вызывать Abort и при необходимости Recover.
Обновить примеры бесконечного while(IsBusy()). После Abort результат доступен
через GetError; подавление callback должно быть явно описано.

**Статус:** уточнён контракт и понижен приоритет. Автоматический watchdog,
потоки и скрытый сервисный цикл не предлагаются.

## I2C-9 — P3 — Комментарии и примеры отстают от зависимостей

**Место:** [i2c.hpp](../src/i2c.hpp),
[i2c.cpp:246](../src/i2c.cpp#L246), [i2c.cpp:714](../src/i2c.cpp#L714).

Упоминаются отсутствующий IrqLock, идемпотентный Register и прежние cache helpers.
Header обещает отсутствие DMA IRQ на F7/G0, хотя TE IRQ включается.
Callback после выхода из локального участка всё равно выполняется в ISR.
Запуск из callback может дойти до EnableIRQ, а изменение реестра во время
Dispatch запрещено текущим контрактом IRQ.

**Предложение:** после исправления кода сохранить полные комментарии и примеры,
обновив DMAReq, кеш, ошибки, внешний timeout и контекст callbacks.
Разделить завершение по I2C STOP и отдельные DMA error IRQ.
Не обещать произвольное изменение регистрации из callback.

**Статус:** открыто; в этом проходе обновляются review, исходные комментарии
не редактируются.

## I2C-10 — P1 — Регистрация IRQ не учитывает отказ и запрет повторов

**Место:** [i2c.cpp:246](../src/i2c.cpp#L246),
[i2c.cpp:702](../src/i2c.cpp#L702), [irq_registry.hpp](../src/irq_registry.hpp).

BindDmaIrqs вызывает Register для TX/RX без устранения одинаковых векторов
и уже существующих регистраций. Теперь такие повторы возвращают InitError.
Сам отказ повтора не удаляет первый обработчик и не создаёт новую запись —
ошибку нельзя описывать как удвоение цепочки.

При этом все результаты Register игнорируются: при заполненной строке реестра
может не быть даже первой регистрации. EnableIRQ всё равно включает NVIC и ставит
_irq_registered=true. Регистрация EV/ER не имеет отката при частичном отказе.
Изменение реестра не маскирует соответствующий вектор, как требует IRQ Registry.

**Предложение:** регистрировать объект один раз на каждый уникальный вектор,
проверять SysInitStatus, откатывать только добавленные записи. Привязку завершать
из main до обмена, чтобы callback не менял таблицу. Способ возврата ошибки
публичным IRQ API согласовать при изменении модуля.

**Статус:** новое замечание с учётом текущего контракта IRQ.

## I2C-11 — P1 — Недопустимые REG/SPEED проходят к массиву и делению

**Место:** [i2c.cpp:55](../src/i2c.cpp#L55),
[i2c.cpp:316](../src/i2c.cpp#L316), [i2c.cpp:448](../src/i2c.cpp#L448).

Переданный REG преобразуется в длину без проверки допустимых 1/2.
Например, static_cast<REG>(3) приводит к чтению _reg[2] за концом массива
из двух байт во время отправки адреса регистра.

На F4 SetUp не проверяет полный набор SPEED. При допустимом PCLK
static_cast<SPEED>(0) попадает в fast-ветку с делением на 3*0.
Обычные именованные значения enum эти случаи не вызывают.

**Предложение:** проверять допустимые значения на границе соответствующего API
до изменения аппаратуры. Если впоследствии выбирается только статическая
конфигурация, форму компиляционной проверки согласовать отдельно.

**Статус:** новое подтверждённое замечание для недопустимых входных значений;
расширение API скоростей не предлагается.

## I2C-12 — P2 — Статусы подготовки DMA игнорируются

**Место:** [i2c.cpp:359](../src/i2c.cpp#L359),
[i2c.cpp:714](../src/i2c.cpp#L714), [dma.hpp](../src/dma.hpp).

SetMemAddr/SetCount возвращают SysStatus, но Begin запускает канал независимо
от результата. При отказе подготовки останется прежняя настройка.
С текущей byte-конфигурацией, допустимой len и неизменным владением обычная
подготовка должна проходить; проблема проявляется при нарушении этого состояния,
например внешнем Release используемого DMA.

Проверка ошибок также ожидает отсутствующий GetTE_Flag вместо GetErrorFlags,
который дополнительно учитывает DME/FE на F4/F7.

**Предложение:** проверять результаты до запуска и обрабатывать аппаратную
ошибку DMA до уведомления об успехе. Отразить владение DMA в документации;
не добавлять повторную таблицу владельцев.

**Статус:** новое замечание к обработке отказов текущего DMA API.

## I2C-13 — P2 — Жизненный цикл и повторная настройка не закреплены

**Место:** [i2c.hpp](../src/i2c.hpp),
[i2c.cpp:55](../src/i2c.cpp#L55), [i2c.cpp:199](../src/i2c.cpp#L199).

DeInit у I2C нет. Abort завершает обмен, но сохраняет регистрацию и DMA.
При уничтожении локального объекта IRQ Registry может хранить указатель на него,
а DMA оставаться занятым. SetUp разрешает повторный сброс периферии,
AttachDMA — замену/отключение потоков. Это не новая передача и не обычный restart.

**Предложение:** согласовать явный DeInit по образцу UART/SPI либо обязательное
время жизни до конца программы. Отдельно закрепить правила повторного SetUp
и AttachDMA; не навязывать переконфигурацию и автоматический менеджер ресурсов.

## I2C-14 — P2 — STOPF считается успехом без проверки полноты данных

**Место:** [i2c.cpp:448](../src/i2c.cpp#L448),
[i2c.cpp:648](../src/i2c.cpp#L648).

На F7/G0 обработка STOPF вызывает Finish. Если _err не установлен,
ставится Idle и выбирается done callback: ни _idx для CPU-передачи,
ни остаток счётчика DMA не участвуют в подтверждении полноты.
Ожидание EN=0 гарантирует остановку DMA, но не получение всей запрошенной len.

**Предложение:** при исправлении завершения проверить последнюю RXNE и фактический
счётчик после остановки, затем передавать буфер/успех. Проверить сочетания
RXNE+STOPF, DMA error+STOPF и завершение последнего RELOAD.
Не считать сам STOP достаточным подтверждением полного DMA RX.

**Статус:** отсутствие проверки подтверждено исходником. Потеря последнего байта
в обычном аппаратном обмене этим просмотром не доказана; нужен отдельный разбор
порядка событий/проверка на плате.
