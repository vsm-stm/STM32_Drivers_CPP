## Список для обсуждения

### SL-1 — P3 — Универсальность T ограничена восстановлением Node по offsetof

**Место:** [Containers/StaticSList.hpp](../Containers/StaticSList.hpp), строка 41.

**Проблема:** next() восстанавливает Node через offsetof(Node,value) и pointer arithmetic. Для нестандартного layout T/Node offsetof может быть conditionally-supported, хотя template не задаёт ограничения. Node objects также заранее создаются и не уничтожаются при erase.

**Последствие / условие:** Header выглядит универсальным для произвольных объектов, но фактический layout/lifetime contract уже.

**Возможное решение:** Указать поддерживаемые свойства T (или static_assert стандартного layout, если это выбранный контракт). Альтернатива — индекс/iterator вместо восстановления Node из T pointer; менять API только после обсуждения.

**Статус:** исправлено 14.10.2026 по выбору пользователя; неподходящий T отклоняется static_assert при компиляции.

### SL-2 — P3 — Имя erase_if() скрывает удаление только первого совпадения

**Место:** [Containers/StaticSList.hpp](../Containers/StaticSList.hpp), строка 72.

**Проблема:** Метод возвращает bool и немедленно выходит после первого match; это не стандартная семантика удаления всех совпадений.

**Последствие / условие:** Пользователь, ожидающий std::erase_if, оставит остальные совпадения. Фактическое поведение само по себе корректно.

**Возможное решение:** Документировать «erase first» или переименовать в erase_first_if; удаление всех добавлять только если нужно.

**Статус:** исправлено 14.10.2026 по выбору пользователя; метод называется erase_first_if().

### SL-3 — P3 — Не описаны invalidation и допустимые контексты использования

**Место:** [Containers/StaticSList.hpp](../Containers/StaticSList.hpp), строка 85.

**Проблема:** Slot возвращается в free list, но старый T* остаётся адресом того же элемента памяти. После повторного push он обозначает новый объект логически; used не отличает поколения.

**Последствие / условие:** Сохранённый pointer после erase может быть ошибочно использован для другого элемента.

**Возможное решение:** Документировать, что erase инвалидирует pointer и next принимает только живой элемент; операции одного контекста либо внешний контракт. Не добавлять поколения/locks без требования.

**Статус:** исправлено 14.10.2026; контракт описан в заголовке.
