# DMA / DMAReq / DMAMUX: проблемы и предложения

Дата: 12.10.2026. Проверена рабочая копия; сборки и аппаратные тесты в этом проходе не запускались.

**Файлы:** [src/dma.cpp](../src/dma.cpp), [src/dma.hpp](../src/dma.hpp), [src/dma_requests.hpp](../src/dma_requests.hpp).

**Зависимости:** System, RCC, CMSIS DMA/DMAMUX; используется UART, SPI, TIM, ADC, I2C, Modbus и WS2812B через TIM.

## Изменения — 14.10.2026

- DMA-1: таблица G0 выбирается по наличию каналов в CMSIS. Поддержаны пять
  либо семь каналов DMA1 и пять каналов DMA2 на моделях, где он есть.
  IRQ выбран по составу контроллеров; DMA2 использует DMAMUX1 7..11.
- DMA-3: SetUp принимает count=0..65535 без запуска. SetCount принимает
  1..65535; неверное значение не записывается в регистр.
- DMA-4: Stream_EN(DISABLE) ждёт EN=0 без таймаута и без SysTick. Методы
  адресов/счётчика отклоняют изменение при EN=1 через Busy. Барьеры DMB
  упорядочивают доступ к буферу до запуска и после подтверждённой остановки.
- DMA-5: проверяется выбранный запрос после учёта preset, direction/size,
  выравнивание адресов и запрет circular для Mem_To_Mem. Проверка маршрута
  закреплена за периферийным драйвером. По решению пользователя Mem_To_Mem
  на F4/F7 пока отклоняется через InitError до изменения регистров/занятости.
- DMA-6: указатель должен точно совпасть с началом канала/стрима; шаг берётся
  из базовых адресов CMSIS, диапазоны DMA1/DMA2 проверяются отдельно.
- DMA-7: добавлен Release() собственного ресурса. Остановка, сброс регистров,
  очистка флагов и снятие used; при отсутствии владения возвращается NotInit.
  Выбор из конструктора сохраняется. DMA не управляет чужими IRQ и общим NVIC.
- DMA-8: общие CacheClean/CacheInvalidate/CacheCleanInvalidate находятся
  в System. На F7 пропускают диапазон целиком в настроенной DMA-области;
  на F4/G0/L0 определены как пустые inline-функции. Момент и диапазон задаёт
  потребитель; перенос вызовов в периферию выполняется при её разборе.

DMA-2 отложен по решению пользователя: ADC/I2C и совместимость их нового API
сейчас не исправляются. UART/SPI/TIM и их AttachDMA также не менялись.
Обновлены DMA.md, System.md, ReadMe.md и комментарии. Сборки и тесты не запускались.

Уточнения закрыты: Mem_To_Mem на F4/F7 пока не поддерживается;
Stream_EN() сохраняет void, подготовку запуска обеспечивает вызывающий код.
SetUp(count=0) остаётся успешным. Имеющаяся реализация Mem_To_Mem на G0 сохранена.

## Список для обсуждения

### DMA-1 — P1 — Таблица G0 жёстко ограничена G030/G031/G041

**Место:** [src/dma.cpp](../src/dma.cpp), строка 39.

**Проблема:** Для всех G0 используется DMA1_Ch4_5_DMAMUX1_OVR_IRQn и только пять каналов. В локальном stm32g071xx.h IRQ называется DMA1_Ch4_7_DMAMUX1_OVR_IRQn и определены Channel6/7.

**Последствие / условие:** G071 не компилирует текущий dma.cpp; каналы 6/7 и DMA2 других G0 не описаны.

**Возможное решение:** Разделить IRQ/таблицы по возможностям device header. Добавлять только существующие каналы и контроллеры; не объявлять все G0 одинаковыми.

**Статус:** исправлено 14.10.2026 по согласованному пункту; сверено с локальными device headers. Сборка после изменения не запускалась.

### DMA-2 — P1 — Новый API потребителей отсутствует в DMA

**Место:** [src/dma.hpp](../src/dma.hpp), строка 244.

**Проблема:** Есть SetUp(settings), ClearFlags/GetTC_Flag и Stream_EN(). ADC/I2C требуют RequestSet, SetUp(settings,requests), Release, GetTE_Flag, ClearTC_Flag и CacheRxOk/CacheClean/CacheInvalidate. В request tables также отсутствуют I2c1::TX_alt, I2c3::RX_alt, I2c4 и G0 I2c3.

**Последствие / условие:** ADC/I2C сейчас не компилируются с этой зависимостью, независимо от корректности их state machine.

**Возможное решение:** Сначала согласовать минимальный общий API DMA и таблицы допустимых запросов, затем подстроить потребителей. Не добавлять отсутствующие методы только ради подавления ошибок компиляции.

**Статус:** отложено по решению пользователя 14.10.2026. Release добавлен по DMA-7; RequestSet, перегрузки SetUp и прочий API потребителей сейчас не добавлены. Кеш согласован через System, без Cache*-обёрток в DMA.

### DMA-3 — P1 — SetCount() принимает значения вне аппаратного 16-битного счётчика

**Место:** [src/dma.hpp](../src/dma.hpp), строка 262.

**Проблема:** Проверяется только n!=0; SetUp() также напрямую пишет settings.count. Значения >65535 не отвергаются.

**Последствие / условие:** Длина 65536 превращается в нулевой счётчик, а большие длины обрезаются; драйвер может ждать завершения несуществующей передачи или считать неполный буфер завершённым.

**Возможное решение:** Проверять диапазон 1..65535 для запуска, а нулевую конфигурацию разрешать только как явно незапущенный setup. Большие передачи разбивать на согласованные блоки.

**Статус:** исправлены диапазоны SetUp/SetCount 14.10.2026. SetUp(count=0) разрешён без запуска. По выбору пользователя Stream_EN сохраняет void; подготовка корректных аргументов запуска возложена на вызывающий код.

### DMA-4 — P1 — Изменение адресов/счётчика не связано с подтверждением EN=0

**Место:** [src/dma.hpp](../src/dma.hpp), строка 303.

**Проблема:** Stream_EN(DISABLE) только очищает EN; setters сразу записывают регистры и не проверяют состояние. SetUp ждёт EN=0, но обычные периферийные пути при abort/restart — нет.

**Последствие / условие:** F4/F7 могут ещё завершать транзакцию после очистки EN. Новые адреса/NDTR или invalidate RX в это время выполняются преждевременно; комментарий ADC о том, что Stream_EN «ждёт», неверен.

**Возможное решение:** Согласовать простой путь остановки с подтверждением EN=0 перед перенастройкой/передачей буфера CPU. Таймаут использовать только с доступным источником времени; не превращать число итераций в миллисекунды.

**Статус:** исправлено 14.10.2026 по выбору пользователя: остановка без таймаута, пригодная для IRQ; адреса/счётчик меняются только при EN=0. SetUp и Release используют тот же Stream_EN(DISABLE).

### DMA-5 — P2 — Проверяется settings.channel, а используется другой effective request

**Место:** [src/dma.cpp](../src/dma.cpp), строка 86.

**Проблема:** F4/F7 проверяют settings.channel<=7 до выбора _preset_ch. G0 лишь маскирует eff_ch, не проверяя request ID; direction/data_size, alignment и допустимые сочетания не проверяются.

**Последствие / условие:** Некорректный preset записывает соседние поля; G0 request может молча превратиться в другой. Один CHSEL без проверки stream не подтверждает маршрут периферии.

**Возможное решение:** Проверять eff_ch после выбора preset, допустимые поля и маршруты для данного MCU. RequestSet должен описывать реальные пары stream/channel, а не только число CHSEL.

**Статус:** проверка полей/выравнивания исправлена 14.10.2026. По выбору пользователя маршруты и зарезервированные request ID проверяются потребителем при его разборе. Mem_To_Mem на F4/F7 пока отклоняется через InitError, его поддержка через FIFO отложена.

### DMA-6 — P2 — GetStreamIndex() принимает адрес внутри регистра блока

**Место:** [src/dma.cpp](../src/dma.cpp), строка 65.

**Проблема:** Диапазон проверяется, затем индекс вычисляется целочисленным делением без проверки остатка.

**Последствие / условие:** Некорректный указатель stream+4 будет принят как существующий stream, но accessor запишет другие регистры.

**Возможное решение:** Проверять точное совпадение с адресом канала/стрима либо шаг и остаток; это короткая проверка входа SetUp().

**Статус:** исправлено 14.10.2026: отдельные диапазоны контроллеров и проверка остатка относительно аппаратного шага.

### DMA-7 — P2 — Нет завершённого контракта владения каналом

**Место:** [src/dma.cpp](../src/dma.cpp), строка 94.

**Проблема:** used устанавливается навсегда после SetUp(). AttachDMA разных драйверов игнорируют ошибку либо новые ADC/I2C ожидают Release(). Объект DMA и аппаратный канал не имеют единой модели повторного использования.

**Последствие / условие:** Повторное подключение может считать чужой канал своим; замена канала оставляет старый занятым.

**Возможное решение:** Согласовать SetUp/Release и обработку ошибки AttachDMA. Release выполняет остановку и снимает занятость только своего ресурса. Если lifetime строго статический, это должно быть единым контрактом всех потребителей.

**Статус:** контракт DMA и Release реализованы 14.10.2026. При штатном завершении ресурс остаётся назначенным; повторный SetUp до Release — ошибка. Отключение запросов периферии, её адресное unregister и проверка результатов AttachDMA остаются работой соответствующих потребителей.

### DMA-8 — P1 — Обслуживание D-cache не согласовано с потребителями

**Место:** [src/dma.hpp](../src/dma.hpp), строка 244.

**Проблема:** DMA не имеет cache API; SPI/TIM не обслуживают кеш, UART делает только TX clean, ADC/I2C ссылаются на отсутствующие helpers.

**Последствие / условие:** При включённом D-cache F7 данные TX/RX могут быть устаревшими либо DMA-данные перезаписываются грязными строками.

**Возможное решение:** По принятому решению: обслуживание затронутых 32-byte lines внутри драйверов на границах передачи. Общие примитивы и требования владения линиями согласовать здесь; для RX завершать DMA до invalidate и не чистить устаревшие RX-строки после приёма.

**Статус:** общие операции System и контракт передачи реализованы/описаны 14.10.2026 по выбору пользователя. Интеграция вызовов в UART/SPI/TIM/ADC/I2C отложена до их разбора; работа этих DMA-путей с D-cache пока не объявляется исправленной.
