# UART / USART — согласованные исправления

## Единый снимок DMA и автоматический запрос G0 — 19.10.2026

G0 конструктор принимает только DMAx_Channely: TX/RX request выбирается USART.
Именованные Req F4/F7 сохраняют прежний формат. Modbus минимально обновлён для
того же типа аргументов. DMA TX/RX IRQ читают TC и ошибки одним GetIRQFlags.
Подробные примеры и комментарии обновлены. Сборки и тесты не запускались.

## Выбор атомарных операций через заголовок — 19.10.2026

- По выбору пользователя UART_USE_ATOMIC определён в uart.hpp через #ifndef,
  значение по умолчанию — 0. Настройка общая для uart.cpp и inline-методов.
- UART_SET_BIT/UART_CLEAR_BIT/UART_MODIFY_REG — прямые макросы-псевдонимы:
  при 0 выбирают обычные SET_BIT/CLEAR_BIT/MODIFY_REG, при 1 — ATOMIC_* ST.
  Ветвлений при выполнении, новых функций и полей объекта нет.
- Переключаются изменения битов CR1/CR3 и полей RCC, обслуживаемых UART.
  SetBaud в обоих режимах восстанавливает только прежний бит UE.
- Значение должно совпадать во всех единицах трансляции. Пользователь меняет
  настройку в uart.hpp и пересобирает драйверы и приложение.
- Комментарии и UART.md обновлены. Выполнен просмотр исходников/diff;
  сборки и тесты обоих режимов не запускались.

## Очистка NE на G0 — 19.10.2026

ISR_FLAGS::NE использует USART_ICR_NECF на G0 и USART_ICR_NCF на F7.
SetUp, Receive, Receive_IRQ и Receive_DMA берут бит очистки из этого enum;
прямых ссылок на имя F7 в общих ветках .cpp больше нет.
Изменение сверено с локальными CMSIS-заголовками. Сборка и тесты не запускались.

## Предыдущий этап: атомарное изменение управляющих регистров — 19.10.2026

- По согласованию применены готовые ATOMIC_SET_BIT/ATOMIC_CLEAR_BIT ST ко всем
  изменениям битов CR1/CR3 в uart.cpp и uart.hpp, включая IRQ_en/DMA_en,
  завершение и ошибочные ветки UART/DMA IRQ.
- В SetUp бит тактирования UART изменяется через ATOMIC_SET_BIT, а поле
  источника RCC на F7/G0 — через ATOMIC_MODIFY_REG с сохранением других полей.
- SetBaud атомарно отключает UE и восстанавливает только его прежнее значение,
  сохраняя остальные текущие биты CR1 вместо записи старого снимка целиком.
- F4/F7 используют LDREX/STREX с повтором, G0 — краткое маскирование IRQ
  с восстановлением прежнего PRIMASK. Это атомарность отдельного изменения
  регистра; контракт сериализации операций и состояния остаётся прежним.
- SR/ICR, DR/TDR, BRR и полные записи инициализации/DeInit сохраняют прямые
  обращения. Снимки регистров для проверок IRQ сохранены.
- Комментарии и UART.md обновлены. Выполнен просмотр исходников/diff;
  сборка, тесты, сравнение ассемблера и измерения тактов не запускались.

## Сокращение чтений регистров USART IRQ — 18.10.2026

- Проверки RXNEIE/TXEIE/IDLEIE, G0 RXFTIE/TXFTIE и разрешения DMA RX используют
  начальные снимки CR1/CR3. До первого callback повторных чтений для этих
  условий нет. Ветка ошибок, изменяющая настройки, заканчивается return.
- F4/F7 принимают один байт по уже прочитанному RXNE без дополнительного
  чтения SR/ISR. На G0 сохранены ограниченный FIFO-loop и проверки наличия
  следующих байтов.
- Проверка DMAT перед OnTxEmpty использует начальный снимок CR3.
  TCIE и TC читаются повторно после callbacks и записи очередного байта.
- F4/F7 сохраняют именованные DMAReq в конструкторе, например:
  USART pc_usart(USART3, 115200, USART::_3::TX::PD8, USART::_3::RX::PD9,
  DMA_Sx::Req::Usart3::TX_DMA1_Stream3, DMA_Sx::Req::Usart3::RX_DMA1_Stream1).
- Выполнен просмотр исходников/diff. Сборки, тесты, сравнение ассемблера
  и измерения тактов не выполнялись; оценка экономии тактов не подтверждена.

## Уточнение API Req и предела IRQ — 18.10.2026

- USART принимает именованные Req после пинов и содержит два DMA_Sx внутри.
  На F4/F7 передаётся Req с потоком; на G0 — {DMAx_Channely, Req}. Пустое {}
  отключает соответствующую привязку. Отдельные DMA-объекты/указатели не нужны.
- Проверка Req выполняется через DebugTrap в обычном конструкторе: валидность,
  принадлежность USART, направление и разные TX/RX ресурсы. Config/consteval
  USART не вводились, как уточнил пользователь. Захват ресурса остаётся в SetUp.
- Принадлежность/направление UART записаны в DMAReq. Дублирующая таблица
  uart_dma_req_table и её обход из SetUpDMA удалены. На F4/F7 адрес потока хранится
  целой константой DMAx_Streamy_BASE; указатель создаётся в DMA_Sx. Имена,
  аппаратные адреса, CHSEL и G0 request IDs сохранены.
- USART содержит оба DMA_Sx даже при пустых Req, без heap/optional/совместимых
  оболочек прежнего API. HasSelection проверяет наличие выбранного ресурса;
  DeInit освобождает ресурс и сохраняет выбор для нового SetUp.
- UART RX/TX обслуживают не больше глубины FIFO за вход в каждом направлении:
  G0 FIFO — 8 слов, иначе 1 байт. IDLE пропускает обычный RX-loop, хвост имеет
  единственный такой же предел. Приход новых байтов не продлевает цикл без границы.
- Modbus минимально переведён на Req и внутренние DMA USART. Протокол,
  callbacks и алгоритм SendData не изменены. Обязательные TX/RX проверяются
  конструктором вместо проверки внешних DMA-указателей в SetUp.
- Комментарии/примеры, UART.md, DMA.md и README обновлены. Выполнен просмотр
  исходников/diff; сборка, тесты и измерение размера/ассемблера не запускались.

## Предыдущий этап разделения IRQ

- Реестр IRQ сохранён. USART, DMA TX и DMA RX имеют отдельные точки входа.
  Два DMA-направления регистрируются отдельно, в том числе на общем векторе.
- На F4/F7 IDLE запрашивает остановку DMA без ожидания; финальные count,
  кеш и ready публикуются из DMA RX IRQ по TC. До этого RX остаётся Busy.
- Ошибки USART сохраняются до завершения остановки RX. Ошибки DMA
  обслуживаются только обработчиком соответствующего направления.
- В DMA добавлены RequestStop и IsEnabled. Блокирующая остановка сохранена
  для вызовов из основного кода; другие драйверы пока не мигрированы.
- DMA TX/RX передаются после пинов в конструкторе, ClockSource следует после DMA.
  Привязки неизменяемые; SetUp настраивает DMA и откатывает свои ресурсы при отказе.
  AttachDMA удалён. DeInit освобождает ресурсы, сохраняя привязки.
- В Modbus изменены только передача DMA конструктору USART, удаление AttachDMA
  и явный override у OnTC. Остальная логика протокола не менялась.
- На G0 IDLE отключает DMAR/DMA без ожидания и завершает пакет в USART IRQ.
  Последний запрос DMA должен быть уже обслужен до остановки; это ограничение
  описано в uart.hpp, UART.md, DMA.md и README. Ошибочный пакет отбрасывается
  без вычисления длины по CNDTR. В USART IRQ блокирующей остановки больше нет.
- Сборки, тесты и аппаратные проверки этого этапа не запускались.

и ожидание остановки в IRQ заменены описанием текущего этапа выше.

## Результат по пунктам

| Пункт | Что изменено |
|---|---|
| UART-1 | UART-флаги проверяются вместе с разрешениями CR1/CR3 и активным состоянием. CPU не читает RDR при активном DMA RX. Descriptors инициализированы. TXE обрабатывается до повторной проверки TC, чтобы не уведомлять по старому флагу после загрузки следующего байта. |
| UART-2 | TX clean, RX clean+invalidate до DMA, invalidate после остановки для реально записанного диапазона. Используются System helpers с пропуском проектных некешируемых областей. Отмена активного DMA через DeInit также возвращает буфер CPU; завершённый буфер повторно не инвалидируется. |
| UART-3 | Общие статусы/флаги/счётчики volatile. GetDataReceivedCount — чистое чтение: Busy/нет готового пакета дают 0. Явный сброс через ClearDataReceivedFlag. Чтение/сброс overflow допускается после остановки. Потоки и блокировки не добавлены. |
| UART-4 | IDLE заканчивает пакет: DMAR выключается, DMA ждёт EN=0, затем читается счётчик, обслуживается кеш и публикуется готовность. F4 SR/DR выполняется после остановки с сохранением ожидающего байта. FIFO-хвост ниже RXFT читается при IDLE. Повторная публикация после DMA TC исключена состоянием и отключением источника. |
| UART-5 | Все режимы проверяют настройку, направление, указатель, длину и Busy. Нулевая длина — Error. IRQ/DMA: 1..65535 без обрезки. Проверяются результаты SetMemAddr/SetCount. Новый RX очищает состояние прошлого пакета; запуск DMA предшествует включению запросов UART. |
| UART-6 | Общая маска PE/FE/NE/ORE, чтение ошибок DMA. Ошибка имеет приоритет над успешным завершением; останавливается своё направление, выставляется Error, вызывается OnError с общей маской. Повреждённый приём не публикуется как ready. После Error/Timeout возможен новый запуск. |
| UART-7 | AttachDMA возвращает SysInitStatus, проверяет полный DMAReq, повторное подключение, SetUp и Register. При отказе освобождаются только приобретённые текущим вызовом ресурсы. Общий TX/RX IRQ регистрируется один раз. IRQ_en не меняет реестр; регистрация UART живёт от SetUp до DeInit. |
| UART-8 | На F7/G0 конструктор фиксирует ClockSource: PCLK (по умолчанию), SYSCLK, HSI, LSE с учётом доступности экземпляра. Источник применяет SetUp; HSI/LSE только проверяются на включение и готовность, запускает их вызывающий код. F4 — PCLK. G0 PRESC=/1, oversampling x16. BRR округляется и проверяется по частоте выбранного источника; SYSCLK учитывает HPRE. SetBaud возвращает SysStatus, использует тот же источник, пишет с UE=0, сохраняет BaudRate. |
| UART-9 | Наличие каждой периферии/GPIO проверяется отдельно. Восстановлен USART6 F411; добавлены runtime/DMA-строки UART7/8 и G0 USART3..6. Учтены общие IRQ G070/G071/G0B0/G0B1. FIFO проверяется по CMSIS, all=5. Исправлены G0 USART1 PA9/PA10 AF1, USART4 PA0/PA1 AF4, PC10/PC11 AF1. |
| UART-10 | DeInit выключает источники и запросы, останавливает свои DMA, снимает только свои регистрации, освобождает DMA и обнуляет состояние до NotInit. Общие обработчики и их NVIC сохраняются. |
| UART-11 | Обновлены комментарии, UART.md и разделы README: реальные статусы, общий таймаут вызова, очередь TX против физического TC, владение буферами, ошибки, явный сброс ready и callbacks protected с вызовом базовой обработки. |

## Согласованные изменения DMA

В [dma.hpp](../src/dma.hpp) добавлены только CanUseRequest(DMAReq) и GetErrorFlags().
В [dma_requests.hpp](../src/dma_requests.hpp) исправлен маршрут USART1 DMA2_Stream5:
это RX, актуальное имя — RX_DMA2_Stream5;
добавлены недостающие UART7/8 и G0 USART3..6. Остальная периферия не менялась.

Маршруты UART проверяются по именованным DMAReq, включая описанные альтернативы.
Добавление всех возможных дополнительных маршрутов каждого MCU отдельно не выполнялось.
LPUART и F4 UART9/10 не добавлялись.

## Контракты и последующие проверки

- **UART-8 — решение принято:** ожидание физического TC перед SetBaud обеспечивает
  вызывающий код. Дополнительного флага в драйвере нет; Busy проверяет только
  программные операции. При очистке TC в IRQ завершение учитывается по OnTC().
- Завершённый пакет обрабатывается до ClearDataReceivedFlag и следующего Receive.
- Для кешируемого F7 RX нужны принадлежащие буферу целые 32-байтные строки.
  Диапазон в одной настроенной dma_regions области пропускается внутри System.
- DMAR=0 не отключает UART-приёмник. Приём между пакетами не гарантируется;
  следующий запуск удаляет старый ввод/ошибки.
- Переопределённые операционные callbacks вызывают базовый метод; OnTC/OnError
  имеют пустые реализации. Реестр и владение ресурсами из callbacks не меняются.
- Операции очистки кеша зависят от числа строк/записей в RAM и барьеров.
  Для численных оценок overhead нужны отдельные сборка и аппаратное измерение.

**Совместимость Modbus:** его текущий вызов GetDataReceivedCount рассчитывал на сброс
ready. Нужен явный ClearDataReceivedFlag при разборе Modbus. По правилу работы
по одному модулю Interfaces/Modbus-slave.* не изменены.

**Ещё не подтверждено сборкой/железом:** совместная сборка с base на выбранных MCU,
обычный/повторный запуск, IDLE с последним байтом, одновременные IDLE/TC/error,
общие IRQ, отказ/откат AttachDMA, отмена DeInit и F7 DMA с кешируемой/некешируемой RAM.
