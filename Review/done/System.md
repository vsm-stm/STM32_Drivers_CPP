## Список для обсуждения

### SYS-1 — P2 — Крайний предел Delay_ms() оставляет слишком узкое окно завершения

**Место:** [src/system.cpp](../src/system.cpp), `System::Delay_ms()`.

**Проблема:** При delay == UINT32_MAX сравнение разности тиков с wait заканчивает ожидание только при разности UINT32_MAX. После следующего тика разность снова нулевая.

**Последствие / условие:** Если опрос пропустит единственное подходящее значение, задержка продолжится ещё один оборот счётчика. Это крайний случай ожидания около 49,7 суток, а не обычных задержек.

**Возможное решение:** Обсудить максимальный аргумент Delay_ms(): ограничить половиной диапазона тиков либо явно исключить такие длительности из контракта. Ограничение Delay_us() в 0x7FFFFFFF тактов уже реализовано и к этому пункту не относится.

**Статус:** принято и исправлено 13.10.2026. Ожидание, включая компенсирующий тик,
ограничено `0x7FFFFFFF` тиками. Для обычных задержек компенсация сохранена;
`Delay_ms(0)` по-прежнему ждёт следующего тика. Обновлены комментарии и документация.
Сборки и аппаратные тесты после этой правки не запускались.

## Уже согласовано и сохранено

- InitAfterBootloader(): HSI, делители /1, питание G0 Range 1, Flash 0 WS;
  компилируется и вызывается из Init() только при STM32_USE_BOOTLOADER.
  База задаёт макрос автоматически по bootloader в project.json; он общий
  для обоих образов и библиотеки драйверов. Без макроса Init() предполагает
  аппаратный сброс и выполняет обычную настройку частот/SysTick/ядра.
  PLL/HSE, MCO, подстройка HSI и RCC-прерывания сохраняются.
- Первые ожидания HSI без таймаута; VOS/Flash — по GetTick() с пределом 100 мс.
- FPU под STM32_STARTUP_ENABLES_FPU; base передаёт определение.
- DWT F7 разблокируется; Delay_us() использует 64-битный расчёт и предел 0x7FFFFFFF тактов.
- SWOTrace() неблокирующий; DebugTrap() использует блокирующий SWO; SetDebugOutput() удалён.
- Ограничения SysTick и MPU описаны в [System.md](../System.md).
- Обслуживание кеша в DMA-путях остальных драйверов остаётся следующим этапом; проблемные места указаны в их отчётах.

## Дополнительно согласовано и реализовано 13.10.2026

- `dma_regions` в project.json: список `name`, `size`, `memory` (SRAM1/SRAM2),
  `mpu_region`; адрес автоматически выделяется с конца выбранной памяти.
- Только F7 с драйверами; только обнуляемые буферы во внутренней SRAM.
- Linker исключает области и отступы выравнивания из обычной RAM и передаёт
  startup записи обнуления, а System — записи настройки MPU.
- `System::Init()` сохраняет изменённые данные при выключении уже работающего
  D-cache, настраивает заданные регионы и снова включает кеш.
- Настройка DMA-регионов вынесена в InitDMARegions(), вызов остаётся в Init().
- Размещение буферов, ограничения и обновление шаблона базы описаны в [System.md](../System.md).
- После этих правок сборки и аппаратные тесты не запускались.
