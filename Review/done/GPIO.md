# GPIO / PIN / PinArray: проблемы и предложения

Исходный обзор: 12.10.2026. Обновлено: 14.10.2026. Проверена рабочая копия; сравнение объектного кода GPIO описано ниже.
Полные сборки и аппаратные тесты не запускались.

**Файлы:** [src/gpio.cpp](../../src/gpio.cpp), [src/gpio.hpp](../../src/gpio.hpp).

**Зависимости:** System и CMSIS RCC/GPIO; PIN используется всеми периферийными драйверами.

## Запись конфигурации — 20.10.2026

SetUp больше не сбрасывает MODER во вход перед настройкой. OTYPER, OSPEEDR,
PUPDR, AFR и MODER записываются по одному разу с заменой поля пина.
MODER — последняя запись; начальный OUTPUT-уровень выставляется через BSRR.
Прежняя очистка остальных полей для INPUT/ANALOG сохранена. Это убирает
промежуточное отпускание из-за MODER=00, но не делает весь SetUp атомарным.
Сравнение ассемблера в исходном обзоре относится к прежней версии; сборки,
новый замер кода и аппаратные тесты этого изменения не запускались.

## Список для обсуждения

### GPIO-1 — P1 — SetUp() не проверяет валидность PIN

**Место:** [src/gpio.cpp](../../src/gpio.cpp), строка 10.

**Проблема:** Default PIN{} имеет port=0; SetUp() вычисляет gpio_id и сдвиг RCC-бита, затем обращается к PORT(). Constexpr-конструктор и публичное pin допускают pin>=16; af_override не ограничен 0..15.

**Последствие / условие:** Необязательный PIN{}, например SS в SPI, вызывает недопустимый сдвиг/обращение к адресу 0. Неверные pin/AF могут записать поля соседних пинов.

**Возможное решение:** В начале SetUp() проверить допустимый порт, pin<16 и AF<16 с возвратом InitError. Драйверы должны пропускать отсутствующие необязательные пины.

**Сделано:** сохранён формат `{GPIOx_BASE, pin, af, peripheral}`, конструктор
стал consteval. GPIO-порт должен присутствовать в CMSIS выбранного МК, номер и AF
должны быть в диапазоне 0..15. Аргументы номера/AF принимаются как uint32_t, чтобы
проверка отклоняла значения вроде 256 до принятия в 8-битные поля.
Проверки этой перегрузки выполняются только при компиляции. По уточнению
пользователя обычный конструктор PIN(GPIO_TypeDef*, uint8_t, uint8_t) сохранён
для создания через GPIOA и аналогичные CMSIS-указатели. Runtime BKPT/цикл не
возвращены; поддерживаемый порт и диапазон номера/AF обеспечивает вызывающий код.

Порт, номер и сохранённый AF закрыты и const. periph_base оставлен публичным const
для чтения существующими проверками USART/SPI/I2C. Присваивание другого PIN
запрещено, копирующее/перемещающее создание и присваивание bool сохранены.
PinArray сразу создаёт элементы через список инициализации, без присваивания.
Размер и набор хранимых полей не увеличены. Явный AF override в SetUp остаётся
runtime-параметром 0..15 под ответственностью вызывающего кода. PIN{} — признак
отсутствующего сигнала; его нельзя настраивать или использовать для доступа к GPIO.

**Согласованная миграция зависимостей:** ADC/TIM будут изменены при разборе
соответствующих модулей: определения/таблицы пинов по образцу USART с проверкой
при объявлении. Конструктор с указателем сохранён, поэтому прежние вызовы
создания PIN в ADC/TIM поддерживаются. В DAC остаётся присваивание целого PIN;
его потребуется заменить созданием с нужной привязкой при разборе DAC.
Код этих модулей не изменён.

**Статус:** GPIO реализован с двумя конструкторами; будущий переход ADC/TIM
на таблицы остаётся в их очереди. Присваивание PIN в DAC ожидает изменения.

### GPIO-2 — P2 — TogglePin() меняет весь ODR через read-modify-write

**Место:** [src/gpio.hpp](../../src/gpio.hpp), строка 145.

**Проблема:** ODR ^= bit читает и записывает весь порт. Другая операция SetLevel() через BSRR между чтением и записью изменяет бит, который старый ODR затем затрёт.

**Последствие / условие:** При использовании разных пинов одного порта из main/IRQ теряются изменения, хотя SetLevel() сам использует BSRR.

**Возможное решение:** Для toggle читать выбранный бит и записывать его set/reset через BSRR: это сохраняет чужие биты. Одновременные toggle одного пина потребуют отдельного согласованного контракта, без общего замка для всех драйверов.

**Сделано:** сохранён ODR ^= bit, добавлен комментарий о запрете изменения
того же порта из IRQ во время read-modify-write. Вариант через BSRR не внедрён.
Сравнение по тактам не выполнялось. В документации также исправлено утверждение
об атомарности TogglePin_BB: чтение и запись бита являются отдельными операциями.

**Статус:** поведение сохранено, ограничение документировано.

### GPIO-3 — P2 — PinArray теряет вид ошибки настройки

**Место:** [src/gpio.hpp](../../src/gpio.hpp), строка 191.

**Проблема:** Любая ошибка PIN::SetUp() превращается в SysInitStatus::NotInit, хотя метод возвращает InitError. Сейчас отсутствие проверок маскирует этот путь.

**Последствие / условие:** После GPIO-1 массив будет возвращать другое состояние вместо причины неудачной инициализации; частичная настройка остальных пинов остаётся неочевидной.

**Возможное решение:** Вернуть InitError либо первый полученный статус и описать, что настройка всех элементов продолжается.

**Сделано:** SetUpAll настраивает все элементы, сохраняя первый статус,
отличный от InitOK. Преобразование ошибки в NotInit удалено.

**Статус:** реализовано.

### GPIO-4 — P3 — Не задано поведение вывода при переводе в OUTPUT

**Место:** [src/gpio.cpp](../../src/gpio.cpp), строка 16.

**Проблема:** SetUp() меняет MODER и атрибуты, но не задаёт начальный ODR. Из предыдущего использования порта сохраняется уровень.

**Последствие / условие:** Для CS/DE/силовых выходов промежуточный уровень может отличаться от ожидаемого. Это вопрос контракта, а не требование добавлять автоматический уровень всем пинам.

**Возможное решение:** Документировать установку нужного уровня BSRR перед включением OUTPUT либо согласовать параметр начального уровня. Режим следует включать последним, как уже сделано в конце SetUp().

**Сделано:** перегрузки SetUp принимают LVL initial_level с default LOW.
Для OUTPUT уровень записывается через BSRR перед итоговым включением режима в
MODER, в том числе при повторной настройке. Для INPUT/AF/ANALOG уровень не меняется.

**Статус:** реализовано.

## Вычисление индекса порта

Сравнены две версии текущего gpio.cpp: деление смещения на
GPIOB_BASE - GPIOA_BASE и явный сдвиг на 10 со static_assert шага 0x400.
Компилятор: arm-none-eabi-g++ 13.3.1 (STM32CubeCLT 1.19.0), C++20, Thumb,
soft-float, без LTO. Использованы локальные заголовки CMSIS и устройств.

| MCU | Ядро | Оптимизация | Результат |
| --- | --- | --- | --- |
| STM32F429 | Cortex-M4 | -O0 / -Og / -Os | Полное совпадение дизассемблированного кода |
| STM32F767 | Cortex-M7 | -O0 / -Og / -Os | Полное совпадение дизассемблированного кода |
| STM32G031 | Cortex-M0+ | -O0 / -Og / -Os | Полное совпадение дизассемблированного кода |

Во всех девяти парах деление превратилось в сдвиг на 10; инструкции UDIV и
вызовов __aeabi_uidiv/__udivsi3 нет. По результату оставлено деление через
разность адресов CMSIS: оно не требует литерала 10 и даёт тот же машинный код.
Дополнительное поле номера порта не добавлено.
