# ADC IRQ: сравнение до и после упрощения

Дата: **18.10.2026**.

Последующее исправление: ошибка consteval ADC_PIN, отмеченная ниже при оценке
IRQ, уже устранена. Таблицы и adc.hpp компилируются для G031/F429/F767.
Результаты сравнения IRQ относятся к сохранённым версиям до этого переноса типа.

## Изменения

- Без DMA выполняется обновление состояния одиночного захвата; с DMA — обработка его завершения. Общая обработка ADC overrun сохранена.
- Ошибки DMA читаются один раз за вызов IRQ. На конечном TC это происходит после EN=0.
- Успешный конечный TC больше не вызывает StopDMA с повторным чтением ошибок и дополнительными проверками указателей.
- Ошибочный путь останавливает захват, очищает свои флаги и вызывает один OnError. OnOverrun удалён.
- При ошибке DMA-буфер отбрасывается без invalidate. Частичные данные использовать нельзя.
- На F4/F7 событие конца последовательности вызывает только OnEOS. OnEOC остаётся только на G0.
- TIM, DMA и их API не менялись. HT/TC по половинам пока не подключены; в circular TC по-прежнему инвалидируется весь буфер.

## Метод

Сравниваются сохранённые исходники непосредственно до этой правки и текущие тела HandleIRQ/StopDMA. GCC 13.3.1, C++20, -Os, -mthumb, -mfloat-abi=soft, -fno-exceptions, -fno-rtti; Cortex-M0+/M4/M7 соответственно. Без LTO. Использованы настоящие CMSIS-заголовки выбранных МК и текущие inline-методы DMA/System.

Это **изолированная компиляция**, а не сборка готовой прошивки. В копиях заголовков для анализа исключены именованные ADC_PIN и DMAReq-таблицы, которые не относятся к телу IRQ. Для отсутствующего TIM_TriggerGenerator объявлена только сигнатура Stop; реализация не подменялась и ошибка полного драйвера не исправлялась. В разобранных путях вызова таймера нет. Разметка объектов ADC/DMA сохраняется.

Учтены: HandleIRQ, исполняемые StopDMA/Stream_EN/ClearFlags, пустые callbacks, диспетчер IRQ с одним занятым и двумя пустыми слотами, входная программная обёртка. Для EOC/EOS на G0 активны оба события; на F4/F7 до правки вызывались оба callbacks, после — только OnEOS. В DMA-путях ADC EOC/EOS/OVR не установлены; в ошибочном пути установлен DMA error без TC, указатель на таймер нулевой. DMA EN снимается при первой проверке.

Число инструкций включает позиции условных IT-инструкций. Неисполненные условные записи в оценке тактов считаются пустыми слотами, без доступа к памяти. Это счёт по выбранному пути, не размер всей функции.

Оценка тактов использует прежнюю простую скалярную модель: ALU — 1, LDR/STR — 2, LDRD/STRD — 3, BL/BLX — 3, операции со стеком зависят от числа регистров, переходы — 1–3 (M0+ taken — 2). Барьеры учитываются только как инструкции. Это не симуляция конвейера, предсказателя или двойной выдачи M7. Диапазон не является гарантированной нижней/верхней границей времени.

Исключены аппаратный вход/выход из исключения, задержки памяти/шин/Flash, реальные задержки барьеров/кеша, дополнительные итерации EN и пользовательский код callbacks. Поэтому числа нельзя выдавать за измерение на плате.

## Кеш и ошибки F7

Успешный TC по-прежнему инвалидирует весь буфер: масштабируемые затраты кеша на успешном пути не уменьшились. Это требует отдельной интеграции HT/TC в DMA.

При DMA error проход убран полностью. Для выровненного буфера 16 КиБ прежняя функция invalidate занимала по той же модели 3126–4152 такта без аппаратных задержек. На F767/216 МГц ошибочный путь до правки: примерно **15,43–20,36 мкс**, после: **0,86–1,03 мкс**. Это выбранный путь DMA error без TC/ADC overrun, с пустым OnError; не гарантия времени при любой ошибке.

Для некешируемого буфера при ошибке исчезает лишь вызов проверки области; большого прохода и до правки не было.

## Границы результата

Выполнена компиляция выделенных фрагментов до/после для трёх ядер; дополнительно получен ассемблер -Og/-O0, но таблицы относятся только к -Os. Предупреждений компилятора нет. Аппаратных измерений и тестов нет. Полная сборка остаётся заблокированной отсутствующим TIM_TriggerGenerator и обнаруженной ошибкой consteval ADC_PIN в статических таблицах вложенного класса. Эти проблемы не исправлялись в данной задаче.

Основной результат — меньше работы на конечном DMA TC и один callback вместо двух на F4/F7. На circular TC выигрыш небольшой. Верхний предел времени IRQ по-прежнему не гарантирован из-за ожидания DMA EN и зависимых аппаратных задержек.
