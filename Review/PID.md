# PID и оценка качества регулирования: проблемы и предложения

Дата: 12.10.2026. Проверена рабочая копия; сборки и аппаратные тесты в этом проходе не запускались.

**Файлы:** [math/PID.c](../math/PID.c), [math/PID.h](../math/PID.h).

**Зависимости:** C math/runtime; вызывается из C++ firmware, отличен от CMSIS-DSP arm_pid_*.

## Список для обсуждения

### PID-1 — P1 — Header не задаёт C linkage

**Место:** [math/PID.h](../math/PID.h), строка 34.

**Проблема:** PID.c компилируется как C, но PID.h объявляет функции в C++ без extern C.

**Последствие / условие:** При обычном #include PID.h и вызове PID() из C++ linker ищет другое symbol name.

**Возможное решение:** Добавить стандартный __cplusplus / extern C guard вокруг C functions. Не переводить C source в C++ ради обхода.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### PID-2 — P1 — Anti-windup ограничивает только положительный интеграл

**Место:** [math/PID.c](../math/PID.c), строка 15.

**Проблема:** Проверяется fabs(ki)*tmp_I < max_ki_I. При отрицательном tmp_I левая часть отрицательна и проходит любой положительный limit; при ki=0 интеграл тоже может расти неограниченно.

**Последствие / условие:** Интегральная составляющая в отрицательном направлении не ограничена и вызывает насыщение/долгое восстановление.

**Возможное решение:** Проверять модуль всего ki*tmp_I и согласовать clamp или отказ накопления при достижении предела. Определить поведение ki=0 и неотрицательность max_ki_I.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### PID-3 — P2 — Dead zone оставляет устаревшую производную

**Место:** [math/PID.c](../math/PID.c), строка 9.

**Проблема:** Внутри зоны |e|<=e_lim не обновляются D и e_old, но результат всегда включает kd*D.

**Последствие / условие:** Даже при e=0 прежняя производная продолжает влиять на выход. При выходе из зоны derivative считается от старой ошибки, но с текущим dT.

**Возможное решение:** Описать ожидаемую dead-zone семантику: обычно D обнулять и e_old обновлять, интеграл держать либо затухать по выбранной модели. Не менять поведение без решения пользователя.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### PID-4 — P2 — Quality calculation делит на нулевую уставку и неверно обрабатывает отрицательную

**Место:** [math/PID.c](../math/PID.c), строка 48.

**Проблема:** get==1 вычисляет ((y-u)/u)*100 без u!=0; guard есть только для sigma. Границы u*1.05 и u*0.95 поменяются местами при u<0. reset не сбрасывает qual->e.

**Последствие / условие:** Получаются inf/NaN, неверное время вне коридора для отрицательной уставки и старое значение ошибки после reset.

**Возможное решение:** Определить результат относительной ошибки при u=0, строить коридор u±abs(u)*0.05, сбрасывать все поля качества. Согласовать смысл t_time: накопленное время вне зоны или время установления.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### PID-5 — P3 — Нет явного контракта инициализации и float math

**Место:** [math/PID.c](../math/PID.c), строка 5.

**Проблема:** Проверяется только dT==0, не dT<0/NaN; init field не используется. fabs() работает с double, хотя все данные float. В коде оставлены закомментированные формулы anti-windup.

**Последствие / условие:** Некорректные параметры дают бессмысленный результат; double на части MCU увеличивает стоимость math.

**Возможное решение:** Документировать параметры и обязательную инициализацию состояния, использовать fabsf для float, убрать старые варианты после выбора формулы. Проверки NaN/negative dT добавлять только в согласованном объёме.

**Статус:** решение не принято, код в рамках этого обзора не изменён.
