# TIM и производные классы: проблемы и предложения

## Согласованный перенос режимов — 20.10.2026

Текущее описание API: [TIM.md](../TIM.md). Исторические разделы ниже относятся
к прежним этапам; отчёт 49/49 не подтверждает сборку нового API.

- SetUpEncoder: целый TIM, только CH1/CH2, без DMA/IRQ и программного накопления;
  Count возвращает аппаратный CNT. Период обязателен, повторная настройка — через DeInit.
- SetUpPulseMeasure: CH1/CH2 и SMCR; direct/indirect mapping и полярность выбираются
  по входу. Период находится в CCR выбранного входа, HIGH width — в парном CCR.
- GetCapture во всех capture-режимах читает CCR напрямую. `_capture[4]` удалён;
  обработчик подтверждает событие и необязательно уведомляет, без снимка данных.
  Чтения периода/ширины не являются атомарной парой; первый цикл/overcapture/переполнение
  обрабатывает приложение.
- SetUpSlave: однократный Reset/Gated/Trigger/ExternalClock через обычный TRGO/ITR;
  источник уже настроен приложением. SetUpOnePulse — отдельная настройка общей базы.
  ITR-таблица активна для F4/F7/G0, отсутствующие/OC-only источники не подставляются.
  У G0 TIM15: TIM2/TIM3; у F410: TIM5 → TIM1. ETR отложен по решению пользователя.
- Серии разделены: SetUpPulseBurst/RunPulses использует RCR+OPM и PWM2 с LOW на
  начальном/конечном CNT=0. Служебный UG не считается импульсом и не даёт callback.
  Подсчёта каждого импульса в IRQ нет. Ширина RCR учитывается отдельно для G0 TIM1
  и TIM15/16/17; callback завершения необязателен.
- SetUpCounter использует второй TIM, PSC=0 и явный период; Count — прямое чтение.
  StopAfter/StopAt взводят compare без старого CC1IF; IRQ разоружает завершение и
  останавливает оба таймера, callback фиксируется при инициализации и необязателен.
  Возможные лишние/неполные импульсы из-за задержки IRQ описаны; аппаратный gate-stop
  не добавлен. Очередную цель задают при остановленных таймерах, впереди текущего CNT
  в пределах его периода.
- По уточнению пользователя второй TIM для конечной квадратуры закреплён
  последним необязательным параметром конструктора. Указатель неизменяемый;
  тот же TIM/неподдерживаемый TRGO/ITR маршрут дают DebugTrap в конструкторе,
  без доступа к регистрам. Существующие вызовы конструктора сохраняются.
  SetUpQuadrature настраивает пару; счётчик получает PSC=1 по выбору пользователя,
  CNT считает полные A/B-циклы. Два toggle-канала дают сдвиг 90°; частота и модуль N
  заданы в полных циклах, знак GenPulse(N) меняет полярность выбранного A-канала.
  Ноль не запускает, INT32_MIN обрабатывается без знакового переполнения; диапазон
  проверяется по ARR второго TIM. На 16-битном счётчике максимум |N|=65535,
  на 32-битном помещается весь диапазон int32_t.
- GenPulse сбрасывает CNT/фазы делителей обоих TIM, взводит единственный compare
  и запускает счётчик раньше генератора. Служебный UG генератора скрыт от TRGO
  выбором Enable при CEN=0; IRQ/программного накопления на каждый цикл нет.
  Необязательный callback закреплён при настройке и вызывается после остановки
  из IRQ второго TIM. Источники IRQ генератора не включаются. Поздний IRQ может
  дать лишние фронты/неполный цикл; это явно описано.
- Stop квадратурного генератора останавливает оба TIM; DeInit освобождает оба,
  сохраняя конструкторную привязку. Свободный до настройки счётчик и генератор
  сохраняют время жизни; отдельная перенастройка счётчика во время владения
  запрещена контрактом. Main согласуется с IRQ обоих TIM, ожиданий в IRQ нет.

Проверка этого этапа: просмотр исходников/diff. Сборки, тесты и запуск на железе
не выполнялись. Файлы базы/CMake и другие драйверы в этом этапе не изменялись.

## Перенос DMAReq и выбор атомарности — 19.10.2026

- TIM_USE_ATOMIC в tim.hpp: 0 по умолчанию, 1 включает ATOMIC_* ST для изменений
  управляющих полей. При временной настройке UG восстанавливаются только URS/UDIS.
- ChannelConfig передаёт {pin, DMAReq}, без внешнего DMA_Sx*. Внутри каждого канала
  хранятся pin и DMA_Sx; копия Req в объекте не сохраняется. На F4/F7 проверка
  существующей таблицы TIM/CHx/Req выполняется в конструкторе, на G0 драйвер
  выбирает request по TIM/CHx, а пользователь передаёт физический DMA-канал.
- SetUpPWM приобретает выбранный ресурс; DeInit освобождает его, сохраняя выбор.
- DMA IRQ и main-only ожидание остановки используют один снимок TC/ошибок.
  TIM IRQ уже использует снимок SR/DIER; добавочных чтений ему не добавлено.
- Составные режимы по-прежнему ждут отдельного разбора. Сборки и тесты не запускались.

Первичный обзор: 12.10.2026. Общая часть обновлена 18.10.2026; ниже сохранены исходные проблемы и отмечен текущий статус.

**Файлы:** [src/tim.cpp](../src/tim.cpp), [src/tim.hpp](../src/tim.hpp), [src/tim_defs.hpp](../src/tim_defs.hpp).

**Зависимости:** System/RCC/GPIO, IRQ Registry, DMA; примеры WS2812B используют общий TIM.
ADC получает общий TIM* и источник в конструкторе; его миграция описана в [ADC.md](ADC.md).

Прежние TIM_PeriodicIRQ, TIM_PWM, TIM_EncoderGenerator, TIM_StepGenerator,
TIM_InputCapture, TIM_PulseMeasure, TIM_EncoderReader и TIM_HWCounter сохранены
в комментариях. Текущий API описан в следующем разделе.

## Текущий этап: общий TIM, независимые каналы — 18.10.2026

Прежний отчёт компиляции 49/49 ниже относится к старому API. **Новый API не
собирался и не запускался на железе.** Выполнен просмотр исходников и diff.

### Внесено по согласованным решениям

- Активен один TIM: до четырёх `{pin, dma}` закреплены конструктором. Объектов
  каналов, Output, AttachDMA и совместимых оболочек старых классов нет.
- SetUp сохраняет `(frequency, callback, period)`: frequency означает Update/PWM
  в Гц. Capture требует явно заданный период. PSC/ARR общие для всех каналов.
  Настройка не запускает счётчик; повторный SetUp требует DeInit.
- SetUpPWM, SetUpCapture и SetCompareIRQ занимают канал один раз общей маской,
  независимо от наличия callback. Можно совмещать разные роли разных каналов.
- Для 16-битного PWM period <=65535, ARR<=65534: CCR=period даёт точные 100%,
  CCR=0 — 0%. Forced active не используется. SetDuty считает процент без
  переполнения 32 бит и без 64-битного деления; SetCCR проверяет свою роль/диапазон.
- PWM DMA использует TIMx_CHx + CCDS=1, отдельные CCxDE. Нет размножения UP
  на несколько активных DMA. Маршруты добавлены в DMAReq и проверяются в TIM.
  Для 16-битных CCR — uint16_t/Half_Word, для 32-битных TIM2/TIM5 — uint32_t/Word.
- У каждого DMA свой обработчик и статус/callback. Timer IRQ DMA не опрашивает.
  Ошибка останавливает только DMA своего канала; Error публикуется после остановки.
  Ожиданий аппаратных флагов в IRQ нет. TC означает завершение чтения буфера,
  а не последнего PWM-периода. Применение последнего preload — последующий Update.
- Буферы имеют проверку длины/выравнивания/ширины; F7 TX clean выполняет System,
  некешируемые области проекта пропускаются. PWM TX invalidate не требует.
- Capture использует прямой TIx по нарастающему фронту. IRQ сохраняет CCR перед
  callback; без callback GetCapture читает hardware CCR. Отключённые polling-флаги
  сохраняются; подтверждение других событий не стирает новый capture после чтения.
- TRGO настраивается SetUpTrigger без IRQ; direct CCx — SetCompareIRQ с nullptr.
  Отдельный TIM_TriggerGenerator не вводится. В последующем этапе ADC получил
  TIM* и выбранный источник в конструкторе; см. [ADC.md](ADC.md).
- DeInit из main останавливает/освобождает только полученные DMA, адресно снимает
  регистрации и очищает роли/callbacks. Привязки конструктора сохраняются.
- Старые классы/алгоритмы и ITR-таблицы сохранены комментариями в концах файлов,
  не компилируются. EncoderGenerator, RunSteps, HWCounter и остальные составные
  режимы остаются отдельным согласованным этапом, без скрытого переноса поведения.
- Примеры WS2812B перенесены на TIM::SetUp/SetUpPWM/SendDMA. Цветовое кодирование
  WS2812B не менялось. Заголовок, TIM.md, DMA.md, README и комментарии обновлены.

### Интеграция DMA: включение источника без изменения NVIC

По уточнению пользователя используется DMA_Sx::Enable_IRQ(IRQ, bool enable_nvic = true).
При false включается только источник, без изменения разрешения или pending-состояния
NVIC. SendDMA восстанавливает TE/DME через Enable_IRQ(..., false) и сохраняет
внешнюю маску вызывающего кода. Отдельный Enable_IRQ_Source удалён.
SetUpPWM при инициализации по-прежнему использует Enable_IRQ с включением NVIC.
Внутренние блокировки не добавлены; этот вопрос интеграции закрыт.

### Ограничения и ответственность вызывающего кода

- Main маскирует соответствующие TIM/DMA IRQ при изменении общего DIER, если
  обработчики могут выполняться: включая SendDMA и IRQ_en. Внутренних PRIMASK/
  IrqLock нет. IRQ одного TIM/DMA-объекта не должны прерывать друг друга.
- F4/F7 TIM4 не имеет DMA CH4. TIM2 CH2/CH4 пересекаются по request routing;
  совместная независимая PWM DMA работа с CCDS=1 отклоняется при настройке.
  Скрытой замены маршрута или timer burst реализации нет.
- Новый цикл PWM не гарантируется завершённым по DMA TC. Буфер освобождён;
  физический хвост/LOW reset trailer учитывает вызывающий код.
- Частота CNT, переполнение capture и overcapture интерпретируются приложением.
  Новый SetUp не меняет старую целочисленную политику расчёта на поиск точной частоты.
- Полные AF-таблицы для всех ранее отсутствовавших выводов не добавлялись.

## Выполнено: общая основа TIM — 18.10.2026

По выбору пользователя сначала исправлена общая часть; алгоритмы PWM,
энкодеров, измерителей и HWCounter остаются следующими отдельными этапами.

- TIMx закреплён конструктором (const pointer); копирование/перемещение запрещены.
- Общий Init отклоняет повторный SetUp до DeInit, включает/сбрасывает только свой
  таймер и один раз регистрирует его Update/CC. Совпадающий вектор не дублируется.
  Ошибки Register возвращаются через InitError; частичная регистрация откатывается.
- IRQ_en меняет DIER. DeInit адресно удаляет только собственные timer handlers,
  сохраняет чужие записи/состояние NVIC и очищает _info. Имя Deinit заменено на DeInit.
- Base HandleIRQ обслуживает SR & DIER только для Update/CC1..4, сохраняет
  отключённые polling-флаги. Специальные capture/HWCounter handlers ещё не исправлены.
- Callback остаётся указателем на функцию: Update задаётся в SetUp, CC — при
  инициализации SetCompareIRQ до Start. Общие SetUpdateCallback/SetCCCallback удалены.
  Уже назначенный ненулевой CC callback не заменяется до DeInit. nullptr не привязывает
  функцию. Отдельные setters специальных режимов переносятся при их разборе.
- SetFrequency отвергает частоту выше timer clock/нулевой период и правильно
  принимает период 65536 для 16-bit. Минимальный PSC рассчитывается без лишнего
  увеличения на точной границе. Используется только 32-битное деление; усечение
  сохранено, поиска точной конфигурации не добавлено.
- На остановленном таймере SetFrequency загружает PSC через UG до Start;
  временный URS подавляет служебный IRQ/DMA request. TRGO-получателей подключают
  после этой настройки. Runtime частота сохраняет прежнюю семантику PSC/ARPE,
  без обещания атомарного изменения или сброса фазы.
- MMS/CCMR меняются масками. CCR accessor использует адреса последовательных
  MMIO-регистров без вычитания указателей на разные члены структуры.
- TIM_PIN вынесен перед TIM, имя TIM::TIM_PIN сохранено. Конструктор consteval
  проверяет GPIO/pin/AF, канал 0..3 и наличие таймера. Старые метаданные и
  присваиваемая компоновка копий сохранены для конструкторов режимов; runtime
  проверки пинов не добавлены. Имена и значения AF-маршрутов не менялись.
- Таблицы RCC/IRQ определены для F7 и отфильтрованы по CMSIS для F4/F7/G0.
  Учтены F410 TIM1_UP, F412 TIM6 без DAC, G0 TIM3/TIM4, TIM6/LPTIM/DAC,
  TIM16/17/FDCAN. Новые GPIO/AF-маршруты для отсутствовавших pin tables не добавлены.
- Изменения в PWM/HWCounter сейчас ограничены откатом неудачной общей настройки
  через DeInit; их алгоритмы и DMA API не переписывались.

**Проверка компиляции:** tim.cpp, GCC 13.3, C++20, -Os, CMSIS из base_files:
23 определения моделей F4 + 14 F7 + 12 G0 = **49/49**, без ошибок и предупреждений.
Полная сборка прошивки и аппаратные тесты не выполнялись. Файлы CMake и
другие драйверы не менялись.

**Остаётся:** PWM DMA/cache/ошибки/освобождение, duty и каналы; алгоритмы
генераторов и измерителей; ITR для G0/F7; TIM_TriggerGenerator с Update **и CCx**.
Базовый DeInit пока не освобождает PWM DMA: это TIM-6, не закрытый этим этапом.

## Список для обсуждения

### TIM-1 — P1 — Нет runtime/ITR таблиц F7 и неполные device guards

**Место:** [src/tim_defs.hpp](../src/tim_defs.hpp), строка 374.

**Проблема:** Таблицы tim_table/itr_table определены только для G0/F4. F7 имеет declarations и pin types, но не definitions; range-for по неполному tim_table не имеет известной длины. F4 строки TIM1..14 добавлены без проверки наличия. G0 ITR routes имеют 0xFF.

**Последствие / условие:** F7 TIM не собирается в текущем виде. MCU без TIM4/5/6/7/8/12/13/14 ломают общую F4 таблицу; G0 HWCounter всегда отвергает имеющиеся routes.

**Возможное решение:** Таблицы строить по device capabilities. Проверить ITR по RM конкретной линии. Явно отделить поддерживаемые маршруты от неподдерживаемых; заглушку 0xFF не считать реализованным HWCounter.

**Статус:** Частично исправлено 18.10.2026: tim_table F7, CMSIS guards/IRQ и compile-time pin checks готовы; tim.cpp компилируется для 49 моделей. ITR G0/F7 остаётся этапом HWCounter; F7 FindITR явно возвращает 0xFF.

### TIM-2 — P1 — SetFrequency() принимает частоту выше timer clock

**Место:** [src/tim.cpp](../src/tim.cpp), строка 74.

**Проблема:** При freq > bus clock ratio=0, затем psc=1 и arr=0. Нижняя проверка arr==0 отсутствует; ARR получает arr-1.

**Последствие / условие:** Метод возвращает InitOK, но ARR становится 0xFFFF/0xFFFFFFFF вместо сверхвысокой частоты.

**Возможное решение:** После расчёта требовать положительный период и допустимый PSC. Верхнюю границу проверять для периода ARR+1, а не ARR: текущий параметр arr означает число тиков.

**Статус:** Исправлено в общем SetFrequency 18.10.2026: freq<=clock, положительные делители/период, проверка arr-1, период 65536 допустим. Расчёт только 32-битный.

### TIM-3 — P1 — PSC preload не загружается перед первым запуском

**Место:** [src/tim.cpp](../src/tim.cpp), строка 93.

**Проблема:** SetFrequency записывает PSC/ARR, но не генерирует UG; Start() только ставит CEN. Periodic/PWM и другие startup paths могут запустить timer с reset PSC=0 до первого update.

**Последствие / условие:** Первый период отличается от рассчитанного, что важно для IRQ, PWM и DMA waveform. Runtime SetFrequency с ARPE/OCPE начинает применяться в разное время без описанного контракта.

**Возможное решение:** Для первичной настройки при остановленном timer загрузить shadow registers через UG и убрать созданный UIF до включения IRQ. Runtime изменение частоты отдельно описать как применение на update, без сброса текущей фазы по умолчанию.

**Статус:** Исправлена начальная загрузка в общем SetFrequency 18.10.2026: UG при CEN=0 с временным URS и очисткой только UIF. Изменение частоты работающего таймера документировано по существующему ARPE, без обещания атомарности.

### TIM-4 — P1 — IRQ_en() отключает чужие обработчики shared timer IRQ

**Место:** [src/tim.cpp](../src/tim.cpp), строка 106.

**Проблема:** Регистрация ориентируется на NVIC irq_up enable. При disable удаляется вся строка IRQ Registry и отключается NVIC, например TIM1_UP_TIM10. Даже если irq_cc уже включён другим объектом, регистрация own source может быть пропущена.

**Последствие / условие:** Выключение TIM10 отключает обновления TIM1; включение одного объекта после другого может не зарегистрировать обработчик.

**Возможное решение:** Адресная регистрация/удаление и own registered flags по согласованному IRQ API. Mask NVIC только при пустой shared строке.

**Статус:** Исправлено для общей основы 18.10.2026: Init регистрирует один раз, IRQ_en меняет DIER, DeInit адресно удаляет this и сохраняет shared NVIC.

### TIM-5 — P1 — PWM DMA не обслуживает кеш и аппаратные ошибки

**Место:** [src/tim.cpp](../src/tim.cpp), строка 256.

**Проблема:** SendDMA() запускает buffer без TX clean F7, не ограничивает len 65535, проверяет только _dma_busy. Handler видит лишь TC и не TE. _dma_busy обычный uint8_t, читаемый из main.

**Последствие / условие:** На F7 идёт старый waveform; oversized transfer обрезается, DMA error оставляет Busy. Polling busy может не перечитать обновление ISR.

**Возможное решение:** Добавить TX clean для фактически читаемого диапазона, проверку длины, видимый флаг и простой error completion. Согласовать buffer lifetime и доступность DMA памяти.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-6 — P1 — AttachDMA()/Deinit() не завершают владение DMA

**Место:** [src/tim.cpp](../src/tim.cpp), строка 234.

**Проблема:** Возврат DMA SetUp не проверяется; dma_up_req=0 на F4, поэтому raw stream получает CHSEL=0 независимо от timer. Deinit базового TIM не прекращает PWM DMA и не снимает DMA registrations.

**Последствие / условие:** Неверный stream/channel молча не передаёт; переинициализация оставляет IRQ/DMA, обращающиеся к уже сброшенному/отключённому timer.

**Возможное решение:** Проверять маршрут и status AttachDMA. Сначала останавливать свои DMA при Deinit, затем сбрасывать timer. Для F4 требовать/проверять реальную DMAReq пары, а не подменять route нулём.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-7 — P2 — Повторная настройка сохраняет чужие поля режима

**Место:** [src/tim.cpp](../src/tim.cpp), строка 15.

**Проблема:** Init только включает clock. EncoderReader не сбрасывает PSC, ряд SetUp сохраняет SMCR/CR1/DIER. EnableTriggerOutput() добавляет MMS=2 через |=, а SetCCMRField() также только OR.

**Последствие / условие:** При смене режима/повторном SetUp возможны старый divider, external clock/OPM или другой MMS. OR не заменяет многобитовое поле.

**Возможное решение:** Согласовать обязательный Deinit между разными режимами либо заменять все относящиеся к текущему mode поля масками. MMS обновлять как поле, не OR. Не сбрасывать чужую периферию.

**Статус:** Исправлено в общей основе 18.10.2026: повторный Init/SetUp — InitError, новая настройка через DeInit; первый Init сбрасывает свой TIM; MMS/CCMR заменяются масками.

### TIM-8 — P2 — SetDuty() переполняет 32-битное произведение

**Место:** [src/tim.cpp](../src/tim.cpp), строка 185.

**Проблема:** (ARR+1)*percent вычисляется в uint32_t. Например period 84 000 000 и percent=100 дают переполнение, хотя период допустим для TIM2.

**Последствие / условие:** Duty получается неверным; при полном 16-bit диапазоне значение CCR=65536 для 100% не помещается в 16-bit register.

**Возможное решение:** Использовать 64-битное промежуточное значение. Отдельно согласовать точные 0/100% для крайних ARR: ограничить период либо использовать допустимый forced level mode.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-9 — P2 — Проверки channel/capabilities отсутствуют в части публичных методов

**Место:** [src/tim.cpp](../src/tim.cpp), строка 237.

**Проблема:** AttachDMA/SendDMA/SetDuty/SetCCR получают Channel и обращаются к arrays/CCR без проверки, что hardware имеет этот канал и что он настроен. PWM constructor индексирует _ch[p.channel]; PulseMeasure проверяет лишь ch<=1, не число каналов timer.

**Последствие / условие:** CH4 на TIM16 либо некорректный TIM_PIN даёт доступ к отсутствующему каналу/за границей arrays. Ошибка SetUp GPIO также игнорируется.

**Возможное решение:** Проверять channel в допустимом диапазоне _info->channel_count, valid configured pin и capability нужного mode. Не расширять таблицы обещаниями unsupported timers.

**Статус:** Частично: конструктор TIM_PIN проверяется при компиляции, таблицы имеют device/port guards, IRQ_en учитывает число каналов. Проверки публичных методов PWM и других режимов остаются их отдельными этапами.

### TIM-10 — P1 — EncoderGenerator не считает полные импульсы и содержит численные крайние ошибки

**Место:** [src/tim.cpp](../src/tim.cpp), строка 315.

**Проблема:** PSC denominator (period+1)*freq*2 считается в 32 битах, не проверяется PSC range/period. GenPulse уменьшает _pulses на каждый update, хотя toggle формирует полный цикл за два периода. Направление меняет CC1P независимо от выбранного A channel; -INT32_MIN переполняется; GenPulse(0) запускает timer.

**Последствие / условие:** Частота/число квадратурных импульсов отличаются от запроса, допустимы division-by-zero и лишний старт.

**Возможное решение:** Сначала определить единицу GenPulse: full cycles или toggle events. Затем 64-bit расчёт и проверки; полярность выбранного канала; ноль — без запуска, INT32_MIN обработать без signed overflow.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-11 — P2 — StepGenerator RunSteps() создаёт IRQ update ещё до движения

**Место:** [src/tim.cpp](../src/tim.cpp), строка 418.

**Проблема:** RunSteps генерирует UG при ранее включённом UIE и не очищает UIF. HandleIRQ всегда увеличивает _step_count на 1. При RCR=steps-1 hardware update происходит после всего пакета, не после каждого шага.

**Последствие / условие:** Software count включает служебный UG; при RCR считает один update вместо steps выходных периодов. SetUp(false) после SetUp(true) также не отключает UIE.

**Возможное решение:** Убирать UIF служебного UG до запуска, согласовать совместимость RCR batch и count_in_isr. Для пакетного режима считать число реально выполненных шагов либо не обещать per-step count.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-12 — P2 — Capture/PulseMeasure prescaler не валидируется

**Место:** [src/tim.cpp](../src/tim.cpp), строка 442.

**Проблема:** PSC = bus_clk/max_freq - 1 без проверки max_freq <= bus_clk и 16-bit range. В PulseMeasure используется такой же расчёт. Имя max_freq не означает измеряемую входную частоту: это tick frequency таймера.

**Последствие / условие:** Слишком высокая max_freq даёт underflow PSC; слишком низкая обрезается. Полученная единица capture/width не соответствует запросу.

**Возможное решение:** Проверять частоту и делитель в 64 битах, назвать/описать параметр как timer tick rate. Для переполнения 16-bit capture определить допустимую длительность и признак потери результата.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-13 — P2 — PulseMeasure getters не адаптированы к выбранному входу

**Место:** [src/tim.cpp](../src/tim.cpp), строка 487.

**Проблема:** Для CH1/CH2 меняются direct/indirect mapping и TS, но CCER всегда выставляет CC1P, GetWidth всегда CCR1, GetPeriod всегда CCR2.

**Последствие / условие:** При выборе другого input channel роли capture и polarity меняются, а API продолжает возвращать фиксированные registers. Это требует отдельного аппаратного подтверждения обеих схем.

**Возможное решение:** Сверить PWM-input/reset sequence для каждого входа; хранить выбранные width/period channel и выставлять соответствующую полярность. Либо поддержать только одну проверенную схему и явно отвергать другую.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-14 — P2 — Timer handler очищает и вызывает события с выключенным DIER

**Место:** [src/tim.cpp](../src/tim.cpp), строка 125.

**Проблема:** TIM::HandleIRQ и InputCapture/HWCounter читают весь SR и очищают весь snapshot, не пересекают его с разрешёнными источниками. PWM вызывает base handler также по DMA IRQ. _capture не volatile.

**Последствие / условие:** Polling flags могут исчезнуть из-за другого IRQ; callback выключенного источника вызывается, если old flag всё ещё установлен. Main polling capture может не увидеть новое значение.

**Возможное решение:** Маскировать обслуживаемые события разрешёнными DIER источниками и соответствующим mode. Для ISR/main capture определить одиночный видимый snapshot.

**Статус:** Частично исправлено 18.10.2026: общий TIM::HandleIRQ маскирует SR по DIER. Собственные handlers InputCapture/HWCounter и публикация capture остаются этапом измерителей.

### TIM-15 — P2 — HWCounter StopAfter() не снимает прежнюю pending compare и не разоружает завершение

**Место:** [src/tim.cpp](../src/tim.cpp), строка 554.

**Проблема:** Перед новым CCR/CC1IE не очищается CC1IF. После достижения цели handler останавливает master, но не снимает own CC1IE и продолжает считать. Остановка master выполняется программно из ISR.

**Последствие / условие:** Старое событие останавливает новое движение сразу; callback может повториться на следующем обороте counter. При высоких частотах master выдаёт дополнительные импульсы до ISR stop.

**Возможное решение:** Очистить соответствующий флаг перед arm и разоружить compare после completion. Явно описать, что CPU stop имеет latency; если нужны точно N импульсов, отдельно выбрать hardware gate/one-pulse схему.

**Статус:** решение не принято, код в рамках этого обзора не изменён.

### TIM-16 — P3 — Большие исторические комментарии и недостающий trigger API затрудняют разбор

**Место:** [src/tim_defs.hpp](../src/tim_defs.hpp), строка 344.

**Проблема:** Комментарии говорят, что headers G0 нет рядом и F7 падает только на link, хотя локальные base_files содержат headers, а range-for требует полного array. ADC ссылается на отсутствующий TIM_TriggerGenerator. ccr() выполняет pointer arithmetic между отдельными register members.

**Последствие / условие:** Текущий текст смешивает план и реализованные возможности; трудно понять настоящий интерфейс.

**Возможное решение:** Сократить комментарии до текущего hardware contract, перечислить реализованные классы. Trigger API решать вместе с ADC-1; CCR accessor можно сделать явным выбором проверенного register, без выдуманных абстракций.

**Статус:** Частично: комментарии общей части/таблиц обновлены, CCR accessor исправлен. TriggerGenerator остаётся отдельным этапом; нужны Update и CCx.

## История задачи от ADC: TIM_TriggerGenerator — 17.10.2026

Изначальное решение ниже заменено общим TIM и enum источника в ADC.
В текущем коде зависимость устранена, отдельный класс не создаётся;
см. актуальный [отчёт ADC](ADC.md). Следующий текст сохранён как история.

**Согласовано:** нужен отдельный TIM_TriggerGenerator в модуле TIM.
ADC получает указатель на него через AttachTrig(), аналогично подключению DMA.
StartTrig_DMA() сначала подготавливает ADC/DMA и затем запускает таймер.
При остановке захвата останавливается подключённый генератор.

**В очереди TIM:**

1. Реализовать генератор на существующей базе TIM. SetUp настраивает период,
   но не запускает счётчик; не подключать таймерный IRQ ради аппаратного триггера.
2. Предоставить ADC описание выбранного аппаратного источника. Значения EXTSEL
   различаются у F4, F7 и G0; сверить маршруты с RM/LL конкретных моделей.
   Пользователь выбрал Update и CCx. Форму request и настройку compare согласовать при отдельном разборе генератора.
3. Устранить необходимые пробелы таблиц TIM-1: определения F7 и проверки
   доступности таймеров по CMSIS; G0 содержит только часть доступных экземпляров.
   Не считать неподдерживаемый таймер рабочим источником ADC.
4. Учесть TIM-3: загрузить PSC/ARR до подключения/запуска ADC, чтобы служебный UG
   не стал лишним измерением и первый период имел настроенную длительность.
5. Обновить примеры совместной настройки TIM и ADC, порядок Start/Stop,
   требования к времени жизни и порядок освобождения при DeInit.

**Статус:** общая основа TIM исправлена 18.10.2026; сам генератор отложен до следующего отдельного этапа.
До реализации генератора зависимость ADC-1 от TIM остаётся незакрытой;
временный класс или обходную реализацию внутри ADC не добавлять.

## Миграция к общему TIM — 18.10.2026

Согласована модель: один общий объект TIM, настройка каналов его функциями,
маска занятых каналов; дополнительных объектов каналов нет. Ожидания аппаратных
флагов в IRQ запрещены. Callback задаётся только при инициализации.

В текущем шаге введена маска занятости compare-каналов. SetCompareIRQ отклоняет
повторную настройку даже при nullptr callback; DeInit сбрасывает маску.
До этого проверялось только наличие ненулевого callback, поэтому настройка
без callback оставляла возможность повторно занять тот же канал.

Перед основной миграцией были запрошены решения о неизменяемых привязках,
триггере для ADC и старых классах. Принятые решения ниже реализованы в общем TIM;
сборка и тесты нового API не запускались.

### Принятые решения по новому API

- Конструктор общего TIM принимает до четырёх описаний `{pin, dma}`. Канал
  определяется самим TIM_PIN; порядок описаний произвольный.
- Эта форма конструктора добавлена. Проверяются повторы каналов, чужой TIM
  и передача DMA без пина. Привязки закрыты, методов их замены нет.
- Триггеры реализованы функциями общего TIM. ADC получил TIM* и выбранный
  источник в конструкторе вместо отдельного TIM_TriggerGenerator.
- Старые классы заменяются, без постоянного совместимого слоя. Использование
  WS2812B мигрирует на новый API; алгоритм кодирования цветов не меняется.

Дополнительные решения также приняты и реализованы:

- SetUp сохраняет прежние параметры; для capture/counter период задаётся явно.
- PWM ограничен периодом, помещающимся в CCR; forced active не добавляется.
- Независимые DMA используют CHx+CCDS, для 32-битных таймеров есть uint32_t*.
- Синхронизацию записей DIER из main обеспечивает вызывающий код маскированием
  соответствующих IRQ. Enable_IRQ(..., false) при запуске DMA сохраняет эту маску.
- Составные режимы разбираются отдельно; старый код сохранён комментариями.

Последующий этап ADC реализован: фиксированные параметры конструктора,
Start(buf=nullptr, len=0), раздельные ADC/DMA IRQ, HT/TC и общий TIM* с источником.
Таймер настраивает приложение; ADC Start вооружает захват и затем запускает TIM.
Сборка и тесты нового API не запускались; см. [ADC.md](ADC.md).
